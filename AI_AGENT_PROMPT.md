# Промпт для ИИ-агента

Скопируйте этот текст в начало задачи:

> Ты работаешь в Fit V2. Сначала полностью прочитай `AGENTS.md`, `docs/FIT_WORKFLOW.md` и `docs/CURRENT_STATE.md`, затем только релевантные текущей задаче разделы `ARCHITECTURE.md`, `FEATURE_PARITY.md` и продуктовой документации. Соблюдай направление UI → repository → query → Supabase. Не обращайся к Supabase из компонентов. Не используй бизнес-триггеры, ручной SQL в Dashboard, `select('*')`, `any` или небезопасные casts. Составные записи реализуй одной явной RPC-транзакцией. Любое изменение БД начинай с migration и DB/RLS тестов. Для локальной разработки используй `npm run dev` и только локальный Supabase; никогда не указывай production Supabase в локальных env-файлах и не отключай защитную проверку. Production-конфигурация существует только в Vercel. Сохраняй внешний вид и пользовательский результат V1, но не копируй legacy data-access код. Старый источник называй только `V1 baseline` или `legacy trainer-app`; не добавляй в Fit V2 названия и URL исходных репозиториев. После подтверждённого merge замени snapshot в `docs/CURRENT_STATE.md`. Перед завершением запусти все проверки из `AGENTS.md` и перечисли, что было проверено.

Если задача добавляет или меняет действие, состояние, экран, форму, карточку,
навигацию или пользовательский текст, добавь к этому готовый UI-промпт из
`docs/UI_TASK_PROMPT.md` и полностью прочитай `docs/UI_IDENTITY.md`. Целевая
айдентика Fit — MONOCHROME PERFORMANCE: графит `#242426` в светлой теме, фон
`#111214` и молочный primary `#F1EDE6` в тёмной; целевой шрифт — Onest. Эти
значения реализуются через общие семантические токены, а не feature-local hex.
`docs/UI_DESIGN_SYSTEM.md` описывает текущую реализацию и нужен для безопасной
миграции без изменения структуры, данных и поведения. Промпт фиксирует порядок
переиспользования компонентов и обязательную визуальную приёмку.
