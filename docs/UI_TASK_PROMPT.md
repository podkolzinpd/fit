# Fit — приёмка UI для всех экранов

Общий порядок для клиента, тренера, auth, чатов, календаря, планирования, Live,
прогресса, ачивок, питания, настроек и любого другого изменяемого экрана.
Scope и таблица проверки — [FIT_WORKFLOW](FIT_WORKFLOW.md).

## Перед изменением

Прочитать [UI_IDENTITY](UI_IDENTITY.md), нужный раздел
[UI_DESIGN_SYSTEM](UI_DESIGN_SYSTEM.md) и [индекс](ACTIVE_CONTRACTS.md).
Для Lime — [дизайн-код](design/FIT_LIME_DESIGN_CODE.md) и
[SVG-каталог](design/FIT_LIME_SOURCE_CATALOG.json).
Проверить роль, маршрут, флаг, тему, плотность и реальный baseline.
Принятый SVG/handoff не требует нового экспорта Figma. Контуры текста не доказывают
точные font-size/line-height.

Сначала существующий компонент, затем небольшой вариант, затем новый примитив
при доказанной потребности. Не создавать вторую палитру, библиотеку или шрифт.
Shared выделять по общему смыслу и поведению, а не похожим пикселям; соседние
экраны не рефакторить ради переиспользования. Данные и права не выводить из макета.

## Простота без потери механик

- Дизайн задаёт геометрию, шрифты, иконки и иерархию. Основное действие очевидно;
  это не ограничение «одна кнопка на весь DOM».
- Сохранить действие не означает постоянно показывать его под каждым кругом.
  Использовать принятое меню/жест/раскрытие.
- Не добавлять несогласованные панели, подписи, метрики, графики, CTA и подсказки.
- Обратная связь обязательна, но SaveStatus/отдельный retry/постоянная подпись
  не обязательны сами по себе. Использовать согласованное поле или контрол.
  Серверную ошибку не выдавать за неверное значение.
- Pending предотвращает дубли и доступно сообщает процесс; disabled читаем.
  Retry может использовать существующее действие без второй кнопки.
- Подтверждение/undo определяются принятой механикой и риском потери данных.
  Не добавлять диалог поверх согласованного свайпа с отменой.
- Заметки/инструкции/действия не должны исчезать. Проверить, где они доступны,
  а не добавлять повторные ряды ради формального сохранения.
- Coachmark — для заметного изменения знакомого сценария, требующего объяснения:
  существующий компонент, один новый ID, краткий текст, user-scoped localStorage.
  Для косметики/служебных правок не нужен; не превращать в тур/новую механику.

Иконки — оригинальные утверждённые SVG или существующие Fit icons. Не смешивать
пакеты, не заменять навигацию emoji/неоднозначными Unicode. Иконке-кнопке нужны
доступное имя и сохранённая область нажатия. Новые SVG не нормализуются под старый stroke.

## Проверка результата

По пунктам плана: исходное состояние → действие → промежуточное → результат/возврат.
Проверять только применимое, но не пропускать достижимые состояния.

- Вид: принятый источник, размеры, шрифты, цвета состояний, порядок, плотность,
  отсутствие лишнего. Скриншоты просмотреть, не только сохранить.
- Ввод: фокус/клавиатура/blur, цифры и текст, валидация, сохранение/ошибка/повтор,
  отсутствие скачков и потери черновика.
- Жесты, перетягивание, отмена, меню, таймеры и переходы выполнить.
  Наличие обработчика не подтверждает взаимодействие.
- Вложенные окна/portals, empty/loading/error/success/completed, fixed bars,
  прокрутка и возврат не наследуют правильность родителя.
- Shared проверить у затронутых ролей. Gate off не должен получать пилотный вариант.
- WebKit390, адаптация430, поддерживаемые темы; узкий экран/desktop/устройство
  по риску. Оригинальный/компактный — там, где существуют.
  Размеры конкретного дизайна не заменять универсальной высотой.
- Сохранить safe area, русский длинный текст, focus-visible, доступные имена,
  контраст, hit targets и reduced motion. Не полагаться на hover/один цвет.
  Не смешивать план и подтверждённый факт.

Один сценарий закрывает несколько ID; полный декартов набор по умолчанию не нужен.
Повторный дефект проверять там, где он проявлялся. Зелёный тест текущей разметки
не подтверждает согласованный UX. Baseline менять только для принятой правки.
Телефон/симулятор/браузер указывать отдельно.

## Запись в существующем PR

Ссылка на план/источник; версия/контекст; ID → результат → проверка → статус.
Для маленькой правки одна строка. Для большого плана ни один ID не теряется.
Отдельный большой отчёт и новый этап согласования не требуются.
