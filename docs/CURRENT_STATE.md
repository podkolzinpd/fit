## Последнее продуктовое изменение

- Клиент может отдельно задать вопрос по завершённой тренировке; обычный факт,
  комментарий или RPE не создаёт обязательной задачи тренеру.
- Тренер отвечает прямо в карточке вопроса; текст обязателен, реакция
  необязательна. Отправка ответа закрывает вопрос автоматически, а повторный
  вопрос не наследует прошлый ответ и реакцию.
- Ответ проверяется по ответственному тренеру конкретной тренировки: автору
  назначения либо основному тренеру самостоятельной записи клиента.
- VisualViewport используется только для определения открытой клавиатуры;
  высота оболочки задаётся CSS `100dvh`. Нижняя навигация скрывается при вводе
  и возвращается без серой области под экраном.
- Несколько тренеров и выбор адресата вопроса оставлены на следующий этап.
- Следующая продуктовая задача без отдельного подтверждения не начинается.

## Последняя проверенная продуктовая точка

- Главные страницы обеих ролей сохраняют voice-first действие и ввод текстом.
  Клиентская главная показывает ближайшее назначение, состоявшуюся неделю и не
  более одного вторичного акцента: ответ тренера, рекорд или цель.
- Создание тренировки использует единый ручной каталог направлений «Силовая» и
  «Бег», компактные фильтры, недавние упражнения и множественный выбор.
- Голосовой/текстовый разбор понимает порядок `3 по 15 20 кг` и
  `20 кг 3 по 15`, устойчив к части опечаток и сохраняет безопасный локальный
  результат при временной ошибке LLM.
- Сохранённые тренировки используют компактную хронику упражнений с раскрытием
  подходов и отдельной кнопкой истории; копирование и удаление находятся в меню.
- Trainer и Client Progress используют одну читаемую ИИ-сводку с реальным
  горизонтом истории и русскими формулировками.
- Ручной беговой MVP завершён: обычный бег, интервалы, активное восстановление,
  СБУ, RPE и компактная динамика работают в планировании, Live и истории.
- Системный каталог содержит локальные public-domain пары кадров упражнений;
  внешнего медиасервиса и лицензионной зависимости нет.

## Инфраструктура и Yandex Cloud

- Локальная разработка и проверки работают только через Podman. Docker у
  владельца проекта не установлен и не используется.
- Yandex Cloud stage содержит Managed PostgreSQL 17 и Serverless Containers;
  миграции доставляются автоматически через GitHub OIDC, private runner и
  forward-only policy.
- Ограниченный Yandex ID pilot и `/v1/clients` работают на stage. Production
  frontend и основной tenant пока остаются на Supabase; полный cutover не
  выполнен.
- Yandex OAuth использует PKCE и публичный Client ID. OAuth Client secret не
  нужен текущему browser-контракту; Supabase-сессия при пилотном входе не
  создаётся.
- Активная ветка `codex/yandex-invitation-lifecycle` добавляет migration `000007`
  и узкие API-команды create/claim/revoke/remove/leave. Прямые runtime-записи
  остаются закрыты; одноразовый код хранится только как SHA-256, claim выполняется
  под row lock, root membership и cross-tenant доступ защищены в PostgreSQL.
- Pilot callback позволяет обеим ролям принять код; тренер создаёт приглашение
  несвязанному клиенту, клиент приглашает/отключает дополнительного тренера,
  а дополнительный тренер может выйти сам. Остальные данные read-only.
- Новая cost-sensitive, destructive или identity-инфраструктура требует
  отдельного решения и не добавляется в продуктовые UI-задачи.

## Проверки активной ветки

- Migration `000007` локально пере-применена к существующей PostgreSQL 17 без
  скачивания образов; 10 actor/RLS/session/lifecycle tests зелёные.
- Supabase `db:reset` воспроизвёл полную историю; 568 pgTAP SQL/RLS tests и
  migration safety зелёные.
- Полный `npm run check` зелёный: 628 frontend tests, coverage, lint, TypeScript,
  DB types, iOS permissions, 32 infra policy tests, 51 API tests и production
  build.
- Yandex callback success/create, error/retry и empty-state визуально приняты на
  390, 430 и 1440; длинный русский текст и код не дают horizontal overflow.

## Проверки последней продуктовой точки

- Повторная приёмка YAFIT-346 проверяет обычную карточку тренировки без
  специальной ссылки из очереди: текст активирует отправку без реакции, ответ
  автоматически закрывает вопрос.
- SQL/RLS-матрица отдельно проверяет ответственного тренера, который не является
  корневым владельцем клиента; посторонний тренер получает отказ.
- На мобильном WebKit 390×844 проверены открытие/закрытие клавиатуры, возврат
  оболочки к высоте viewport и отправка текстового ответа без реакции.
- Для `main` зелёные 618 frontend-тестов с coverage, lint, TypeScript, типы БД,
  iOS permissions, infra policy, 41 API-тест и production build; отдельно
  зелёные 568 SQL-тестов и WebKit-сценарий ответа тренера.
