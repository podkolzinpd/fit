## Активная работа

- Yandex ID/profile vertical slice, серверная tenant-allowlist и постоянный
  stage delivery находятся в `main`: GitHub OIDC без JSON-ключа, immutable
  образ по Git tree hash `services/api`, автоматические forward-only миграции
  перед API revision, private smoke и rollback. `#468` обходит известный сбой
  `DeployRevision` Terraform provider через официальный REST API, строит запрос
  только из reviewed plan JSON и требует отсутствие container drift после
  refresh. `#473` добавил прямые `iam.serviceAccounts.user` bindings; run
  `32308441654` подтвердил их, но получил HTTP 403. В каталоге нет явного
  folder-level grant; ветка фиксирует bootstrap и диагностику. Миграция `000004`, API revision и cutover не применены.
- Функциональный MVP признан достаточным для системной фазы удобства. Аудит
  `#420` зафиксировал P0/P1/P2; навигационная ясность завершена в `#421`,
  информационная архитектура Trainer Progress — в `#423`, visual regression
  ключевых маршрутов — в `#425`, типографика — в `#427`, геометрия компонентов —
  в `#429`, единые состояния интерфейса — в `#431`. Мобильная тренировочная
  фаза P0/P1 закрыта финальной приёмкой `YAFIT-316`; desktop shell тренера
  отложен пользователем и не является следующей автоматической задачей.
- Пользователь продолжает продуктовую полировку по одному выбранному экрану за
  раз: отдельные ветка/PR/CI/production-проверка. Для согласованного плана
  Progress разрешён последовательный переход к следующей задаче только после
  полного завершения предыдущего PR. Главные страницы клиента и тренера
  сохраняются без изменений.
- Тёмная палитра из Figma-макета «Фит» (node `116-4449`) перенесена в набор
  токенов `theme-dark-pilot` и закрыта default-off allowlist по образцу Apple
  Health (`VITE_DARK_THEME_PILOT_ENABLED` + `VITE_DARK_THEME_PILOT_USER_IDS`,
  описаны в `OPERATIONS.md`). Разметка, состав экранов и тексты не менялись; вне
  allowlist тёмная тема осталась прежней, поэтому committed visual baselines не
  тронуты. Палитра применяется, когда участник пилота сам включил тёмную тему в
  профиле; выбор хранится в `localStorage` устройства.

## Последняя проверенная продуктовая точка

- Отдельная серия улучшений Progress идёт по согласованному плану. `#474`
  исправил доступность горизонтов 1/3/6 месяцев и расчёт регулярности по
  реальному периоду от первой завершённой тренировки. Второй отдельный блок
  переводит ИИ-контракт на русские предметные формулировки и закрывает старые
  технические ключи безопасным отображением; полный план сохранён в
  `docs/design/PROGRESS_SCREEN_PLAN_2026-08-20.md`.
- После `#461` сохранённый план показывает компактный список упражнений и
  раскрываемые подходы без потери блоков и интервалов. Строка упражнения во
  всех режимах просмотра состоит из спокойного названия со стрелкой и одной
  числовой сводки; разные повторения читаются через `/`, пропущенный подход —
  через `—`. Подробные подходы раскрываются нажатием на строку, а история
  остаётся отдельной кнопкой-часами с понятным доступным именем и зоной 44 px.
  Между упражнениями нет декоративных линий. На карточке управляемой
  тренировки изменение остаётся видимым, а редкие копирование и удаление
  собраны в подписанное overflow-меню; read-only доступ не расширен. Данные,
  доступы, LLM, SpeechKit и главные страницы ролей не менялись.
- Экран планирования из карточки спортсмена использует зафиксированный контекст
  клиента в шапке, сохраняя переключатель «План / Завершённая». Дата и начало
  собраны компактно, окончание и заметка раскрываются по необходимости,
  голосовой/текстовый ввод сворачивается после добавления упражнения, а каталог
  и массовые операции больше не дублируются. Бег с RPE не сжимает время,
  дистанцию и единицы измерения в одну строку. Расчёты, LLM, SpeechKit и главные
  страницы ролей не менялись.
- Форма копии тренировки показывает упражнения компактными раскрываемыми
  строками. Отдых, заметка и беговые пресеты собраны в `⋯`; нижнее действие не
  перекрывает ввод при открытой iOS-клавиатуре. Права и данные не менялись.
- Изолированный Yandex Cloud stage содержит приватные Managed PostgreSQL 17 и
  Serverless Container без прогретых экземпляров. Миграции `000001`–`000003`
  применены; API readiness подтверждён. Код `#413` добавил проверку Yandex ID,
  hashed identity mapping, allowlist и read-only `/v1/profile`, но миграция
  `000004` и новая revision ещё не развёрнуты. Образ с tag
  `cee48ab2b835ed45b7f1f7d010512274e04bb704` уже сохранён в Container Registry
  и должен переиспользоваться при следующем run. Production frontend продолжает
  использовать Supabase, публичный invoker и frontend cutover не включены.

## Постоянные ограничения

- LLM-разбор и SpeechKit не менять без отдельного продуктового решения.
- UI перед сдачей проверяется на Client 390/430 px и Trainer 1440 px; для
  мобильных сценариев обязателен WebKit.
- После merge изменений приложения обновляется и заново запускается iOS bundle.
- Локальные контейнеры и Supabase запускаются только через Podman. Docker у
  пользователя не установлен и не планируется; не предлагать его установку.
  Когда Podman недоступен, обязательные migration/pgTAP-проверки выполняются в
  CI. Production-секреты не читаются и не выводятся.
- Backlog и статусы подтверждаются через YAFIT; этот файл — индекс, не замена
  Tracker.
