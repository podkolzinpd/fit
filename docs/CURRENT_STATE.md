## Активная работа

- Yandex ID/profile vertical slice, серверная tenant-allowlist и постоянный
  stage delivery находятся в `main`: GitHub OIDC без JSON-ключа, immutable
  образ по Git tree hash `services/api`, автоматические forward-only миграции
  перед API revision, private smoke и rollback. `#468` обходит известный сбой
  `DeployRevision` Terraform provider через официальный REST API, строит запрос
  только из reviewed plan JSON и требует отсутствие container drift после
  refresh. `#473` добавил прямые `iam.serviceAccounts.user` bindings; run
  `32308441654` подтвердил их, но получил HTTP 403. В каталоге нет явного
  folder-level grant; ветка фиксирует bootstrap и диагностику. Миграция `000004`, API revision и cutover не применены.
- Функциональный MVP признан достаточным для системной фазы удобства. Аудит
  `#420` зафиксировал P0/P1/P2; навигация, информационная архитектура Trainer
  Progress, visual regression, типографика, геометрия и единые состояния закрыты
  в `#421`…`#431`. Мобильная тренировочная фаза P0/P1 закрыта приёмкой
  `YAFIT-316`; desktop shell тренера отложен пользователем.
- Пользователь продолжает продуктовую полировку по одному выбранному экрану за
  раз: отдельные ветка/PR/CI/production-проверка. Для согласованного плана
  Progress разрешён последовательный переход к следующей задаче только после
  полного завершения предыдущего PR. Главные страницы клиента и тренера
  сохраняются без изменений.
- `YAFIT-327` завершает цельную композицию Trainer Progress без дублирующего
  обзора и глобальных раскрытий: текущая неделя и ИИ видны сразу, бег и замеры
  открываются отдельными компактными маршрутами. Контракт LLM, клиентский
  Progress и главные страницы ролей не изменены.
- Тёмная палитра из Figma-макета «Фит» остаётся default-off пилотом через
  allowlist; переменные, пользовательское включение и ограничения описаны в

## Последняя проверенная продуктовая точка

- Участникам allowlist `VITE_DARK_THEME_PILOT_*` поиск в списке клиентов отдаётся
  полем Fit: полная ширина на `--input`, иконка лупы, подписанная кнопка сброса,
  фокус-кольцо на обёртке через `:focus-within`, плейсхолдер на
  `--secondary-label-fg` вместо `--muted` (4.2:1 и 4.3:1, ниже AA). Поле
  показывается от шести клиентов; порог считается по всему списку, поэтому во
  время ввода оно не исчезает. Вне пилота экран прежний, committed visual
  baselines не тронуты; отдельного флага не заводили, чтобы не настраивать новую
  переменную в Vercel. Экран вынесен в `ClientsListPage.tsx`: иначе компонентный
  тест тянул в покрытие остальные пять страниц клиента.
- Серия улучшений Progress `#474`…`#482` прошла по согласованному плану:
  горизонты 1/3/6 месяцев и регулярность считаются по реальному периоду от
  первой завершённой тренировки и по реальной истории, ИИ-контракт переведён на
  русские предметные формулировки, измеримые сравнения перенесены в проверяемые
  серверные факты, визуальная иерархия анализа унифицирована для тренера и
  клиента, замеры собраны в один компактный блок с отдельным раскрытием истории
  и настройки. `#481` закрыл приёмку состояний, длинных названий и размеров
  390/430/1440 px. План — в `docs/design/PROGRESS_SCREEN_PLAN_2026-08-20.md`.
- После `#461` сохранённый план показывает компактный список упражнений и
  раскрываемые подходы без потери блоков и интервалов: во всех режимах строка —
  это спокойное название со стрелкой и одна числовая сводка (`/` для разных
  повторений, `—` для пропущенного подхода), подходы раскрываются нажатием,
  история остаётся кнопкой-часами с зоной 44 px, декоративных линий нет. Редкие
  копирование и удаление собраны в подписанное overflow-меню; read-only доступ
  не расширен.
- Экран планирования из карточки спортсмена держит контекст клиента в шапке и
  переключатель «План / Завершённая»; дата и начало собраны компактно, окончание
  и заметка раскрываются по необходимости, голосовой/текстовый ввод сворачивается
  после добавления упражнения, каталог и массовые операции не дублируются, бег с
  RPE не сжимается в одну строку.
- Форма копии тренировки показывает упражнения компактными раскрываемыми
  строками. Отдых, заметка и беговые пресеты собраны в `⋯`; нижнее действие не
  перекрывает ввод при открытой iOS-клавиатуре. Права и данные не менялись.
- Изолированный Yandex Cloud stage: приватные Managed PostgreSQL 17 и Serverless
  Container без прогретых экземпляров, миграции `000001`–`000003` применены, API
  readiness подтверждён. `#413` добавил проверку Yandex ID, hashed identity

## Постоянные ограничения

- LLM-разбор и SpeechKit не менять без отдельного продуктового решения.
- UI перед сдачей проверяется на Client 390/430 px и Trainer 1440 px; для
  мобильных сценариев обязателен WebKit.
- После merge изменений приложения обновляется и заново запускается iOS bundle.
- Локальные контейнеры и Supabase запускаются только через Podman. Docker у
  пользователя не установлен и не планируется; не предлагать его установку.
  Когда Podman недоступен, обязательные migration/pgTAP-проверки выполняются в
  CI. Production-секреты не читаются и не выводятся.
- Backlog и статусы подтверждаются через YAFIT; этот файл — индекс, не замена
  Tracker.
