# Fit — текущее состояние проекта
> Rolling snapshot для продолжения между сессиями, максимум 120 строк. После merge сведения заменяются; полная история хранится в Git, PR и Tracker.
Обновлено: 2026-09-11. База реализации: `main` `733709d8` (#889). Первый реальный tenant перенесён в Yandex stage, но ещё не включён в sticky routing; Supabase остаётся его единственным рабочим backend до отдельного cutover.
## Последняя проверенная продуктовая точка
- YAFIT-480: Home, Progress и завершение используют общий подтверждённый личный факт без ожидания ИИ: база/изменение/рекорд, две записи и даты. После save/edit/delete обновляются производные запросы. Старая сводка подписана отдельно. Первая запись больше не PR в обоих backend. YAFIT-481 добавляет компактную карту последней тренировки на Home; YAFIT-482/483 добавляют сводку и центр результатов.
- Главные страницы обеих ролей сохраняют voice-first действие и ввод текстом; Client Home показывает ближайшее назначение, состоявшуюся неделю и максимум один вторичный акцент. Live разделяет нейтральный таймер и активный отдых.
- Создание, Live и завершение прошлого плана сохраняют прежнюю логику без дубликатов. Yandex stage поддерживает non-Live lifecycle, cancel/reschedule, комментарий и author-scoped soft-delete с optimistic/tenant checks.
- Единый мобильный viewport-контракт восстанавливает полную высоту Trainer, Client и авторизации после закрытия клавиатуры даже при resize WebKit. Создание тренировки использует каталог «Силовая»/«Бег», недавние упражнения и фильтры; мобильный sheet прокручивается, а новый клиент из пустых «Тренировок» и «Прогресса» попадает в форму своего профиля.
- Голосовой/текстовый разбор понимает числа словами, дробный вес, интервальный бег и связки; неоднозначность открывает проверку. Сохранённые тренировки — компактная хроника с копированием и удалением.
- ИИ-сводка и production-разбор работают через Yandex Cloud Functions, локальный разбор — в Supabase. `main` содержит Yandex PostgreSQL operations для `app_feedback`; внешние DataLens/Telegram/Tracker подключения отложены.
- План нового анализа: `docs/design/PROGRESS_AI_WHOLE_PERIOD_ANALYSIS.md`. Контракт v8 получает полный выбранный и предыдущий периоды, цель, обратную связь и замеры без закрытых заметок; большой вход разбирается частями. Ответ: «Движение к цели» → «Что заметил ИИ» → «Что делать дальше» → «Чего не хватает»; числовой пересказ без вывода отклоняется.
- Публичные условия, политика конфиденциальности и страница запроса удаления аккаунта доступны без таббара. Принятая редакция сохраняется под RLS; заявка на удаление отменяема и не удаляет данные автоматически. Интерфейс входа и регистрации больше не предлагает Google; существующие Google-аккаунты и серверный провайдер не удалены.
- Профиль тренера — одна компактная анкета; редактирование, подробности и публикация остаются внутри карточки. Настройки содержат уведомления, тренировки, оформление, рабочие инструменты, аккаунт и помощь; данные каталога и ИИ-сценарии не меняются.
- Профиль спортсмена содержит личные данные и связи с тренерами; тема, анимация, карта тела, уведомления, установка, помощь, документы и выход находятся в `/me/settings`.
- Web Push о сообщениях настраивается у обеих ролей и ведёт в точный диалог. Нативная iOS-оболочка пока показывает только локальное напоминание о незавершённой тренировке; полноценным сообщениям нужны APNs, Android/FCM в репозитории отсутствуют.
- Assistant открыт всем тренерским аккаунтам и защищён `TrainerOnly`; `VITE_ASSISTANT_NAV_ENABLED=false` — общий kill switch. Durable turns/actions и narrow RPC сохраняют owner/RLS. Новые turn'ы создают workout draft, прежние карточки читаются; исходная диктовка сохраняется при уточнении клиента. Числовые поля можно очистить, composer держит микрофон и отправку на одной линии, неизвестное имя открывает полный выбор доступных клиентов.
- PWA показывает отдельную установку для iPhone через Safari и Android через системное окно или меню Chrome. Беговой MVP и локальный каталог работают; Yandex Web Push producer, lease/retry и минутный private timer работают на stage; гребля использует темп `/500 м`.
- Каталог сохраняет 663 прежних ref и добавляет 317 проверенных Gym Pro animation family; после удаления дублей основной выбор содержит 312 карточек. Старые id, варианты, синонимы и custom-карточки доступны в поиске и истории. Видео запускается по тапу, повторный тап открывает технику, `+ / ✓` меняет выбор. Точная Vital-анимация наследуется историческими дублями без смены `ref`; узкая тяга использует отдельную проверенную пару кадров и не наследует wide-grip ролик. 1 240 старых JPG удалены и блокируются, непокрытое упражнение остаётся текстовым.
- Client и Trainer Progress используют короткую историю подтверждённого периода: лучший результат, тренировки, `X/Y` недель, улучшенные упражнения, карта тела, сравнение, связь с целью и ближайший план. Тренер видит plan/fact, сигналы и публикацию; выполнение плана не выдаётся за прогресс к цели.
- Trainer Progress сохраняет прежнюю композицию. У клиента сверху период с превью ИИ, затем неделя и результаты, полная карта ниже замеров и свёрнута. С Home она открывает точную тренировку, зону и даты с возвратом в тот же срез. Измерения, карта и LLM используют подтверждённые метрики; fallback не сбрасывает прокрутку, ошибки замеров локальны, бег следует общему периоду.
- Карта Home занимает полную ширину карточки: фигура по центру под переключателем, группы выровнены по верху фигуры. Изменение результата показано сразу с датой прошлой записи; переходы — «Открыть тренировку» и «Разбор нагрузки». Общий счётчик включает кардио; остальные группы раскрываются. План: `docs/design/CLIENT_HOME_RESULT_ALIGNMENT.md`.
- Карточка спортсмена у тренера — один нейтральный вход в планирование,
  равноправные переходы в историю/прогресс, действие «Добавить этапы». Выбор
  фигуры/схемы — настройка аккаунта тренера, не смешивается с выбором клиента.
- Расписание показывает месяц, неделю, события и планы без времени; Assistant сохраняет тренировку только после подтверждения черновика.
- После успешного завершения клиент видит одноразовый отчёт: краткие факты,
  точный план/факт, один главный результат, обратную связь, мышцы и действия.
  История и тренерский сценарий сохраняют компактный экран YAFIT-280/341.
- Live сохраняет каждое изменение подхода на устройстве, автоматически досылает pending-черновики и ограничивает зависшие запросы. Finish сначала отправляет
  открытую строку; ошибка закреплена у повтора. Поля и галочка сохраняют зону
  нажатия 44 px; соседние строки стоят вплотную и каждая занимает 44 px.
  Активное упражнение не обёрнуто во вторую округлую карточку, а план
  раскрывается по требованию без изменения сохранённых плановых данных.
  Подтверждённый фактический вес подставляется дальше внутри той же плановой
  группы; ручной факт важнее, будущие подходы и сам план заранее не сохраняются.
  После 20 минут без содержательного действия клиент получает одно мягкое
  напоминание с возвратом в Live и выбором продолжить или завершить. Работающий
  отдых продлевает окно; завершение, удаление и отключение настройки снимают
  уведомление. В iOS доставку планирует ОС, в вебе есть service-worker и inline
  fallback при следующем открытии.
- Клиент может безопасно отключить текущего тренера в профиле: серверная
  операция атомарна, повтор идемпотентен, самостоятельная история, назначения,
  замеры и цели сохраняются. Серверное переподключение после явного отключения
  использует тот же атомарный merge и не допускает двух активных тренеров.
- Новые одноразовые коды приглашения в клиентском профиле, карточке клиента у
  тренера и первом плане имеют единый compact copy-action, подтверждение
  «Скопировано» и fallback для iOS/WebView.
## Инфраструктура и Yandex Cloud
- ИИ-анализ Progress использует контракт `training-progress-v13` и агрегатор
  `summary-aggregate-v1`: все уникальные упражнения текущего и предыдущего
  периодов сохраняются, но сырые подходы заменены первой/последней/лучшей
  точкой, трендом и максимум восемью контрольными сессиями. Fingerprint включает
  полные исходные данные и версии правил; неизменное ручное обновление возвращает
  кэш, одинаковые одновременные запросы делят одну генерацию. Обычный путь — один
  модельный вызов, затем максимум один короткий repair без повторной истории.
  Автотесты блокируют live AI и используют только mock-ответы. Старые сводки
  совместимы; полный план — `docs/design/PROGRESS_AI_AGGREGATION_AND_DEDUPLICATION.md`.
- Локальная разработка и проверки используют только Podman. Docker не нужен.
- Stage содержит Managed PostgreSQL 17 и Serverless Containers. Миграции
  доставляются автоматически через GitHub OIDC, private runner и forward-only
  policy; `fit_api` не имеет прямых domain grants, а private push timer создаётся
  только после отдельного cost approval и health-check точной ревизии.
- Ограниченный Yandex ID pilot и доменная цепочка представлены в `000001–000027`:
  `000026` добавляет actor-scoped Assistant state, `000027` — безопасное linking
  FIT-профиля с Yandex ID и read-write app-session только через явный
  `yandex`/`read_write` rollout assignment. Assistant, session digests и push
  secrets не выставляются через `ops_readonly`.
- Live AI smoke: parser прошёл, summary получил 400 из-за формата тестового запроса; исправление и повтор описаны в `docs/design/CLIENT_PROGRESS_AI_VERIFICATION.md`. Native AI использует metadata IAM token без статического ключа; точную роль
  один раз выдаёт `fit-stage-api` администратор, а OIDC не меняет folder IAM.
- Yandex OAuth использует PKCE и публичный Client ID; secret browser-контракту
  не нужен, Supabase-сессия при пилотном входе не создаётся. Production callback
  зарегистрирован для `fit-drab.vercel.app`; stage API допускает этот origin,
  но production rollout остаётся default-off до настройки Vercel allowlist.
- `main` содержит 14-дневную read-write Yandex ID-сессию: stage валидирует/отзывает opaque token, frontend восстанавливает профиль и блокирует истёкшую/неразрешённую сессию.
- Серверный `yandex/read_write` rollout первого перенесённого tenant управляется
  отдельным manual-only workflow из `main`: он использует уже существующий
  masked `FIT_TENANT_TRAINER_ID`, проверяет role-specific domain root и имеет
  идемпотентные `inspect`/`enable`/`disable`. Операция не применяет миграции,
  не создаёт платные ресурсы и не выводит UUID профиля.
- `main` расширяет единый Yandex API-контракт на read-write app-session:
  клиенты, связи, замеры/цели, тренировки, feedback и push state принимают
  `x-fit-session`; одновременная отправка read-only и read-write credentials
  закрывается с `401`. После безопасной привязки сервер сразу возвращает
  app-session только профилю с действующим `yandex`/`read_write` assignment;
  сама привязка сохраняется и для профиля, ещё не включённого в rollout.
- `main` содержит независимый default-off sticky route основного Trainer
  Assistant для одного перенесённого профиля. История, turns/actions,
  упражнения, parser и training summaries используют одну `x-fit-session` и
  Yandex API; mismatch или ошибка не переключают отдельный запрос на Supabase.
  Остальные пользователи и вкладки сохраняют текущий Supabase backend.
- `main` содержит отдельный default-off sticky route всего основного
  интерфейса для ровно одного перенесённого profile UUID. Профиль, клиенты,
  упражнения, цели/прогресс, тренировки/Live/post-workout, приглашения,
  Assistant, сводки, feedback и push используют один `x-fit-session`; ошибки
  не переключают отдельные запросы на Supabase. После выбора Yandex backend
  старая browser Supabase-сессия завершается. Вне allowlist production не
  меняется; UI и маршруты остаются прежними.
- Yandex migration `000035` сохраняет author-scoped пользовательские упражнения; доступ и `created_by` остаются tenant-safe.
- Yandex migration `000038` приводит push к multi-device контракту Supabase: отдельный PK подписки, `(user_id, endpoint)`, адресная строка outbox и удаление только протухшего устройства. API принимает endpoint только в actor-authenticated body; tenant catalog переносит подписки по `id`.
- YAFIT-490/510: личный чат спортсмена с каждым тренером хранит текст и приватное фото, черновик и повтор отправки без дубля. Меню даёт ответ/копирование и авторские изменение/удаление; фото открывается с zoom/save, поиск работает по всей истории, первое непрочитанное фиксируется точной парой времени и ID и отмечается только после показа. Отключение сохраняет переписку без возврата доступа к данным. Supabase использует realtime, Yandex — polling/foreground refresh; Web Push ведёт в диалог. Assistant не читает чат и вложения.
- `main` содержит `000036`: receipts/retry Telegram/Tracker и четыре analytics
  views. В кластере сохранён уже включённый managed access для DataLens, но
  отдельный пользователь, подключение и перенос дашбордов пока не выполнялись.
- Стабильный Vercel Preview синхронизируется с verified `main`; полноценная
  app-session использует прежний UI и read-write stage API. Вне allowlist
  production остаётся на Supabase.
- Реальный invite → join → leave/remove smoke — внешняя проверка.
- Remote rehearsal маскированно выбирает cohort и закрепляет fingerprint; run `34589510827` перенёс 5 строк tenant, проверил 30 таблиц и идемпотентность. Production Supabase не изменён.
- Source-only audit `34621729406` нашёл masked standalone-client на 196 строк:
  13 тренировок, 60 упражнений и 108 подходов; stage dry-run ждёт merge режима.
