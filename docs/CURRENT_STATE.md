## Активная работа

- Yandex ID/profile vertical slice, серверная tenant-allowlist и постоянный
  stage delivery находятся в `main`: GitHub OIDC без JSON-ключа, один SHA-образ,
  автоматические forward-only миграции перед API revision, private smoke и
  rollback. После `#459` созданы GitHub repository variables, approval
  Environment `yandex-stage`, OIDC-федерация и две subject-привязки к
  `fit-stage-terraform`; оба state-секрета сохранены в GitHub. Первый новый
  plan-run остановился до Terraform на OIDC exchange с HTTP 401; готовится
  безопасная диагностика claims и ответа, без вывода токенов. Production
  frontend и Supabase не переключаются. После `#454` локальный запуск
  автоматически готовит Supabase и PostgreSQL 17, а CI проверяет обе цепочки
  миграций.
- Функциональный MVP признан достаточным для системной фазы удобства. Аудит
  `#420` зафиксировал P0/P1/P2; навигационная ясность завершена в `#421`,
  информационная архитектура Trainer Progress — в `#423`, visual regression
  ключевых маршрутов — в `#425`, типографика — в `#427`, геометрия компонентов —
  в `#429`, единые состояния интерфейса — в `#431`. Мобильная тренировочная
  фаза P0/P1 закрыта финальной приёмкой `YAFIT-316`; desktop shell тренера
  отложен пользователем и не является следующей автоматической задачей.
- Пользователь продолжает продуктовую полировку по одному выбранному экрану за
  раз: отдельные ветка/PR/CI/production-проверка, без автоматического перехода
  к следующему экрану. Главные страницы клиента и тренера сохраняются без
  изменений, пока пользователь отдельно не попросит их менять.

## Последняя проверенная продуктовая точка

- После `#461` сохранённый план показывает компактный список упражнений и
  раскрываемые подходы без потери блоков и интервалов. В `#462` название
  упражнения отделено от спокойного действия «История» с общей SVG-иконкой,
  понятным доступным именем и мобильной зоной нажатия. На карточке управляемой
  тренировки изменение остаётся видимым, а редкие копирование и удаление
  собраны в подписанное overflow-меню; read-only доступ не расширен. Данные,
  доступы, LLM, SpeechKit и главные страницы ролей не менялись.
- Экран планирования из карточки спортсмена использует зафиксированный контекст
  клиента в шапке, сохраняя переключатель «План / Завершённая». Дата и начало
  собраны компактно, окончание и заметка раскрываются по необходимости,
  голосовой/текстовый ввод сворачивается после добавления упражнения, а каталог
  и массовые операции больше не дублируются. Бег с RPE не сжимает время,
  дистанцию и единицы измерения в одну строку. Расчёты, LLM, SpeechKit и главные
  страницы ролей не менялись.
- После `#452` карточка спортсмена у тренера использует одну компактную сводку
  вместо двух равнозначных таблиц, одно главное действие планирования и
  спокойные переходы в историю и прогресс. Редактирование профиля находится в
  overflow-меню, цель показана раньше ближайших назначений, заметка облегчена,
  дублирующий заголовок ближайших тренировок удалён. Расчёты, доступы, LLM,
  SpeechKit и главные страницы ролей не менялись.
- `YAFIT-316/P1.9` закрыл финальную мобильную приёмку P0/P1. Creation, review,
  plan, Live, завершение и history проверены как один путь; пустое и частичное
  выполнение, 10 подходов, длинные названия, отдых, сетевой retry, touch-зоны и
  состояния CTA защищены WebKit/component/e2e. Desktop и P2 не начинать без
  отдельного решения пользователя.
- После `#423` первый экран Trainer Progress отвечает на три вопроса: какова
  регулярность клиента, где есть измеримый прогресс и что требует внимания.
  Подробный AI-анализ и замеры доступны отдельными уровнями; расчёты, LLM,
  SpeechKit и главные страницы обеих ролей не менялись.
- В рамках `YAFIT-315/P1.7` подтверждённый положительный результат получил
  единый success-акцент на вторичных экранах: личный рекорд в истории и карточке
  упражнения, главный вывод Client Progress и недельный результат Trainer
  Progress. Расчёты, тексты LLM и главные страницы обеих ролей не менялись.
- В рамках `YAFIT-315/P1.8` пользовательские подписи Progress и истории
  приведены к понятному русскому языку: «Личный рекорд» вместо «Новый рекорд»,
  «ИИ-анализ» вместо `AI`, «в неделю» вместо сокращения; счётчики используют
  правильные формы слов. Проценты остаются целыми, остальные числа Progress —
  максимум с одним знаком после запятой.
- После `#415`–`#417` беговой MVP покрывает форматы, интервалы, активное
  восстановление, смешанные тренировки, голосовой/текстовый ввод и компактный
  confirmed-only прогресс. LLM, SpeechKit и сравнение темпа между несопоставимыми
  дистанциями не менялись.
- После `#398` Progress клиента собран вокруг goal-aware LLM-сводки: тренировочная
  сводка учитывает активную цель клиента, `TrainingSummaryCard` показывает статус
  цели и качество данных сводки.
- После `#395` любая завершённая тренировка считается состоявшейся, даже если
  план выполнен частично; Client Home отдельно и понятно показывает упражнение,
  точный подтверждённый результат и тип персонального рекорда.
- После `#393` voice-first остаётся первым действием Client Home: микрофон и
  ввод текстом сохранены над остальными блоками. Progress показывает главным
  показателем все завершённые тренировки за неделю или месяц, а назначенный
  план — отдельной расшифровкой. Форма замера свёрнута; LLM-сводка и периоды
  1/3/6 месяцев не менялись.
- Изолированный Yandex Cloud stage содержит приватные Managed PostgreSQL 17 и
  Serverless Container без прогретых экземпляров. Миграции `000001`–`000003`
  применены; API readiness подтверждён. Код `#413` добавил проверку Yandex ID,
  hashed identity mapping, allowlist и read-only `/v1/profile`, но миграция
  `000004` и новая revision ещё не развёрнуты. Production frontend продолжает
  использовать Supabase, публичный invoker и frontend cutover не включены.

## Последние проверки

- `#459`: полный `npm run check` прошёл после подливания `main`; GitHub CI и
  Vercel прошли перед merge. Первый Yandex stage workflow не применял Terraform,
  не загружал образ и не запускал миграции. После OIDC/bootstrap-настройки
  повторный run также остановился до Terraform на token exchange HTTP 401.
- `#454`: GitHub migration-safety/app/database/yandex-database/e2e и Vercel
  прошли. Локально прошли `npm run check`, `npm run local:verify`, повторный
  запуск pending-миграций и smoke `/health`, `/ready`, frontend. Обычный dev не
  очищает базы и не обращается к Yandex Cloud.

## Ближайший roadmap

1. Исправить OIDC exchange по безопасной диагностике, получить и проверить
   Terraform plan, затем отдельно одобрить миграцию `000004` и private auth
   revision; production frontend не переключать.
2. Продолжать UI-полировку только с экрана, который явно выберет пользователь;
   не собирать несколько экранов в один PR. Desktop shell тренера и P2
   отложены и без нового прямого решения не начинаются.

Ручной беговой MVP `YAFIT-300/301/307/302/303` завершён. Актуальный UX/UI-план
и отложенные фичи находятся в `docs/design/PRODUCT_USABILITY_AUDIT_2026-08-18.md`

## Постоянные ограничения

- LLM-разбор и SpeechKit не менять без отдельного продуктового решения.
- UI перед сдачей проверяется на Client 390/430 px и Trainer 1440 px; для
  мобильных сценариев обязателен WebKit.
- После merge изменений приложения обновляется и заново запускается iOS bundle.
- Локальные контейнеры и Supabase запускаются только через Podman. Docker у
  пользователя не установлен и не планируется; не предлагать его установку.
  Когда Podman недоступен, обязательные migration/pgTAP-проверки выполняются в
  CI. Production-секреты не читаются и не выводятся.
- Backlog и статусы подтверждаются через YAFIT; этот файл — индекс, не замена
  Tracker.
