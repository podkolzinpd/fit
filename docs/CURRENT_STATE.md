## Проверки

- Для этой документационной ветки обязательны смысловая проверка ссылок и
  `git diff --check`; сборка приложения не требуется.
- Проверки продуктового кода фиксируются здесь только после фактического запуска,
  без переноса старых зелёных результатов на новый commit.

## Постоянные ограничения

- LLM-разбор — основная функция продукта; UI-правки не меняют его prompt,
  matching, fallback и сохранение без отдельного решения.
- UI перед сдачей проверяется в WebKit на ширине 390 px.
- После merge изменений приложения обновляется и заново запускается iOS bundle.
- Текущий backlog и статусы задач подтверждаются через YAFIT; этот файл служит
  индексом, а не заменой Tracker.

## Как обновлять этот файл

- Обновить дату и проверенный commit `main`.
- Удалить завершённую активную работу и записать одну следующую задачу.
- Оставить только последние значимые изменения, нужные для продолжения.
- Записать только реально выполненные проверки и актуальные блокеры.
- Не добавлять дневник, полный список PR, длинные логи или пересказ сессии.
