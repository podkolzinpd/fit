- После полного завершения клиент видит сбалансированный итог с доступными
  фактами и общим для Home/Progress подтверждённым личным результатом. Рекорд
  и рост показывают дельту к прошлому факту. «Поделиться» даёт
  выбрать «Итог», «Достижение» или «Прогресс»; третий сюжет доступен только при
  сопоставимой прошлой тренировке. Каждый вариант получает собственный PNG
  `1080×1350`, fallback — текст. Health-пилот показывает калории только с
  устройства за точный интервал. Частичный итог безопасен, но не является
  визуальным референсом; обратная связь и детали остаются ниже.
- Live сохраняет каждое изменение подхода на устройстве, автоматически досылает pending-черновики и ограничивает зависшие запросы. Finish сначала отправляет
  открытую строку; ошибка закреплена у повтора. Поля и действие собраны в
  полноширинную строку высотой 48 px, а соседние подходы разделены интервалом
  8 px. Статус сохранения вынесен из зоны действий и не перехватывает нажатия.
  Пустой прошлый результат скрыт, отдых настраивается одной короткой строкой,
  а техника без проверенной анимации остаётся компактной и текстовой.
  При открытой iOS-клавиатуре активная строка веса или повторений автоматически
  остаётся внутри видимой области; прокручивается только содержимое приложения.
  Активное упражнение не обёрнуто во вторую округлую карточку, а план
  раскрывается по требованию без изменения сохранённых плановых данных.
  Подтверждённый фактический вес подставляется дальше внутри той же плановой
  группы; ручной факт важнее, будущие подходы и сам план заранее не сохраняются.
  После 20 минут без содержательного действия клиент получает одно мягкое
  напоминание с возвратом в Live и выбором продолжить или завершить. Работающий
  отдых продлевает окно; завершение, удаление и отключение настройки снимают
  уведомление. По окончании отдыха кнопка остаётся в success-состоянии
  `Отдых завершён` до следующего подтверждённого подхода или нового отдыха,
  в том числе после возврата приложения из фона.
  В iOS доставку планирует ОС, в вебе есть service-worker и inline
  fallback при следующем открытии.
- Клиент может безопасно отключить текущего тренера в профиле: серверная
  операция атомарна, повтор идемпотентен, самостоятельная история, назначения,
  замеры и цели сохраняются. Серверное переподключение после явного отключения
  использует тот же атомарный merge и не допускает двух активных тренеров.
- Новые одноразовые коды приглашения в клиентском профиле, карточке клиента у
  тренера и первом плане имеют единый compact copy-action, подтверждение
  «Скопировано» и fallback для iOS/WebView.
## Инфраструктура и Yandex Cloud
- Chat media repair (2026-09-15): Supabase bridge принимает `204 No Content`
  от `authorize_chat_* RETURNS void`, не пытаясь разобрать пустое тело как JSON.
  Регрессия воспроизведена до исправления (upload/sign/remove возвращали 503);
  API adapter/route tests после исправления проходят. Live S3 smoke ключами
  активной stage-ревизии выявил отдельный `PutObject 403 AccessDenied`:
  prefix-scoped policy не заменяет базовые IAM/ACL grants, а cross-cloud
  аккаунт Yandex не принимает ни в IAM, ни в ACL. После подтверждения владельца
  создан bucket-owned `fit-chat-media` account с READ/WRITE ACL и теми же media
  prefix restrictions; отдельный stage Lockbox доступен только API/migration.
  Его immutable IDs выбираются через `YC_STAGE_MEDIA_S3_CREDENTIALS`; старый
  stage secret/key сохраняется. Новый ключ прошёл реальную запись, повтор и
  signed GET 200 с совпадением байтов. Подключение к API ожидает merge/deploy;
  E2E отправка фото пока НЕ подтверждена.
- ИИ-анализ Progress использует контракт `training-progress-v14` и агрегатор
  `summary-aggregate-v3`: статистика считается по всем упражнениям, сильнейшие
  сигналы передаются подробно, остальные — компактным индексом и полным
  rollup. Модельный JSON целится в 19 000 символов при жёстком пределе 20 000,
  ответ — 1 000 токенов. Fingerprint включает итоговый агрегат, модель и версии
  правил; точный кеш используется даже при ручном обновлении. Общая
  блокировка в БД исключает параллельные вызовы между serverless-инстансами,
  повтор ошибки подавляется 30 минут, на период разрешён один платный вызов в
  сутки, на клиента — не более трёх. Открытие, focus/reconnect/remount, новый
  день и переключение периода вообще не вызывают endpoint генерации: создать
  или обновить анализ можно только явной кнопкой. Один готовый результат модели
  используется клиентом и тренером без второго вызова, при этом внутренний текст
  тренера клиенту не раскрывается. Автоматические retry и AI-repair удалены,
  есть аварийный выключатель генерации. Автотесты используют только mock-ответы
  и локальную БД; live AI smoke не запускается. Полный чеклист —
  `docs/design/PROGRESS_AI_EXPLICIT_REFRESH.md`.
- Quality gate ИИ-анализа блокирует неподтверждённое утверждение об изменении
  техники, но не отбрасывает весь безопасный ответ из-за нейтрального указания
  на отсутствие наблюдений или общего напоминания. После расходующего лимит
  отказа качества интерфейс не предлагает немедленный повтор; временные ошибки
  сохраняют retry. План и проверки: `docs/design/PROGRESS_AI_TECHNIQUE_QUALITY_GATE_FIX.md`.
- Неудачная генерация учитывается в общем дневном лимите, но после общей для
  периода 30-минутной паузы освобождает периодный слот. Успешная и действующая
  pending-попытки по-прежнему блокируют дубль, просроченный lease — нет. Yandex
  repository сохраняет точный код ошибки генерации, поэтому интерфейс не
  показывает общий retry для cooldown/лимита/quality failure. План:
  `docs/design/PROGRESS_AI_FAILED_ATTEMPT_RETRY_FIX.md`.
- Подтверждённый production `401 authentication_required` возникает до
  collector/model gate, когда браузер отправляет устаревший Supabase access
  token. Summary transport обновляет существующую сессию только после такого
  ответа и повторяет запрос ровно один раз; лимиты, cooldown и остальные ошибки
  не повторяются. Служебный бесплатный preflight использует фактический backend
  клиента, а оставшийся `401` показывается как истёкшая сессия. План:
  `docs/design/PROGRESS_AI_SESSION_RECOVERY.md`.
- Backend-only RPC блокировки генерации и публикации общего кеша защищены
  узкими `EXECUTE` grants только для `service_role`; они не зависят от browser
  JWT/session GUC. Это устраняет production `PT403` до model request, сохраняя
  нулевой расход токенов на кешированных, заблокированных и тестовых вызовах.
- Локальная разработка и проверки используют только Podman. Docker не нужен.
- Stage содержит Managed PostgreSQL 17 и Serverless Containers. Миграции
  доставляются автоматически через GitHub OIDC, private runner и forward-only
  policy; `fit_api` не имеет прямых domain grants, а private push timer создаётся
  только после отдельного cost approval и health-check точной ревизии.
- Ограниченный Yandex ID pilot и доменная цепочка представлены в `000001–000027`:
  `000026` добавляет actor-scoped Assistant state, `000027` — безопасное linking
  FIT-профиля с Yandex ID и read-write app-session только через явный
  `yandex`/`read_write` rollout assignment. Assistant, session digests и push
  secrets не выставляются через `ops_readonly`.
