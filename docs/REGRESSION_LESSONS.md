## RL-QUICK-PILOT-ISOLATION-20261029 — эксперимент и прежняя приёмка

Область: все экраны и новые независимые флаги. Synthetic ID старых UI fixtures
может совпадать с новым пилотом. Нельзя включать новый флаг глобально в test
webServer: старая приёмка неожиданно проверит другую композицию. Новый сценарий
получает явный acceptance opt-in; CI обязан передавать его в dedicated harness.
Проверить gate-on новый путь и неизменённый gate-off старый путь. Не менять
старые assertions, baseline или digest ради скрытия этой ошибки.

## RL-STACKED-PR-BASE-20261030 — свежий head не означает свежую базу

После squash предшественника сохранённая ветка может остаться base следующего
PR: GitHub не обязан автоматически перевести его на main. Перед дорогим CI
проверять baseRefName/base SHA вместе с head SHA, состоянием предшественника
и фактическим diff. При завершённом предшественнике retarget на main сделать
до synchronize/current-head CI. Старый зелёный head или равенство файлов сами
не подтверждают правильный целевой merge. Случай1879 и исправление сохранены
в [каноническом журнале, итерация37](design/CLIENT_REFERENCE_SCREENS_20261029.md).


## RL-PUBLIC-PROFILE-SESSION-20261030

Публичная анкета может загрузиться раньше приватной app-session. Безусловный
useDataBackend в её кнопке чата приводил к render-crash ещё до проверки actor.
Использовать существующий optional context в публичной оболочке и отдельный
защищённый child после готовности; не ослаблять backend контракт закрытых страниц.
Проверять удержанным ответом сессии: анкета/ссылка входа доступны до него,
обычная кнопка чата — после. Разбор CI/old-red→fixed-green: клиентский план,
[итерация41](design/CLIENT_REFERENCE_SCREENS_20261029.md).
