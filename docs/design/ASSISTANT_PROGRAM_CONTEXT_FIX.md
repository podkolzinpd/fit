# Assistant: сохранение анкеты и влияние истории на нагрузку

Локальная ветка `codex/program-context-load-fix` от `3f4e178f`.
Работа из бокового диалога: исходная рабочая копия, PR #955 и production не меняются.

## Согласованные проверки

1. Первый ответ сохраняется, включая условия до однозначного выбора клиента.
2. Уточнение ограничений всегда содержит понятный ответ и следующий шаг;
   заполненность анкеты отделена от возможности генерации.
3. Однозначная частота проверяется по исходному сообщению. Несоответствие
   цитате, противоречие и неоднозначность требуют уточнения.
4. История и анкета дают одну основу нагрузки для модели и числовых назначений:
   фактическую частоту, объём, свежесть, знакомые упражнения и пробелы.
5. При неполной/старой истории стартовый режим подписан явно; по отсутствию
   записей нельзя утверждать, что человек не тренировался.
6. Другая активность уточняется до вида, частоты и дней, без универсальных
   коэффициентов. Совпадающие дни требуют отдельного уточнения.
7. Один набор упражнений с разной историей получает разные числовые назначения;
   видно, что изменилось и почему. Сохраняется срок четыре недели и 4/8/12 занятий.
8. Уточнение пользователя «это неочевидно»: вопрос о полноте истории показывается
   в карточке с двумя явными кнопками. Тренеру не нужно знать специальную фразу.

## Реализация и границы правил

- `program-context-v2` сохраняет агрегат каждого состоявшегося занятия до
  ограничения последних исполнений упражнения тремя записями. Состав SQL-запросов
  и права доступа не меняются. Считаются только положительные подтверждённые
  повторы/секунды размеченного упражнения; custom/неизвестные ref не выдают
  сопоставимый объём. Обычный счётчик состоявшихся тренировок включает их.
- `observed-load-v1` использует 28 дней до даты среза включительно, четырьмя
  семидневными окнами. Нулевые недели учитываются, крайние календарные недели не
  экстраполируются. Для опытного клиента регулярными считаются записи минимум
  в трёх окнах с последней сопоставимой записью не старше 14 дней.
- При такой истории и отсутствии известных пробелов: до трёх подходов,
  RPE 7, недельный объём не выше записанного среднего. Повышение частоты
  распределяет тот же предел между большим числом дней. Необязательное
  упражнение убирается, если мешает уложиться в предел.
- При возврате, старых/неполных данных или начальном опыте: до двух подходов,
  RPE 6,5; первые две недели одинаковые, третья добавляет повтор/5 секунд,
  четвёртая закрепляет. Временной бюджет может дополнительно уменьшить подходы.
- Это явные продуктовые правила стартового пилота, не измерение способности
  клиента восстанавливаться и не доказанная сравнительная методика. Числовые
  веса не назначаются. Сравнение с программами тренеров остаётся отдельной задачей.
- Для достаточной истории минимальный совместимый объём — пять обязательных
  движений × выбранная частота. При конфликте сначала уточняется полнота записей.
  Если подтверждена неполнота, применяется явно объяснённый стартовый режим;
  если полнота — предлагается меньшая частота или ручное составление.
- Карточка использует существующие `assistant-flow-card`, `assistant-message-copy`,
  `assistant-flow-actions`, нейтральные поверхности и кнопки Fit. Основное действие
  после уточнений — «Подтвердить и составить». Новые стили и токены не добавлены.
- Native Yandex chat остаётся выключенным: используется существующий общий
  orchestrator и приватная Yandex Cloud Function с Supabase actor/RLS-источником.
  Схема БД, флаги, allowlist, deployment и сохранение программы не меняются.

## Проверка

`generate.test.ts`, `yandex-program-generator-function.test.ts`,
`AssistantProgramPilotCard.test.tsx`. Все LLM-вызовы в тестах заменены фикстурами;
платная генерация и клиентские данные в production не использовались.

Локальный `npm run check` прошёл: 1 553 frontend tests, проверки infra/types,
lint/typecheck и build. После финальной проверки прогрессии повторный API check
прошёл: 582 tests; 32 DB integration tests пропущены без локальной БД, схема БД
не менялась. Последние правки текста/расположения кнопок проверены целевыми
96 API tests и 6 component tests. Регрессия двухосевой прогрессии проверяет
явное одновременное увеличение повторов и усилия, независимо от стартовой схемы.

WebKit-матрица расширена вопросом/кнопками на 390/430/1440 px в обеих темах.

завершение WebKit до выполнения проверок. Визуальная приёмка и реальный
чат → Cloud Function → сохранение остаются непроверенными.
