# Актуальные названия только в новой копии

## Подтверждённое решение пользователя — 03.09.2026

> Старые тренировки оставить как есть, а новые названия подставлять только в
> создаваемую копию.
>
> Вот так было бы хорошо и не нужно перезаписывать старые.
>
> Только давай супер аккуратно, важно не сломать старые записи, хоть их и не много.

## Acceptance

1. Только создание копии обновляет известное старое каталожное название по
   точному системному ref и совместимому inputKind.
2. Исходная запись, просмотр истории и редактирование плана/результата
   сохраняют прежние названия. Нет backfill, SQL, миграций или удаления данных.
3. Custom, неизвестные ref/названия, несовместимые поля и специальные подписи
   (включая беговые отрезки) не переименовываются.
4. Ни ref, ни пользовательские комментарии, ни варианты упражнений не
   объединяются. Прежний перенос факта в план новой копии не меняется.
5. Восстановление незавершённой копии также показывает актуальные известные
   названия; её локальный черновик не подставляется при редактировании оригинала.
6. Проверяются Client 390/430 и Trainer 1440, light/dark, Chromium/WebKit,
   отправка новой копии без id оригинала и неизменность исходных данных.

## Реализация

- `copiedExerciseName` распознаёт только известные названия прежнего каталога
  и раннего базового набора; нормализует регистр, е/ё и пробелы, но не угадывает
  упражнение по синонимам или похожести.
- `copyWorkout` по умолчанию сохраняет snapshot. Обновление opt-in включается
  только в ветке новой копии; `completedWorkoutDraft` его не включает.
- Редактирование не восстанавливает creation-only local draft. Новая копия
  сохраняет набранные значения и обновляет только безопасно сопоставленное имя.
- UI: прежние `WorkoutExerciseEditor`, `WorkoutExerciseHeader`, `Field`,
  `WorkoutCta`; primary «Сохранить план». Новых CSS/токенов/coachmarks нет.
- Production-аудит всех записей не выполнялся: Supabase CLI и доступный браузер
  не авторизованы. Тесты используют локальные fixtures и все 663 справочных ref;
  это не выдаётся за чтение production-истории.

## Проверки

- Целевые unit-контракты: 107/107. Включены все 663 исторических каталожных ref,
  совпадающие custom-названия, неизвестные подписи, беговые форматы и сохранность
  полного исходного объекта.
- Полный `npm run check`: пройден; 1142 frontend unit, 306 API tests
  (29 существующих DB-integration tests skipped), lint/typecheck, coverage,
  generated types, iOS permissions, 80 infra-policy tests и build.
- Browser: 6/6 — Client 390/430 и Trainer 1440 в Chromium и WebKit,
  каждый в light/dark. Проверены создание/восстановление/сохранение копии,
  повторное открытие оригинала и редактирование при незавершённой копии.
  Снимки исходной записи, копии и обеих exercise cards проверены локально.
- Дополнительный параллельный прогон со снимками дал два мобильных WebKit
  сбоя (в том числе Page crashed). Оба повторены последовательно: 2/2,
  без изменения production-кода и без ослабления проверок.
