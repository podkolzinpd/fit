# Привязка тренера и спортсмена по коду

## Проблема

Обмен кодами и проверка ролей работали, но вход в ручной ввод кода находился
только в настройках. В профиле спортсмена была видна генерация кода для
тренера, а ввод кода от тренера отсутствовал. У тренера ввод кода спортсмена
также был отделён от рабочего списка клиентов. Из-за этого два направления
подключения выглядели как незавершённый сценарий.

## Acceptance

1. Спортсмен из блока связи с тренером открывает «Ввести код тренера», вводит
   полученный код и после успеха возвращается в свой кабинет.
2. Тренер из списка клиентов открывает «Ввести код», вводит код спортсмена и
   после успеха открывает подключённую карточку клиента. Вход доступен и при
   пустом списке клиентов.
3. Экран подключения явно различает роли: спортсмену предлагает код тренера,
   тренеру — код клиента. При открытии ссылки приглашение и основное действие
   также называют правильную сторону.
4. Возврат и swipe-back ведут спортсмена в профиль, тренера — в список
   клиентов. Ошибки, повторная отправка, отзыв, срок, одноразовость и безопасная
   смена тренера сохраняют существующее поведение.
5. Схема данных, права, чат, уведомления и ИИ-контур не меняются.

## Матрица проверки

| Пункт | Видимый результат | Проверка | Статус |
| --- | --- | --- | --- |
| 1 | «Ввести код тренера» в профиле спортсмена | component + сквозной mobile Chromium | Выполнено |
| 2 | «Ввести код» в списке клиентов, включая пустое состояние | component + сквозной mobile Chromium | Выполнено |
| 3 | Ролевые заголовки и тексты `/join` | visual 390/430/1440 + e2e | Выполнено |
