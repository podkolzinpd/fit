# Клиентский Lime: переключатель режимов карты тела

Продолжение разрешённого завершения клиентского дизайна. База — main28309ef4 после PR#1468. Дополнительный WebKit-проход раскрыл все семь разделов ПРО; при просмотре снимков обнаружен один новый подтверждённый остаток, V20/P1.

## Неизменяемый план

1. V20: «Прогресс / Нагрузка» в раскрытой карте тела использует legacy pseudo-surfaces с radius9px/7px (`styles.css:2233–2237,3867–3870`, `TrainingBodyProgressMap`). Подтверждено в работающем WebKit390D. Клиентское место — `ClientBodyMapDisclosure` в ПРО. Тренерские потребители общего компонента не меняются.
2. Подключить `.body-progress-modes` к уже существующему клиентскому segmented-контракту `fit-client-lime.css`: контейнер28px/padding4/gap4, сегмент44px/radius24px, текущие Lime surface/divider/accent/text-on-accent. У этого компонента selection выражен через `aria-pressed`, а не `.active`; учесть это CSS-селектором и отключить старые псевдоповерхности только внутри client scope. Тексты, выбор режима, данные и расчёты не менять.
3. Расширить приёмку заполненного прогресса: действительно открыть все семь ПРО-разделов; режимы карты «Прогресс / Нагрузка» переключаются, selected стили соответствуют существующему контракту, обе темы390/430, пустая карта и карта с подтверждённым подходом, нижний край доступен. Проверить другой клиент и тренерский shared-компонент без изменения старой геометрии.
4. Полный check, обязательные CI/Android, штатный merge и проверка итоговой опубликованной версии, содержащей #1468 и эту правку. Не объявлять полностью проверенными остальные состояния по одному новому тесту.

## Не добавляем неподтверждённые правки

«Спереди / Сзади» уже pill/44px; числовые клетки графика регулярности не являются кнопками и карточками верхнего уровня. Их не перекрашиваем и не меняем по одному внешнему сходству. Нейтральные действия цели и семантические состояния сохраняются. Главная, Live, создание и trainer не перепроектируются.
