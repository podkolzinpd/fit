# Безопасное отключение выбранного тренера — 2026-10-07

Продолжение согласованного пункта6 [GitHub#1492](https://github.com/podkolzinpd/fit/issues/1492).
Владелец разрешил исправлять воспроизведённые дефекты и штатно выпускать изменения.

## Воспроизведение

Два настоящих WebKit-контекста, Fastify API и собственная PostgreSQL17.
Современная карточка принадлежит спортсмену; тренер подключён одновременно
через membership и явную active relationship, как после приглашения.
Профиль → меню выбранного тренера → Отключить → подтверждение:
API возвращает204 и интерфейс сообщает успех, но active relationship остаётся.
Следующее чтение /connections снова содержит этого тренера; доступ не закрыт.
Yandex writer перенёс только старый membership-only контракт, без уже существующей
legacy-логики закрытия явной связи. Отмена отключения корректна.

Отказ для старой trainer-owned карточки — отдельное предусмотренное ограничение,
не повод автоматически переносить или удалять историю. Оно сохраняется.

## Изменение

- Только numbered Yandex migration135, публичная команда и маршрут прежние.
- Актор — серверная сессия: роль client и владение карточкой обязательны;
  UUID выбранного тренера не предоставляет права.
- Под блокировкой карточки закрыть active relationship выбранного тренера
  с disconnected_at/by и удалить только его membership в одной транзакции.
- Повтор успешен; membership-only, relationship-only и обе формы поддержаны.
- Другие тренеры, карточка, тренировки, замеры, цели и финансы не меняются.
- Прежний writer сохранён для точного Down, но закрыт от public/fit_api.
- Не добавлять Supabase migration, новую кнопку, новый дизайн или автоматическую
  миграцию legacy trainer-owned карточки. Самостоятельный выход тренера —
  другой контракт и не объявляется проверенным этим исправлением.

## Приёмка

Пять actor/RLS регрессий: три источника доступа, независимость второго тренера,
сохранение истории/владения, повтор, запрет бывшему тренеру, запрет чужому актору,
legacy guard и минимальные grants. Чистая цепочка, полный npm run check,
обратимость migration135, настоящий UI/API/DB цикл в старом и Lime-дизайне.
Выпуск только после всех более ранних активных PR (#1493–#1496), обновление от main
и свежий обязательный CI перед каждым merge. Production ещё не подтверждён.
