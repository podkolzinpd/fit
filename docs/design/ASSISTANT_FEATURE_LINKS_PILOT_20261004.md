# Assistant feature links pilot — 2026-10-04

## Решение

Ассистент отвечает на навигационные вопросы готовой внутренней ссылкой. Например,
«Где лежит продвинутая сводка прогресса?» ведёт клиента на
`/me/progress?view=pro`. Ответ строится детерминированным каталогом маршрутов до
LLM, поэтому модель не придумывает URL.

Каталог покрывает стабильные разделы клиента и тренера. Для trainer-only страниц
конкретного клиента ссылка формируется только после единственного совпадения
имени с доступной actor-scoped карточкой. Frontend принимает только заранее
разрешённые относительные маршруты; внешние и неизвестные URL отбрасываются.
Естественные вопросы по русским и английским названиям функций, включая InBody,
ведут сразу в нужный раздел. По запросу ассистент показывает полный каталог для
текущей роли, а неизвестную функцию явно называет неизвестной вместо ложного
совпадения с общим разделом.

Вызов навигатора основан на намерении, а не на обязательных словах «где» или
«в приложении»: поддерживаются короткое имя функции, «покажи», «посмотреть»,
«хочу в», «мне нужен», «как» и явные команды перехода. Запись тренировки в
Assistant всегда навигирует в основной composer главной страницы; отдельный
record-workout action здесь не запускается даже при прямой диктовке клиента и
упражнений. Старый незавершённый record-workout черновик не восстанавливается,
не принимает новые фрагменты и не блокирует запуск программы. Генерация
программы и подготовка сводки остаются в action pipeline.
Ответ «что умеешь» отражает фактический пилот: составление программы,
навигация по приложению и короткий разговор о фитнесе и спорте. В квизе
программы видны примеры ответа, а команда продолжить прежний курс наследует
условия последней программы и не запускает полный опрос заново.
Каталог сверяется с реальными статическими маршрутами клиента и тренера; для
контекстных экранов тренера поддержаны карточка, редактирование, тренировки,
цель, финансы, прогресс и замеры конкретного однозначно найденного клиента.

## Rollout

- Независимый default-off выключатель — `enabled` в приватном database allowlist.
  Серверный experiment переносит это решение во frontend; browser allowlist нет.
- Персональный серверный allowlist хранит только SHA-256 нормализованного native
  Yandex login `brainbuster98`, без email и публичного UUID. Миграция `000123`
  заменяет ошибочно внесённый login, снимает возможную старую привязку и
  разрешает повторное связывание только после проверенного OAuth callback.
- Привязка к профилю выполняется после проверенного Yandex OAuth callback и
  только для роли `trainer` или `client`.
- Остальные аккаунты продолжают проходить прежний Assistant pipeline и не
  получают link markers.
- Уже открытая до выпуска FIT-сессия не содержит подтверждённый Yandex login.
  Маршрут `/auth/yandex/refresh-assistant` обновляет её через обычный PKCE
  callback без предварительного выхода и возвращает пользователя в Assistant.
  Backend по-прежнему привязывает флаг только после проверки разрешённого login.

## Приёмка

- [x] Точный ответ для ПРО-сводки клиента.
- [x] Естественные запросы про InBody и замеры ведут в секцию измерений.
- [x] Запрос о доступных страницах или функциях возвращает полный каталог роли.
- [x] Неизвестная функция не маскируется под найденный общий раздел.
- [x] Навигатор вызывается без обязательных якорей «где» и «в приложении».
- [x] Команда записи тренировки ведёт из Assistant в основной composer роли.
- [x] Прямая диктовка тренировки не запускает record-workout action в Assistant.
- [x] Старый record-workout черновик не восстанавливается и не блокирует программу.
- [x] Команды программы и сводки не перехватываются навигацией.
- [x] Контрактные примеры покрывают все опубликованные client/trainer destinations.
- [x] Role-specific каталог стабильных маршрутов.
- [x] Однозначный выбор клиента и UUID-проверка динамического пути.
- [x] Safe-path parser отклоняет внешние и неизвестные ссылки.
- [x] 44 px touch target для ссылок в сообщении.
- [x] Отдельный environment kill switch и database allowlist.
- [x] Повторный callback идемпотентен; выключенный allowlist не включается снова.
- [x] Существующую FIT-сессию можно обновить без выхода; другой Yandex ID не
  заменяет текущий профиль.
- [x] Unit и PostgreSQL integration contracts.

## Откат

Установить `enabled=false` для единственной allowlist-строки и прочитать значение
обратно.
Сохранённые сообщения остаются читаемыми, но новых link markers не создаётся.
