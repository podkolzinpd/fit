# Fit Lime: рабочий день, расписание и тестовое наполнение

Тикет: YAFIT-590 (родитель YAFIT-539).

Подтверждено владельцем 3 октября 2026: «фиксируй план, все делай, выкатывай все сам, разрешаю».
Базовый main: b8fda43315e2e7998e80ddc2d132cf514d9063e2.
Scope: только два ранее согласованных server-assigned тренера Fit Lime, без расширения allowlist.
Контактные данные в публичный план не дублируются; точные аккаунты указаны в запросе владельца.

## Неизменяемый согласованный план

### PR 1. Главный экран — рабочий день

- Убрать отдельные блоки «Продолжить тренировку», «Последняя тренировка», «Начать», «Составить», «Установка и уведомления».
- Оставить дату, незавершённые действия, сообщения, календарь дня и «+».
- Переименовать вкладку «Сегодня» в «День», добавить возврат к сегодняшней дате.
- Сохранить доступ к незавершённым тренировкам через события и карточку действий.

### PR 2. Создание и проведение тренировок

- Единый «+» с выбором «Начать сейчас» или «Запланировать».
- Для планирования подставлять выбранную дату; для начала — текущее время.
- Голосовой и ручной ввод разместить внутри формы.
- Разделить состояния: черновик, запланирована, идёт, завершена, отменена.
- Защитить черновики, исключить дубли при повторном сохранении.
- Не завершать и не удалять старые тренировки автоматически.

### PR 3. Расписание и история

- Режимы «Календарь» и «Список».
- Фильтры по клиенту и статусу, включая проведённые тренировки.
- Переход из недели к выбранному дню.
- Завершённые тренировки сохраняются на своих датах.
- События без времени — отдельной группой.

### PR 4. Установка и уведомления

- Перенести постоянное управление в настройки.
- Разделить установку приложения, разрешение уведомлений и действующую подписку устройства.
- Убрать повторные приглашения, когда подключение исправно.
- При ошибке показывать конкретную причину и способ исправления.

### PR 5. Наполнение двух тестовых аккаунтов

По 15 клиентов каждому тренеру — 30 всего, с обычными вымышленными именами, без видимой пометки «Демо».

По 60 тренировок на аккаунт за прошлую, текущую и следующую недели:

- Спокойные и загруженные дни.
- Несколько тренировок подряд и пересечения.
- Короткие и длинные названия.
- События без времени.
- Пустые планы и планы с упражнениями.
- Завершённые тренировки и по одной незавершённой для проверки продолжения.

Техническую метку происхождения сохраняем скрыто: для повторного запуска без дублей и точечного удаления созданных записей. Существующие данные не изменяем.

Создание не должно отправлять уведомления, начислять оплаты или выдавать ачивки. Изоляцию от реальной статистики проверяем до наполнения.

### PR 6. Итоговая UX/UI-проверка

- Проверить оба аккаунта уже на заполненных календарях.
- Исправить обрезание текста, отступы, перекрытия навигацией и кнопкой «+».
- Проверить формы с клавиатурой, выбор даты и возвраты без потери введённого.
- Пройти сценарии создания, начала, продолжения, завершения и просмотра истории.
- Проверить, что остальные пользователи не затронуты.

Порядок: 1 → 2 → 3 → 4 → 5 → 6. Наполнение идёт перед финальным аудитом, чтобы проверять не пустые экраны. Тесты — в каждом PR.

## Preflight и границы

- Поток product. Существующая Fit Lime identity, оригинальные Figma SVG и YS Geo/REM сохраняются. Новая палитра/шрифты/иллюстрации не создаются.
- Переиспользовать ScheduleV2, FitLimeDatePicker, FitLimePlanComposer, QuickStartWorkoutSheet, Page, Modal, Coachmark, AsyncView, существующие формы и calendar URL helpers. Точные имена подтверждаются по коду.
- Primary на дне/расписании — «+»; в создании — подтверждение выбранного действия.
- PR1–4 не меняют клиентский Home, AI/SpeechKit, финансовые расчёты и условия ачивок. Флаги и серверная авторизация сохраняются.
- PR5: только Yandex migration/API/операционный путь с проверкой actor/точного scope, hidden provenance и идемпотентностью. Никакого ручного SQL в production Dashboard, подключения локальных тестов к prod или Supabase fallback.
- Проверять данные/пусто/loading/error+retry, две пилотные роли и непилотного тренера/клиента, прямые URL, долгие имена, сохранение даты и черновиков, mobile Chromium/WebKit и desktop1440.
- Открытая проверка PR5: определить существующие точки исключения синтетических записей из push/оплат/ачивок/статистики до любой production-записи. Не считать отсутствие client login достаточной изоляцией статистики.
