# YAFIT-764 — безопасные синонимы и сленг каталога

Статус: утверждён пользователем 2 сентября 2026 года. Исходный план и порядок
PR не меняются без нового явного согласования.

## Цель

Все 662 системных упражнения должны находиться по профессиональным,
разговорным и сленговым названиям без неверных автоматических подстановок.

## Жёсткие ограничения

- Не удалять, не переименовывать и не объединять автоматически упражнения,
  созданные тренерами.
- Не менять их идентификаторы и историю тренировок.
- Системные дубли не удалять физически: скрывать только из нового выбора,
  сохраняя старые ref.
- Не отправлять полный словарь синонимов в каждый LLM-запрос.

## Этапы

### PR 1 — безопасность каталога

- Разделение системных и пользовательских записей во всех обновлениях.
- Безопасное скрытие системных дублей.
- Совместимость старой истории и прогресса.
- Регрессии на сохранность пользовательских упражнений.

### PR 2 — поиск всех 662 упражнений

- Нормализация падежей, числа, ё/е, опечаток и оборудования.
- Три уровня соответствий: точные, неоднозначные, поисковые.
- Приоритет недавних и пользовательских упражнений.
- Отчёт конфликтов и бюджет производительности.

### PR 3 — полный словарь и ввод программы

- Проверенные профессиональные, разговорные, сленговые и английские названия.
- Исправление конфликтов и дублей.
- Журавлик в Смите.
- Отделение названия от технических уточнений: хват, негативная фаза, рукоять,
  поочерёдность, положение кистей, выполнение на каждую ногу.
- Контрольный e2e на присланной программе из 21 строки.

## Приёмка

- Все строки контрольной программы распознаются либо дают осмысленный
  подтверждаемый выбор.
- Ноль молчаливых неверных подстановок.
- Подходы, повторы и технические указания не теряются.
- Пользовательские упражнения и их история не изменяются.
- App, database, Chromium/visual и WebKit зелёные; каждый PR выкатывается и
  проверяется отдельно.

## Матрица PR 1

| Пункт | Видимый результат | Проверка | Статус |
| --- | --- | --- | --- |
| Системные и пользовательские записи разделены | Пользовательская карточка остаётся в picker даже при совпадающем имени или ref | unit + component | Выполнено |
| Системные дубли скрыты безопасно | В новом выборе остаётся одна каноническая карточка | unit + component | Выполнено |
| Старая история совместима | Оба прежних системных ref остаются в полном каталоге | unit | Выполнено |
| Пользовательские данные сохранены | Нет миграции, delete/update и автоматического объединения | review + tests | Выполнено |

Loading, error и empty-состояния не меняются: фильтрация применяется только к
успешно загруженной выдаче picker. Права ролей, создание, редактирование и архив
пользовательских упражнений остаются без изменений.
