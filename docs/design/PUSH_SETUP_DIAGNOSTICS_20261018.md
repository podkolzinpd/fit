# Диагностика подключения Web Push — 18.10.2026

## Наблюдение и границы знания

Пользователь показал экран настроек с ошибкой браузера `Push service initialization failed` после попытки включить уведомления. По одному снимку нельзя установить, почему push-сервис отказал: не видны тип запуска приложения, разрешение системы, стадия обращения к PushManager и состояние установки. Доступа к этому телефону и его Web Inspector нет.

Проверка кода показала, что клиент выводил исходное сообщение браузера без этапа и кода поддержки. Также обнаружен отдельный риск: статус подписки может вызвать новую подписку фоном после уже выданного разрешения. Это прежнее поведение из PR #810, а не подтверждённая причина данного снимка. В диагностическом изменении оно не меняется, чтобы не подменить исходный сценарий.

## Узкая правка

- Различать отказ запроса разрешения, регистрации Service Worker, чтения существующей подписки и создания новой подписки.
- При ошибке кнопки «Включить» показать понятное сообщение и копируемый код поддержки с типом платформы, запуском с домашнего экрана и состоянием разрешения.
- Не включать в диагностику endpoint, ключи подписки, VAPID-ключ или полный текст исключения браузера; ничего автоматически не отправлять.
- Не менять запрос разрешения, алгоритм подписки, серверную запись, предпочтения категорий и автоматическую сверку статуса.

## Проверка и следующий шаг

Модульные тесты должны различать четыре этапа и проверять отсутствие ключей в скопированном тексте. На экране настроек кнопка диагностики должна быть доступной для нажатия. После выпуска следует повторить именно неудачный сценарий на устройстве и получить код поддержки. Только по этому результату можно выбирать узкий исправляющий патч и проверять получение тестового уведомления; без повторения нельзя объявлять причину устранённой.

Локально: полный `npm run check` завершился успешно (2734 frontend-теста; API — 1426 пройденных и 160 пропущенных тестов локальной БД), целевой сценарий с отказом браузерного push-сервиса прошёл в WebKit и Chromium. Снимок WebKit просмотрен; целевая кнопка имеет высоту не менее 44 px. Реальный iPhone, фактическая доставка и причина исходного отказа остаются непроверенными.
