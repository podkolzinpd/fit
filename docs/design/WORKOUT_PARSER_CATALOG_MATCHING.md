# Серверное сопоставление упражнений после разбора

Статус: реализовано и локально проверено, ожидает production release. Утверждено владельцем продукта 2026-09-16.

## Неизменяемый план

1. Оставляю внешний формат ответа без изменений. Экраны продолжат получать упражнения, `ref`, подходы, значения и порядок в текущем формате. Это снижает риск поломки существующих сценариев и старых клиентов.

2. Убираю каталог из промпта YandexGPT. Модель получает только исходный текст и извлекает:

   - исходную фразу;
   - предполагаемое название упражнения;
   - вес, повторы, время и дистанцию;
   - количество подходов;
   - позицию упражнения в тексте.

3. После ответа модели сервер ищет каждое упражнение по всему актуальному каталогу:

   - системные упражнения;
   - новые Gym Pro;
   - пользовательские упражнения текущего пользователя.

4. Поиск выполняется одновременно по исходной фразе и по названию, выделенному моделью. Учитываются:

   - точное название;
   - перестановка слов;
   - `ё/е` и формы слов;
   - опечатки;
   - спортивные синонимы;
   - оборудование;
   - группа мышц.

5. Использую существующие правила поиска приложения, чтобы серверный разбор и ручной каталог не выдавали разные результаты.

6. Правила выбора остаются безопасными:

   - точное однозначное совпадение подставляется автоматически;
   - несколько похожих вариантов показываются пользователю;
   - недостаточно уверенное совпадение не выбирается автоматически;
   - несуществующий `ref` попасть в тренировку не может.

7. Сеты и круговые не отдаю полностью на усмотрение модели. Существующий детерминированный разбор структуры остаётся основным, а позиции из ответа модели используются для правильного сопоставления упражнений.

8. Поддерживаю частичный результат. Если найдены два упражнения из трёх, они показываются на проверке, а только третье требует уточнения. Вся тренировка не должна падать из-за одной строки.

9. Разделяю типы ошибок:

   - модель недоступна;
   - модель вернула некорректную структуру;
   - упражнение не найдено;
   - найдено несколько вариантов.

   Сообщение «Разбор временно недоступен» останется только для настоящего сбоя сервиса.

10. Добавляю обезличенную диагностику: длительность, код ответа, количество строк, найденных упражнений и неоднозначностей. Сам текст тренировок в логи не записывается.

11. Проверяю:

   - три формулировки со скриншота;
   - точные и разговорные названия;
   - опечатки и голосовые искажения;
   - пользовательские упражнения;
   - одинаковое упражнение несколько раз;
   - веса, повторы и подходы;
   - сеты и круговые;
   - смешанный успешный и неуспешный разбор;
   - полный текущий каталог из 1165 упражнений;
   - отказ и некорректный ответ YandexGPT.

12. Выкатываю сначала обновлённый серверный парсер. Благодаря сохранению текущего формата ответа отдельное одновременное обновление интерфейса не требуется. После выкатки проверяю проблемный текст в продакшене и сверяю не только успешность запроса, но и выбранные упражнения.

Не меняю SpeechKit, VPN, базу данных, сохранение тренировок, интерфейс ввода и текущую модель. Основное изменение будет изолировано внутри серверного разбора.
