## Подтверждено

1. Существующий `/assistant`, без отдельного приложения или чата.
2. Первый выпуск доступен только точному аккаунту тестового тренера.
3. Исходные данные — доступная этому тренеру история клиента и квиз в чате.
4. Цель конкретной программы спрашивается явно, даже если в профиле есть цель.
5. Генерация через LLM в Cloud Function, упражнения только из существующего каталога.
6. Горизонт — ровно четыре недели, 1–3 занятия в неделю по ответу клиента: 4/8/12 назначений.
7. Приоритет — согласованность и пригодность программы.

## Реализованный контракт

Существующий `/assistant` → накопленная анкета → подтверждение → свежий
actor-scoped снимок клиента → приватная `fit-generate-program` → проверка →
черновик → явное атомарное добавление в расписание.

Квиз понимает свободный текст. LLM возвращает только список изменений с точными
цитатами из последнего сообщения; код сохраняет остальные ответы. Смена клиента
сбрасывает анкету. Цель программы обязательна независимо от цели в профиле.
Доступны 1–3 занятия в неделю, ровно 4 недели и 4/8/12 назначений.

Первый выпуск — базовые занятия на всё тело для взрослых без заявленных текущих
болей, травм и ограничений. Нужны 30–120 минут и день отдыха между занятиями,
включая переход воскресенье–понедельник. Это ограничения пилота, а не медицинская
оценка. При неподдерживаемых условиях ассистент просит уточнить анкету.

## Контекст и модель

Supabase loader читает данные с JWT тренера и RLS: профиль, цель, последний вес,
завершённые тренировки за 56 дней, подтверждённые фактические подходы и обратную
связь. Чистый агрегатор считает регулярность и прошлые исполнения упражнений,
сохраняет даты и отсутствие данных. План не подменяет факт. Закрытые заметки,
контакты, имена и личная переписка в генератор не передаются.

Реальные вызовы показали, что свободные числовые назначения модели нарушают
ограничения длительности и прогрессии. Поэтому итоговая схема гибридная:

- Модель выбирает только существующие exerciseRef из допустимых вариантов для
  пяти обязательных движений: приседание, движение в тазобедренном суставе,
  горизонтальные жим и тяга, корпус; дополнительное упражнение необязательно.
- Небольшой набор из 25 существующих упражнений размечен по движению,
  оборудованию и поддержке корпуса. Ref, название и тип проверяются тестами
  против канонического каталога; custom и неразмеченные упражнения исключены.
- Код рассчитывает подходы, повторы/удержания, RPE, отдых и четыре недели;
  модель не назначает килограммы. Объём подгоняется под время, упражнения
  повторяются по неделям. Прогрессия условна: только при сохранении техники
  и целевого усилия. Четвёртая неделя закрепляет третью.
- Валидатор проверяет структуру, допустимость упражнений, время, объём,
  интенсивность, переходы недель и календарь. Эти проверки подтверждают
  согласованность правил, но не доказывают индивидуальную пригодность программы.

Приватная Cloud Function не имеет доступа к БД или Lockbox. Её runtime SA имеет
только право вызова LLM; вызвать функцию может SA существующего оркестратора.
Usage возвращается оркестратору, который отправляет метрики существующим доступом.
Одна подтверждённая попытка — один вызов генерации, без скрытых циклов исправления;
лимит 5 попыток в сутки. Повтор turn не запускает ещё одну платную генерацию.

## Просмотр, изменение и сохранение

Карточка использует общие Fit-компоненты и показывает даты, упражнения,
подходы, повторы, RPE, отдых и правило прогрессии. Основное действие —
«Добавить в расписание». Изменение условий возвращает к анкете и требует
подтвердить новый полный черновик; точечное редактирование программы отложено.

Сервер принимает только canonical payload сохранённого предложения. 4/8/12
тренировок создаются одной транзакцией; стабильные request IDs защищают от дублей.
Изменения клиента/тренировок после снимка и снимок старше 24 часов отклоняются.
Проверка изменений отдельных целей и замеров этим timestamp guard не покрывается.
Старые действия сохраняют прежний лимит 4 и совместимость истории.
