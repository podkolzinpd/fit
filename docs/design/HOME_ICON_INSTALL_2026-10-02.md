# Исправление иконки «На экран Домой»

## Запрос и границы

Вместо утверждённого фиолетового знака на лаймовом фоне iPhone показал серую
иконку F. Исправить только установку сайта на главный экран. Не менять favicon,
FitLogo, native icons, push, экраны, бизнес-логику или общий hosting contract.
Референс — исходный `assets/home-screen-logo.png` и присланная пользователем
миниатюра. Новых UI-компонентов, токенов или действий нет; primary остаётся
системным «Добавить» в Safari.

## Подтверждённая фактура до исправления

- HTML и manifest уже ссылались на новый b4 рисунок; прямые PNG совпали с исходными.
- `/apple-touch-icon.png` оставался старым (3766 байт вместо 7669).
- `/apple-touch-icon-precomposed.png` и `/apple-touch-icon-180x180.png` возвращали
  HTTP 200 `text/html`, а не изображение (SPA fallback).
- Основной b4 PNG и manifest имели `Cache-Control: no-store`. В повторной
  проверке PNG не загрузился за 12 секунд; стандартный alias ответил за 11,9 с.
- Это доказывает несогласованность discovery/fallback и плохую повторную
  доставку, но не единственную причину F на конкретном устройстве. Проверка
  Playwright Image.decode не равна системной установке iOS.

## Исправление и приёмка

1. Тот же рисунок в PNG 180/192/512; непрозрачные лаймовые углы, контрастный знак,
   maskable safe circle. Используется существующий генератор, без нового дизайна.
2. Хеш содержимого в `/assets/home-icon-…png`: существующий hosting pipeline
   выставляет immutable cache, проверяет checksum и сохраняет старые версии.
   Новый рисунок всегда получает новый URL. HTML/manifest остаются некешируемыми.
3. Preload Apple PNG и одинаковый рисунок на трёх стандартных Apple адресах.
   Старые b4 URLs сохраняются для уже открытых страниц.
4. Регрессии: ссылки/размеры/пиксели/safe circle/hash/cache, GET/HEAD доставки;
   локальный WebKit и системный Safari; полный check, CI, production smoke.

Сохранённые ранее системные ярлыки не переписываются приложением. Не обещать
их автоматическое обновление или устранение любых сетевых таймаутов.

## Проверки ветки

- Три целевых теста прошли: ссылки/hash/pixel/safe-circle, стандартные aliases,
  подготовленные production GET/HEAD routes и правильные cache headers.
- WebKit 390, Chromium 430/1440: PNG декодируется как 180×180, overflow отсутствует,
  прежний in-app логотип сохранён. Проверялся локальный маршрут `/auth` без
  production-данных; локальная форма входа отличается флагами окружения.
- Полный `npm run check` прошёл frontend lint/types/coverage, DB types,
  permissions/media/infra/hosting и API lint/types. Один неизменённый API-тест
  сжатия tenant bundle превысил 5 секунд при параллельной нагрузке. Повтор всего
  API-набора с двумя workers прошёл: 1040 passed, 61 штатный skipped.
  API build и frontend production build прошли отдельно.
- Safari iOS 26.5 / iPhone 17 Simulator: production baseline и локальная
  исправленная версия прошли полный путь «Поделиться → На экран Домой →
  Добавить». На SpringBoard виден правильный рисунок; пиксели сохранённого
  WebClip `icon.png` локальной версии полностью совпали с PNG 180×180 из ветки
  (iOS меняет упаковку файла, поэтому сравнивались декодированные пиксели).
  F в этой сети не воспроизведён; проверка production после выпуска остаётся
  отдельным гейтом, устранение всех сетевых таймаутов не заявляется.
- Пользователь разрешил выпустить PR #1353 вне очереди отдельного Android
  PR #1350. Уже слитый другим исполнителем #1352 включён обновлением от main;
  после обновления ветка повторно проходит CI, проверки не обходятся.
