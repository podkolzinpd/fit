# Полный список упражнений выбранного дня у тренера

Канонический план и журнал задачи YAFIT-673. Запрос и макет согласованы
29.10.2026. База main7930e52f; отдельная ветка
`fix/coach-athlete-history-calendar-20261029`.

## Согласованный результат

- H1. В истории спортсмена у тренера после выбора даты показывать все
  упражнения каждой тренировки этого дня, в сохранённом порядке. Не обрезать
  список и не выводить «Ещё N упражнений».
- H2. Если результат не записан, показывать только название. Подтверждённые
  записанные результаты — под названием, с существующим форматированием
  веса/повторов/времени/дистанции. План не становится фактом. Пустые значения
  не подменяются «Не выполнено», «Без результата» или нулями.
- H3. В карточке выбранного дня одна дата над группой, внутри — число
  упражнений и прежний статус тренировки. Названия читаются на полной ширине;
  результаты располагаются ниже. Полный список прокручивается обычной страницей.
- H4. Служебные исходные записи и комментарии к отдельным упражнениям не
  загромождают этот краткий просмотр; они остаются сохранены и доступны в
  деталях по существующей ссылке карточки. Существующие отзывы и реальные
  метаданные тренировки сохраняются.
- H5. Переиспользовать ClientWorkoutHistoryCalendar, WorkoutChronicleCard,
  WorkoutStatus, factLine и Lime-токены/YS Geo. Включить узкий вариант только
  в тренерском календаре. Клиентский календарь, обычные списки, планы,
  навигация/возврат, выбор даты и темы сохраняют своё поведение.
- H6. Проверить отсутствие результатов, смешанные/полные факты, пустую
  тренировку, длинные названия, несколько тренировок за день и возврат из
  деталей. Существующие темы: тренерский Lime тёмный, вне Lime — светлая
  и тёмная; новую светлую тему Lime не создаём. WebKit390/430 и совместимость тренера1440; контроль
  неизменности обычного списка и клиентского календаря.
- H7. Целевые тесты и полный npm run check, обязательный зелёный CI, штатное
  слияние/публикация и проверка опубликованной сборки. Затронутый мобильный
  web-слой обновляется штатным процессом; физический телефон не объявляется
  проверенным по браузеру/симулятору.

Границы: только представление выбранного дня. Нет изменений БД/API,
сохранения, данных/истории, доступа, пилотов, календарной сетки, навигации,
расчётов и общих правил завершения. Условные названия/цифры из эскиза не
переносятся в пользовательские тренировки. Основное действие карточки —
существующее открытие деталей; новых кнопок нет.
