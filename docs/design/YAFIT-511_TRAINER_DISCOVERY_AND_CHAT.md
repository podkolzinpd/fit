# YAFIT-511 — поиск тренера и общение до подключения

## Пользовательский результат

Спортсмен видит ненавязчивый вход в каталог тренеров на главной, открывает
существующую публичную анкету, начинает обычную переписку до подключения и в
том же чате принимает приглашение тренера к совместной работе.

## Подтверждённые границы

- Отзывы, рейтинг, проверка документов, избранное, расписание, бронирование,
  оплата и подбор ИИ не входят в первый этап.
- Отдельного раздела «Обращения» нет: новые диалоги сразу попадают в обычные
  «Сообщения» тренера.
- Анкета тренера и настройка её публичности уже существуют и не
  пересобираются.
- Каталог, поиск, фильтры и просмотр публичной анкеты уже выпущены в YAFIT-493;
  в этой задаче они переиспользуются и проверяются на интеграционных границах.
- Переписка не передаётся ИИ автоматически.

## План выпуска

Работа выпускается четырьмя последовательными PR. Каждый PR начинается от
актуального `main`, проходит обязательный CI, сливается с учётом очереди и
проверяется в production до начала следующего.

### PR 1. Предпочтение карточки на главной

- Хранить для аккаунта спортсмена одно из состояний: показывать, напомнить
  через 30 дней, больше не показывать.
- Отсутствующая запись означает «показывать» и сохраняет совместимость со
  старыми клиентами.
- «Напомнить позже» вычисляет срок на сервере; клиент не может подставить дату.
- «Неинтересно» нельзя отменить повторным snooze-вызовом.
- Сохранить одинаковый контракт Supabase и Yandex.
- Пользовательского UI в PR 1 нет.

### PR 2. Серверная безопасность переписки до подключения

- Разрешить спортсмену создать диалог только с тренером из опубликованной и
  включённой в каталог анкеты.
- Для пары спортсмен–тренер существует один диалог.
- Скрытие анкеты запрещает новый диалог, но сохраняет существующую историю.
- До подключения тренер не получает доступ к тренировкам, прогрессу, замерам и
  другим закрытым данным спортсмена.
- Добавить серверное ограничение частоты новых диалогов и блокировку.
- Сохранить parity Supabase/Yandex и существующие подключённые/отключённые
  диалоги.

### PR 3. Общение и приглашение внутри чата

- Кнопка «Написать» в существующей публичной анкете открывает или создаёт
  единственный диалог.
- Новый диалог появляется в обычных «Сообщениях» тренера с подписью
  «Не подключён».
- Существующие текст, фото, ответы, редактирование, удаление, поиск,
  непрочитанные и повтор отправки работают без отдельной реализации.
- Тренер отправляет существующее приглашение внутри диалога; спортсмен
  принимает его там же.
- После подключения подпись исчезает, а история переписки сохраняется.
- Push открывает точный диалог для обеих ролей.

### PR 4. Карточка на главной и запуск для всех

- Показать клиенту без подключённого тренера компактную карточку
  «Нужен тренер?» после основных блоков текущего дня.
- Единственное primary-действие карточки — «Найти тренера».
- «Напомнить позже» скрывает карточку и возвращает её через 30 дней.
- «Неинтересно» скрывает карточку на главной навсегда и на всех устройствах.
- Подключение тренера автоматически скрывает карточку.
- Постоянный вход «Профиль → Тренер → Найти тренера» остаётся доступен.
- Провести полный end-to-end обеих ролей и включить функцию для всех.

## Состояния интерфейса

- Каталог и анкета сохраняют существующие loading, empty, error/retry и success.
- Создание диалога имеет pending, блокирует повторный тап и показывает ошибку с
  повтором.
- Блокировка и недоступная анкета дают понятный закрытый результат без утечки
  причины или данных.
- Карточка главной скрыта для тренера, подключённого спортсмена, dismissed и
  активного snooze; показывается клиенту без тренера при отсутствии запрета.
- Ошибка загрузки предпочтения не показывает навязчивую карточку до retry.

## Выпуск и откат

- Миграции только добавляют данные и сохраняют старые клиенты.
- До PR 4 на главной нет нового входа; backend-функции защищены авторизацией.
- Финальный UI имеет общий production kill switch; отключение не затрагивает
  существующие каталог, анкеты и чат.
- После каждого merge проверяются production, Yandex stage и свежая iOS
  Release-сборка из точного merge-коммита.
