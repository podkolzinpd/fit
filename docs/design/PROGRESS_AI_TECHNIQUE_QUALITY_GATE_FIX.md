# Progress AI — исправление ложного отказа проверки техники

Статус: утверждено владельцем продукта 15.09.2026, в работе.

Связанная задача: продолжение [#916](https://github.com/podkolzinpd/fit/issues/916).

## Пользовательский результат

Безопасный ИИ-анализ не пропадает целиком из-за нейтрального упоминания техники
или общего напоминания выполнять движение аккуратно. Неподтверждённое утверждение
«техника улучшилась/ухудшилась» по-прежнему блокируется. После отказа, который уже
израсходовал дневной лимит периода, интерфейс не предлагает немедленный повтор.

## Неизменяемый план

### 1. Зафиксировать подтверждённую причину

- Воспроизвести действующую проверку локально на трёх классах текста:
  нейтральный пробел данных, безопасное общее напоминание и неподтверждённая
  оценка изменения техники.
- Не запускать live AI и не использовать production-данные в тестах.

Статус: выполнено. Действующая проверка блокирует все три класса только из-за
наличия основы слова «техник».

### 2. Сузить блокирующее правило

- Блокировать только утверждения, которые оценивают состояние или изменение
  техники без наблюдений за выполнением движения.
- Разрешить нейтральную фразу об отсутствии данных и общее безопасное
  напоминание, не выдающее наблюдение за факт.
- Сохранить блокировку утверждений вида «техника улучшилась/ухудшилась»,
  «техника стала лучше/хуже» и «техника остаётся стабильной».
- Внести одинаковое правило в production Yandex API и совместимый Supabase
  контур.

Статус: выполнено локально.

### 3. Сделать состояние ошибки честным

- Для отказа проверки качества объяснить, что ответ не сохранён, а новый запрос
  для этого периода будет доступен на следующий день.
- Для отказа качества и серверных суточных лимитов не показывать отдельную
  кнопку немедленного повтора.
- Старый сохранённый анализ и остальные блоки Progress оставить видимыми.
- Временные сетевые ошибки по-прежнему получают явный повтор.

Статус: выполнено локально.

### 4. Проверить без расхода токенов

- Unit-тестами проверить разрешённые и запрещённые формулировки.
- API-тестом с mock provider доказать один локальный вызов mock и отсутствие
  автоматического AI-repair.
- Component/repository-тестами проверить наличие или отсутствие `Повторить` для
  разных классов ошибок.
- Запустить обязательный `npm run check`. Все сетевые ответы модели остаются
  замоканными; live AI smoke не запускать.

Статус: выполнено. 63 frontend/repository/quality-теста и 21 целевой API-тест
прошли; полный frontend/API check прошёл после синхронизации зависимостей.

### 5. Выпустить по очереди PR

- Перед публикацией проверить активные PR: более ранний активный PR выпускается
  первым; неактивный очередь не блокирует.
- Дождаться зелёного CI, слить PR и дождаться штатного production deployment.
- Production проверить по версии, health и чтению сохранённого анализа. Кнопку
  генерации не нажимать: production smoke должен потратить 0 токенов.

Статус: ожидает реализации.

## Acceptance matrix

| Сценарий | Ожидаемый результат | Проверка | Статус |
| --- | --- | --- | --- |
| «Нет данных о технике выполнения» | Анализ не отклоняется только из-за этой фразы | unit | Выполнено |
| «Сохранять аккуратную технику выполнения» | Анализ не отклоняется как ложный факт | unit/API mock | Выполнено |
| «Техника выполнения улучшилась» | Анализ блокируется | unit/API mock | Выполнено |
| Quality failure после платного ответа | Нет приглашения немедленно повторить запрос | repository/component | Выполнено |
| Временная ошибка сервиса | Есть явное действие `Повторить` | component | Выполнено |
| Локальная и CI-проверка | 0 live AI-вызовов и 0 токенов | mock contract | Локально выполнено; CI ожидает PR |
| Production rollout | Функция доступна, старый анализ читается | health/read-only smoke | Ожидает |

## Границы

- Prompt, агрегатор, лимиты, fingerprint, БД и тренировочные данные не меняются.
- Два близких по времени запроса 15.09 имели разные fingerprint; без доказанного
  совпадения клиента и периода они не считаются дубликатом и не расширяют этот PR.
- Истёкший дневной лимит конкретного периода не сбрасывается вручную.
