# YAFIT-385 — атомарная привязка самостоятельного клиента

## Контракт

- Самостоятельная карточка клиента остаётся канонической: её `id`, владелец и собственная история не меняются.
- Карточка, заранее созданная тренером, архивируется и получает `merged_into_client_id` канонической карточки. Физического удаления нет.
- Тренировки, подходы, замеры, пользовательские метрики, цели и сводки тренера переносятся одной транзакцией.
- Пользовательское упражнение тренера не меняет владельца и остаётся в его каталоге. В перенесённой тренировке оно становится самодостаточным снимком с прежними названием, группой, типом и значениями подходов.
- Авторство (`created_by`, `updated_by`, `published_by`) не переписывается.
- Приватная заметка тренера переносится в membership канонической карточки. Старая карточка и приглашение остаются аудит-следом.
- Повтор того же успешно использованного кода тем же клиентом возвращает тот же результат и не создаёт дубли.
- Если у клиента уже есть другой активный тренер, операция останавливается с `trainer_switch_required`. Смена тренера реализуется отдельной задачей с явным подтверждением.

## Безопасность

- Приглашение и обе карточки блокируются на время операции.
- Составные внешние ключи откладываются только до конца текущей транзакции.
- Неоднозначные коллизии (активная тренировка, замер на ту же дату, активная цель, метрика с тем же именем, совпадающая сводка) не объединяются автоматически.
- При любой ошибке PostgreSQL откатывает перенос целиком: код остаётся доступным, исходная карточка не архивируется, данные не перемещаются.
- До и после переноса сохраняются точные количества зависимостей в `client_merge_operations`.

## Границы задачи

Эта миграция не меняет интерфейс, сценарий отвязки и сценарий смены тренера. Они выпускаются отдельными PR после проверки этой серверной основы в production.
