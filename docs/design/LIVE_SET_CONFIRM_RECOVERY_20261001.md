# Восстановление сохранения Live-подхода — 2026-10-01

## Проблема

После неоднозначного ответа API введённые значения остаются на устройстве, но
клиент хранит только черновик чисел. Намерение пользователя подтвердить подход
не сохраняется. Поэтому «Повторить» может дослать уже записанный черновик,
снять предупреждение и при этом оставить подход неподтверждённым. Старая ошибка
координатора также может продолжить блокировать завершение тренировки после
того, как refetch уже доказал наличие значений на сервере.

## Решение

- отдельно хранить на устройстве признак незавершённого подтверждения подхода;
- при повторе выполнять исходное подтверждение, а не только сохранение чисел;
- считать восстановление успешным только когда сервер вернул подтверждённый
  подход с теми же значениями либо повторное подтверждение завершилось успешно;
- очищать сохранённое намерение, локальный черновик и прошлую ошибку только
  после доказанного результата;
- при обычном неуспешном autosave сохранять существующее поведение: числа не
  теряются и повторно отправляются на сервер.

## Проверка

1. Ошибка autosave, после которой refetch видит те же значения, больше не
   оставляет координатор и UI в ошибочном состоянии.
2. Ошибка confirm после успешного сохранения значений оставляет подтверждение
   в очереди; «Повторить» вызывает confirm и только затем очищает очередь.
3. Перезагрузка страницы сохраняет намерение подтвердить подход.
4. Удаление подхода и успешное завершение тренировки очищают оба локальных
   следа.
5. Обычный успешный autosave не создаёт намерение подтверждения.

Бизнес-правила значений, API и схема PostgreSQL не меняются.
