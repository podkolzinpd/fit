# Клиентский просмотр абонемента и оплат

Тикет: YAFIT-575

## Пользовательский результат

Клиент видит в своём кабинете компактную информацию об абонементе и оплатах,
которую ведёт тренер. Данные доступны только самому клиенту и не позволяют
получить финансовую информацию других спортсменов.

## План

1. Добавить отдельный клиентский read-only контракт финансов. Сервер определяет
   клиента по авторизованной сессии и не принимает произвольный `clientId`.
2. Возвращать клиенту только отображаемые поля: тренер, название и срок
   абонемента, стоимость, оплачено, остаток, дата оплаты, оставшиеся занятия и
   история платежей. Не возвращать внутренние комментарии и служебные поля
   тренера.
3. Добавить в Кабинет клиента компактную карточку «Оплата тренировок». Вход в
   раздел виден всегда: без финансового учёта карточка коротко сообщает, что
   абонементов пока нет; при нескольких тренерах данные разделены по тренерам.
4. Добавить простой экран просмотра «Оплата тренировок» с блоками «Абонемент» и
   «Оплаты». Клиент ничего не редактирует, не подтверждает и не удаляет.
5. Собрать экран на существующих Fit-компонентах и токенах: одна компактная
   ссылка «Подробнее», поверхности Foundation UI Identity v1, ритм
   4/8/12/16/20/24, touch targets не меньше 44 px. Проверить центрирование,
   одинаковые высоты, длинные суммы и отсутствие наложений на 320/390/430 px.
6. Защитить доступ на уровне PostgreSQL/API: идентичность клиента берётся из
   `auth.uid()`, выборка ограничивается собственной карточкой клиента и её
   связями с тренерами. Чужой идентификатор нельзя передать ни в маршруте, ни в
   query/body.
7. Проверить cross-client/IDOR-сценарии, очистку кеша между аккаунтами,
   совпадение сумм с кабинетом тренера, loading/empty/error/retry, несколько
   тренеров и несколько абонементов.
8. Обновить продуктовую документацию, пройти локальную Yandex
   PostgreSQL/API/RLS проверку, компонентные и мобильные визуальные проверки,
   полный `npm run check`, PR/CI и production verification.

## Границы

- Только просмотр информации клиентом.
- Без оплаты внутри приложения, подтверждений, споров, уведомлений и
  редактирования.
- Правила автоматического списания тренировок и финансовый кабинет тренера не
  меняются.

## Проверено локально

- Yandex PostgreSQL migration, actor/RLS и cross-client изоляция: `local:verify`.
- Полный `npm run check`: 2 185 frontend-тестов, 1 008 API-тестов и production build.
- Мобильная геометрия 320/390/430 px, WebKit и Chromium: без переполнения и
  наложений; длинные ФИО, названия и суммы остаются внутри карточек.
