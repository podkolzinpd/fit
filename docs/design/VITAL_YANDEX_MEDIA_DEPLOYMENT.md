## Зафиксированный план

1. Проверяю очередь PR
   - Если есть более ранний активный PR — не обгоняю его.
   - Работаю от актуального `main`.
2. Делаю отдельный ручной workflow для Vital → Yandex
   - Не меняю проверенную загрузку Vital в Supabase.
   - Переиспользую существующий зашифрованный пакет, manifest и подготовку файлов.
   - Добавляю отдельный Yandex-загрузчик, чтобы не смешивать Vital с чатами и пользовательскими фото.
3. Настраиваю безопасный доступ
   - GitHub получает краткоживущий доступ через OIDC.
   - Bucket и закреплённая версия ключей берутся из тех же настроек, что использует Yandex API.
   - Жёстко заданный `fit-stage-media-s3` не используется.
   - Workflow завершается ошибкой, если bucket и ключи не соответствуют друг другу.
4. Проверяю целевой bucket до загрузки
   - bucket закрытый;
   - публичные чтение и листинг запрещены;
   - версионирование подтверждается первой записью реального объекта manifest;
   - временные probe-объекты не создаются и объекты автоматически не удаляются;
   - никакие ключи и содержимое файлов не выводятся в лог.
5. Проверяю исходный пакет
   - ровно 2 010 файлов;
   - общий размер — 71 514 430 байт;
   - путь, размер и SHA-256 каждого файла совпадают с утверждённым manifest;
   - лишние или отсутствующие файлы блокируют загрузку, но автоматически ничего не удаляется.
6. Загружаю файлы в Yandex
   - ключи сохраняются в формате `fit-exercise-media/vital-pro/...`;
   - JPG получают `image/jpeg`, MP4 — `video/mp4`;
   - задаётся подходящее кэширование;
   - совпадающие файлы пропускаются;
   - отсутствующие или отличающиеся загружаются повторно;
   - используются ограниченная параллельность и повторы при временных ошибках.
7. Полностью проверяю содержимое Yandex
   - скачиваю обратно все 2 010 объектов;
   - заново вычисляю SHA-256 содержимого;
   - сверяю размеры и хеши с manifest;
   - повторный запуск должен показать ноль загрузок и 2 010 подтверждённых файлов.
8. Проверяю выдачу медиа через приложение
   - авторизованная Yandex-сессия получает signed URL;
   - JPG и MP4 реально открываются;
   - проверяются коды `200`, правильный `Content-Type`;
   - MP4 поддерживает `Range` и ответ `206`;
   - просроченная или неавторизованная ссылка не даёт доступ.
9. Провожу пользовательский smoke
   - каталог упражнений;
   - подробная техника;
   - Live-тренировка;
   - мобильные WebKit/iPhone и Chromium;
   - при Yandex-сессии анимации загружаются из Yandex, запросов к Supabase Storage нет.
10. Выкладываю безопасно
   - сначала PR с кодом workflow и тестами;
   - полный CI;
   - merge;
   - read-only аудит;
   - фактическая загрузка;
   - повторный аудит и smoke;
   - фиксирую итоговые количество, размер и fingerprint.
