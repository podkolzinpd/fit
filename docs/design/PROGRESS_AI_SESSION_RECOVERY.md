# Progress AI — восстановление истёкшей Supabase-сессии

Статус: утверждено владельцем продукта 16.09.2026, реализовано и проверено локально.

## Подтверждённая причина

Production-запрос клиента дошёл до legacy-маршрута Yandex API со старым
Supabase access token. Сервер вернул `401 authentication_required` до
агрегации, блокировки генерации и обращения к модели. Клиент повторно использовал
тот же token, поэтому последующие нажатия не могли исправить состояние.

## План

1. При точном `401 authentication_required` от summary-маршрута один раз
   обновить существующую Supabase-сессию и повторить тот же запрос с новым
   access token.
2. Не повторять автоматически parser-запросы, лимиты, cooldown, ошибки качества,
   сетевые ошибки и ответы `5xx`. Второй `401` завершает сценарий явной ошибкой
   входа.
3. Служебный `summaryDiagnostic=1` направлять через фактически выбранный backend:
   Supabase-клиент — через legacy bridge, Yandex-клиент — через native API.
   Оба варианта выполняют только `preflight`, не вызывают модель и не сохраняют
   анализ.
4. Любой оставшийся `401` показывать как истёкшую сессию, а не как общую ошибку
   обновления.
5. Проверить всё локальными mock/component/repository-тестами. Live AI smoke и
   платные запросы в тестах не запускать.

## Ожидаемый результат

- обычная активная сессия делает один запрос;
- устаревший access token восстанавливается за один refresh и один повтор;
- восстановление не может создать два платных вызова, потому что первый `401`
  завершается до model gate, а все серверные fingerprint/lock/limit правила
  остаются действующими;
- если refresh token тоже недействителен, пользователь получает точное сообщение
  о необходимости заново войти;
- служебный preflight показывает состояние реального production-маршрута при
  нулевом расходе токенов.

## Acceptance

- [x] `401 authentication_required` → один `refreshSession` → один повтор с
  новым token.
- [x] Второй `401` не повторяется.
- [x] Любой не-auth ответ не вызывает refresh/retry.
- [x] Supabase preflight идёт через `/v1/legacy/summarize-client-training` с
  `diagnostic: preflight`.
- [x] Yandex preflight остаётся на native diagnostic route.
- [x] Unit/component tests не имеют live AI/network вызовов.
- [ ] Production deploy и бесплатный preflight подтверждены отдельно.
