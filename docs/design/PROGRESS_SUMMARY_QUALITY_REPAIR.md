# Повторный отказ проверки качества

Пользователь снова получает отказ проверки качества после выпуска #871.
Этот код ошибки означает три отклонённых структурно корректных ответа,
а не отсутствие тренировок или таймаут. По старым логам невозможно определить
точное нарушенное правило: сохранялось только количество нарушений.

1. Передавать модели отклонённый ответ непосредственно перед замечаниями.
2. Записывать фиксированные причины на каждой попытке без текста анализа.
3. Проверить восстановление после отклонения и отказ после трёх нарушений.
4. Сохранить эквивалентное поведение Supabase и Yandex.
5. Выпустить по очереди активных PR; успешную генерацию на production-данных
   подтверждать отдельно от deployment и неавторизованного smoke.

Регрессионный тест воспроизводит отсутствие assistant-сообщения и проверяет
его наличие в повторном запросе. Существующий тест сохраняет отказ после трёх
некачественных ответов. Точный триггер последнего production-отказа неизвестен;
исправление повторов не является доказательством успешного пользовательского
обновления. Для повторного отказа теперь доступны названия нарушенных правил.
