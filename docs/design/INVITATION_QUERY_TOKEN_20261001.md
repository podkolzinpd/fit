# Надёжная передача защищённого приглашения

Статус: утверждено владельцем продукта 2026-10-01.
Тикет: `YAFIT-577`.

## Пользовательский результат

Новая защищённая ссылка не теряет bearer-token при отправке через системный
share, мессенджер, QR-код, Safari или установленный web app. После открытия
пользователь проходит прежние preview → вход/регистрацию → явное подтверждение
подключения. Старые fragment-ссылки продолжают работать.

## Зафиксированный план

1. Для всех новых приглашений формировать
   `https://fit-training.ru/invite?token=<токен>&source=yandex`. Одинаковый адрес
   используется системной кнопкой «Поделиться», копированием и QR-кодом.
2. Страница приглашения принимает новый `/invite?token=…&source=…` и старый
   `/invite#token=…&source=…`. Если query и fragment одновременно содержат
   разные credentials, ссылка считается некорректной.
3. При открытии проверять формат токена, сохранять его в существующий browser
   session context и только после подтверждённой записи удалять token/source из
   адресной строки. При запрещённом browser storage ссылка остаётся reloadable,
   а пользователь получает существующую инструкцию открыть её в Safari или
   Chrome.
4. Не передавать bearer-token в Метрику, SPA pageview, referrer, OAuth URL,
   пользовательские события или ошибки. Начальная страница использует
   `Referrer-Policy: no-referrer`, а аналитические URL очищаются отдельно.
5. Не менять API, БД, создание/отзыв/срок приглашения, определение роли,
   preview, явный claim и атомарность подключения. `/join?code=…` остаётся
   fallback ручного ввода.
6. Сохранить отдельные состояния active, claimed, revoked, expired, role
   mismatch, storage blocked и recoverable API error с `Повторить`. Новых
   экранов, кнопок и текстов не добавлять.
7. Проверить новые и старые ссылки для клиента и тренера, до и после входа,
   системный share, copy и QR, storage blocked, конфликт credentials, Safari,
   WebKit 390/430 px и существующий full check. После зелёного CI выпустить
   production frontend и проверить новый bundle на `fit-training.ru`.

## Поток и границы

- Поток: `identity-runtime`.
- Базовый main: `d89b34a0`.
- Таблицы/API/migrations: без изменений.
- Общий контракт: существующие `InvitationShare`, preview и claimLink.
- Yandex implementation: существующий production adapter без изменений.
- Legacy: старый hash-format и `/join?code=…` остаются читаемыми.
- Feature flag: не нужен; изменение обратно совместимо и откатывается возвратом
  генерации hash-ссылки.
- Вне scope: короткие серверные ссылки, новый UI, новые состояния, изменение
  ролей, срока жизни или правил отзыва приглашений.
