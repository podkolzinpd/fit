# YAFIT-576 — компактный пустой экран Live

Согласованный план: привести пустой экран Live-тренировки к компактному виду без изменения бизнес-логики. Задача: [YAFIT-576](https://st.yandex-team.ru/YAFIT-576). Исходное состояние — пустая тренировка после быстрого старта у клиента или тренера. Референс — существующий Live и Foundation UI Identity v1; переиспользуем `WorkoutHeader`, `Page`, `useConfirm`, семантические `--danger`, `--surface-raised`, общие SVG-иконки. Единственное главное действие — выбор первого упражнения.

Ниже — исходная нумерация согласованного плана; смысл пунктов не менять без согласования.

1. Пока упражнений/подходов нет, оставить LIVE и имя, убрать дублирующий статус и нулевые счётчик/полосу прогресса; прогресс возвращается при появлении подходов.
2. Сделать строку таймера компактнее только в пустом Live; сократить пустую карточку до короткого приглашения и одного главного действия добавления упражнения.
3. В нижней панели пустого Live оставить только красную иконку корзины для удаления тренировки. Использовать существующую подтверждаемую команду; обеспечить доступное имя, зону нажатия, pending и сообщение об ошибке с возможностью повторить. Заполненную тренировку не удалять этой кнопкой.
4. Проверить обе роли, 390/430/1440 px, светлую/тёмную тему, WebKit, safe area, отсутствие горизонтальной прокрутки, пустое и заполненное состояние; затем зелёный CI, merge и production smoke.

Вне scope: серверный контракт, сохранение подходов, таймер отдыха после добавления упражнений и экраны главной.

## Матрица приёмки

| Пункт | Видимый результат | Проверка | Статус |
| --- | --- | --- | --- |
| 1 | LIVE/имя без 0/0; после подхода виден прогресс | WebKit обеих ролей + существующие filled-Live тесты | Локально проверено |
| 2 | Компактная строка и одна основная кнопка | Скриншоты 390/430/1440, light/dark | Локально проверено |
| 3 | Внизу только корзинка; подтверждение, ошибка, повтор | WebKit обеих ролей, API/DB контракт уже покрыт | Локально проверено |
| 4 | UI и production без регрессии | `npm run check`, CI, production smoke | В работе |

Состояния: loading и ошибка загрузки остаются в существующем `AsyncView`; пустое и заполненное состояние проверяются для обеих ролей; ошибку удаления показываем рядом с основным содержимым, повтор — через корзинку. При уже добавленных упражнениях остаётся штатная кнопка завершения, а корзинки пустого состояния нет.
