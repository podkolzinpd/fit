# YAFIT-654 — шесть приоритетных исправлений клиента

## Утверждённый план (не изменять формулировки)

Предлагаю **5 PR на шесть исправлений**. Сначала выпускаем небольшие правки, фото делаем двумя этапами: серверная поддержка → подключение интерфейса.

1. **PR №1 — высота и оформление двух контролов**
   
   - «В цель» / выбор этапа цели: **48 px** в обоих браузерах и темах.
   - «Продолжить тренировку»: **48 px**, на всю доступную ширину.
   - Сохраняем обработчики, навигацию и права доступа.
   - Правки ограничиваем клиентским Lime.

2. **PR №2 — снятие этапа цели**
   
   - Исправляем возврат прежнего этапа после выбора «Без этапа».
   - Разделяем начальное значение формы и осознанный пустой выбор.
   - Проверяем сохранение, перезагрузку, восстановление черновика и смену этапа.
   - При ошибке сохранения выбранное значение остаётся в форме.

3. **PR №3 — понятные ошибки замеров и настроек**
   
   - При неудачном удалении замера показываем ошибку и возможность повторить.
   - При потере ответа сначала проверяем результат удаления, чтобы не повторять запись вслепую.
   - При сбое загрузки карты тела показываем ошибку и «Повторить» вместо исчезновения настройки.
   - Сохраняем выбранный формат карты, тему, плотность и анимации.

4. **PR №4 — серверная поддержка фото упражнения**
   
   - Проводим фото через действующие API и хранилище до сохранённого упражнения.
   - Проверяем права владельца, ограничения файла и обработку отказов.
   - Повтор запроса не должен создавать дубли или удалять уже сохранённое фото.
   - Сохраняем совместимость с упражнениями без фото. Если нужна миграция — проверяем её отдельно на локальной БД.
   - Пользовательский интерфейс подключаем следующим PR.

5. **PR №5 — сохранение фото из клиентского интерфейса**
   
   - Подключаем подготовленную серверную поддержку.
   - Успех показываем после подтверждённого сохранения.
   - При ошибке сохраняем введённые поля и выбранное изображение для повторной попытки.
   - Проверяем фото после закрытия окна и перезагрузки приложения — одного предпросмотра недостаточно.

Перед **каждым PR** повторно сверяем актуальный код и уже работающие решения. Для интерфейса проверяем обе темы, 390/430, WebKit/Chromium; для фото — дополнительно реальные локальные API и хранилище.

Выпуск — **по очереди, после проверок, только на прежние четыре тестовые учётки**. Ввод чисел, клавиатуру, подтверждение подходов, перенос карточек и таймер отдыха сохраняем.

## Scope и сверка перед PR1

- База: main f45aedae; роль client, клиентский Lime + независимый client-workout-reference, прежние четыре тестовых профиля.

- Переиспользуем: существующие .button/.field, токены Lime и узкий client-workout-reference scope.
- Действительно меняем в PR1: только геометрию двух контролов C05/C06; обработчики и стадия C01 остаются следующему PR.
