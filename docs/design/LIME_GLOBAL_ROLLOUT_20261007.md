## Утверждённый план

**План — 3 последовательных PR.** Клиентскую приёмку считаю пройденной тобой. Тренерское включение — после завершения текущего теста.

**PR 1 — общий механизм переключения**

- Добавить серверные режимы «пилот / все / выключено» отдельно для клиентов и тренеров.
- Обеспечить включение для существующих и новых аккаунтов.
- Сохранить текущий пилот до массового запуска.
- Предусмотреть отдельный быстрый откат каждой роли.
- Проверить получение флагов при входе, обновлении страницы и смене аккаунта.
- Учесть зависимость тренерского оформления от нового расписания: одного флага Lime сейчас недостаточно.

**Приёмка:** переключение работает для обеих ролей, отключение сохраняется после повторного входа, права и данные пользователей не меняются.

**PR 2 — включение всем клиентам**

- Перевести клиентский режим из пилота во «все».
- Проверить действующий аккаунт вне пилота и новый аккаунт, клиентов с тренером и без.
- Проверить обе темы и вложенные окна после переключения.
- Опубликовать и проверить работу на опубликованной версии.

**Приёмка:** новый дизайн доступен всем клиентам; тренерское включение остаётся прежним.

**PR 3 — включение всем тренерам**

- После завершения теста перевести тренерский режим во «все».
- Расширить необходимые флаги нового расписания, от которых зависит оформление.
- Проверить тренера вне пилота: расписание, клиентов, создание тренировок, Live, профиль и вложенные окна.
- Опубликовать и проверить работу на опубликованной версии.

**Приёмка:** новый дизайн доступен всем тренерам, клиентская часть продолжает работать.

**Порядок: PR 1 → публикация → PR 2 → проверка → PR 3 → проверка.** Перед массовым включением также перепроверю ранее обнаруженные задержки загрузки. Для устанавливаемых приложений проверю, требуется ли отдельный выпуск обновления.

Это план переключения уже опубликованного дизайна. Дополнительные PR на исправления появятся только при подтверждённых ошибках.

## Последующие прямые решения пользователя

- «он тестит, все работает»: клиент принят владельцем, текущий тренерский тест успешен; дополнительная ручная приёмка не требуется.
- «ок, делай, но не запускай включение без моего ока»: реализация разрешена, активация all и расширение пилота запрещены до отдельной явной команды.
- Включение не процентное: сначала все клиенты, затем все тренеры. Подготовленные PR2/PR3 доставляют ручные операции; сам merge или публикация этих PR НЕ переводит режим в all. Их активационные пункты остаются ОЖИДАЕТ ОК.

## Контракт и границы реализации

PR1: numbered Yandex migration с pilot/pilot/pilot, независимые client/trainer/schedule режимы,
role checks через auth.uid(), missing controls = false. Приватный IAM owner API, точное подтверждение
каждой записи, compare-and-set revision. Runtime fit_api не читает/не меняет настройки напрямую.
PR2: main-only workflow_dispatch для клиента (inspect по умолчанию); все действия без автоматических триггеров.
PR3: такой же отдельный trainer workflow, атомарный trainer all + schedule all; schedule rollback отдельный.
Старые allowlists/назначения и binders сохранены; новые аккаунты получают all по серверной роли, без добавления email/UUID в список.
Перезапуск миграций/повторный вход не переписывает modes. Откат через private workflow, не SQL Dashboard и не Down migration.
Режим off отменяет дизайн для всех соответствующей роли. Режим pilot возвращает только прежние назначения.
Отключение trainer Lime сохраняет schedule_mode: отдельно можно вернуть schedule pilot/off после отключения trainer all.
Включение trainer all расширяет существующие gates имени (migration118) и даты (migration133) только при последующих действиях с тренировкой; алгоритмы не переписываются, массовых изменений старых тренировок нет.
Открытые страницы получают новый actor при штатном refresh/reload/login; мгновенный push flags не обещан.
