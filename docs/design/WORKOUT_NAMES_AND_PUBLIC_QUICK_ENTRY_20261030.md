# Названия тренировок и общий выпуск quick-entry

Дата:30.10.2026. Задача [YAFIT-692](https://st.yandex-team.ru/YAFIT-692). Владелец утвердил четыре PR и самостоятельное выполнение,
слияние и выпуск всего плана. Канонический журнал — этот файл; тикет/PR
содержат статус и ссылки, не второй журнал.

## Граница и принятое поведение

- Предыдущий пакет YAFIT-675 из пяти PR теперь выпускается всем тренерам и
  спортсменам по их ролям. Прежнее ограничение исходной парой заменено явным
  решением владельца30.10.2026. История и доказательства пилота сохранены в
  [прежнем плане](QUICK_WORKOUT_AND_BOOKING_PLAN_20261029.md).
- Новые названия и их представление — тоже всем. Серверные права, доступ к
  клиентам/чужим тренировкам и read-only не расширяются.
- Изменение названия требует native read_write сессию; read_only и двойные
  credentials не дают новой возможности записи.
- Название тренировки одно для тренера и спортсмена; пользователь видит его
  только у доступных ему тренировок. Переименование обновляет оба представления.
- Оригинальный54/компактный48, таймеры/пауза, суперсеты, жесты, заметки,
  сохранение результатов, даты и соседние клиентские доработки сохраняются.
- Не расширяем независимые пилоты питания, клиентского reference-дизайна
  и других задач ради выпуска quick-entry. Новые функции работают в действующем
  представлении пользователя; существующие темы не заменяются незаметно.
- Никакого массового переименования старых записей. При отсутствии названия
  показывается «Тренировка», оно не записывается в БД автоматически.

## Проверка и выпуск

Каждый PR: фактический diff/scope → применимые проверки → обязательный CI →
обычное слияние с сохранением свежего main. Тяжёлые UI cases не размножаются по
всем осям; существующие сценарии переиспользуются, уникальные проверки не удаляются.
Исходные ошибки, если будут, записываются честно; retries/таймауты не ослабляются.
Общий выпуск через штатные Cloud.ru API/frontend и Android OTA после успешного
current-main CI. Для PR1 явно включить all в production-сборках и проверить
обычного пользователя вне прежней пары, не только конфигурационную переменную.
Для нового title API — PostgreSQL17 clean chain/actor/RLS и точный release.
Финал: published assets/version/health, роли и картинки, фактическое название у
спортсмена с fixture API; физический телефон не считается проверенным по браузеру.

## Итерация1 — 30.10.2026 — Codex / OpenAI

Задача: зафиксировать утверждённые4PR и начать самостоятельный выпуск всем.
Расхождения: старый quick-entry допуск требует ровно2ID и дополнительно Lime;
одного расширения списка недостаточно. Последнее решение владельца явно заменяет
эту границу, не серверную авторизацию. В свежем main уже есть клиентский showTitle.
Сделано: проверены чистый checkout, свежий main fc824f2c, инструкции и актуальные
компоненты. Создана отдельная ветка PR1 от main; чужие рабочие ветки не заняты.
Решения: явный all с сохранением off/pilot; существующее title и узкое изменение
метаданных; общие карточки дорабатываются поверх соседних клиентских PR.
Отвергнуто: расширять allowlist до произвольного списка, пересохранять весь
результат ради названия, массово заполнять старые имена, расширять другие пилоты.
Проверка: статический аудит; реализация/новые проверки/публикация ещё впереди.
Открыто: все4PR и опубликованная приёмка. Действующий production пока прежний.
Дальше: общий режим quick-entry, совместимость тем/ролей и штатный выпуск PR1.
