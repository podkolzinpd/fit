# YAFIT-920 — видимость ввода Live над iOS-клавиатурой

Статус: реализовано в ветке `fix/live-input-keyboard-visibility`.

Исходное требование пользователя: когда корректируется вес или количество
повторений, активное поле должно оставаться удобным для ввода и не скрываться
под открывшейся клавиатурой.

## Acceptance-чеклист

1. При фокусе на любом числовом поле Live активная строка подхода остаётся
   целиком видна над клавиатурой, включая кнопку подтверждения.
2. Появление клавиатуры после события фокуса повторно выравнивает активную
   строку по фактической видимой высоте iOS WebView.
3. Переключение между весом и повторениями одной строки не вызывает лишней
   прокрутки, если строка уже видна.
4. Прокручивается только внутреннее содержимое Fit; корневое окно не сдвигается.
5. Закрытие клавиатуры сохраняет действующий контракт восстановления полной
   высоты экрана.
6. Сохранение, подтверждение и значения подхода не меняются.

## Матрица проверки

| Пункт | Видимый результат | Проверка | Статус |
| --- | --- | --- | --- |
| 1 | Поле и галочка находятся внутри уменьшенной видимой области с отступом 16 px | WebKit 390 px, принудительно перекрытая вторая строка | Выполнено |
| 2 | После применения keyboard viewport выполняется повторное позиционирование | `visualViewport`-состояние + отложенная проверка активного поля | Выполнено |
| 3 | Уже видимая строка не прокручивается повторно | Проверка границ до вызова внутренней прокрутки | Выполнено |
| 4 | Меняется `scrollTop` только `.content` | WebKit фиксирует вызов внутренней прокрутки и геометрию строки | Выполнено |
| 5 | Существующие тесты мобильной оболочки и закрытия клавиатуры | Полный набор проверок проекта | Выполнено |
| 6 | Полный Live-сценарий продолжает ввод, автосохранение и подтверждение | Существующий WebKit Live-сценарий после новой проверки | Выполнено |
