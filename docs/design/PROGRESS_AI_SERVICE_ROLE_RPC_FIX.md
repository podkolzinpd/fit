# Progress AI: service-role RPC production fix

## Пользовательский результат

Явное создание или обновление ИИ-анализа на Progress больше не падает с
`training_summary_forbidden`. Существующие ограничения расходов сохраняются:
неизменный агрегат возвращается из кеша, параллельный запрос не запускает вторую
генерацию, тесты и deployment не вызывают модель.

## Зафиксированный план

1. Воспроизвести production-ошибку и закрепить доказательство: новые версии
   функции возвращают `PT403` до модели.
2. Добавить forward-only миграцию, которая переопределяет только четыре
   служебных RPC и полагается на уже закрытые права `EXECUTE service_role`.
3. Исправить SQL-тесты: убрать искусственную подстановку JWT-role, отдельно
   доказать доступ `service_role` и запрет `anon/authenticated`.
4. Проверить локальный Supabase через Podman и весь проект; любые AI-вызовы,
   live smoke и удалённую генерацию в тестах не запускать.
5. Обновить документацию фактической причины и защиты от повторения.
6. Открыть один PR, проверить очередь, дождаться зелёного CI, смержить.
7. Дождаться применения migration, затем повторно выкатить summary-функцию и
   проверить production-логи.
8. Production-проверка без токенов: сначала убедиться, что исчез `PT403`;
   реальный платный анализ запускать только через уже сделанное пользователем
   действие, без автоматических повторов.

## Границы

- UI, prompt, агрегатор и формат отчёта не меняются.
- Секреты Lockbox не ротируются: функция уже получает backend credential и
  доходит до RPC, а отказ создаётся внутри SQL-проверки.
- Yandex stage database migration не меняется: её API вызывает аналогичные RPC
  через `fit_api` с actor context; найденный дефект относится к Supabase
  service-role bridge production-функции.
- Никаких production SQL через Dashboard и никаких live AI smoke.
