   Визуально: обе клиентские темы,390/430, WebKit/Chromium, полный scroll,

4. Открыть PR, дождаться зелёных обязательных проверок. Соблюсти очередь более
   ранних активных PR; перед merge обновиться от main и повторить необходимые
   проверки. Следующий PR готовить без смешения scope; выпускать последовательно.
5. После разрешённого merge проверить опубликованную сборку и каждый ID из PR,
   обновить доказательства/статусы. Мобильные действия — по текущему workflow;
   физический iPhone не объявлять проверенным без реальной проверки.
