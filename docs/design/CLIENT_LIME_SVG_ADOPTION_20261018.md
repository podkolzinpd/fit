## Последовательность: 4 PR реализации

Документационная фиксация выполняется отдельно и не включена в эти четыре.
Каждый PR должен давать завершённое изменение видимого сценария. Не делать
отдельный релиз пустой библиотеки, которую пока никто не использует.

### PR 1 — каталог и фильтры (L1, L2, C2)

- Переиспользовать header/picker-паттерн SVG; выделить общий вариант шапки,
  если текущего недостаточно. Не подключать клиенту всю тренерскую CSS-область.
- Каталог: оригинальная иконка фильтра, облегчённые разделители; поиск,
  preview и создание остаются на прежних местах сценария.
- Фильтры: один заголовок; под ним обычное поле «Название упражнения» с
  различимой границей/фоном поля. Оно не выглядит декоративной подписью.
- Сохранить общие `search` и параметры фильтрации при каталог ↔ фильтры.
  Фокус/ввод в этом варианте не вызывает `setFiltersOpen(false)`.
- В клиентском варианте фильтры позволяют последовательно менять параметры,
  а существующее «Показать упражнения» возвращает к результатам. Не менять
  алгоритмы поиска, ранжирование и состав каталога.
- Сохранить выбранные упражнения, счётчик, подтверждение добавления,
  preview без окраски в selected, pending и повтор без дублей (#1694/#1695).

Приёмка: ввести название до/после выбора параметров; вернуться назад и снова
открыть фильтры; clear query не сбрасывает параметры; пустая выдача, loading,
ошибка, длинный запрос, клавиатура, 0/1/несколько выбранных, pending/partial retry.
Сохранить различие воспроизведения и выбора. Проверить источник открытия из
плана и Live; тренерский reference-вариант не меняется заодно.

### PR 2 — календарь истории и геометрия дня (L3, C1)

- Применить геометрию Calendar Day и общие размеры визуального маркера.
  Отдельный44×44 hit target не должен растягивать36×36 круг.
- Проверить/убрать конфликтующие `min-height`, width/max-width, padding,
  line-height, inset `box-shadow` и border именно в клиентском варианте.
- Selected — лаймовая заливка, today — один контур; при совпадении selected
  важнее. Отметка/счётчик тренировок не меняет форму и центрирование цифры.
- Сохранить переход месяца, выбранную дату, недоступные/пустые даты,
  различение нескольких тренировок и список выбранного дня.
- Описать повторно используемый стиль дня для следующего PR; тренерские
  карточки недели и маршруты не переносить.

Приёмка: computed width=height для видимого маркера во всех состояниях,
tap area≥44×44, today≠selected / today=selected, 1/несколько тренировок,
короткий/длинный месяц, возврат из деталки. Без сдвига сетки и навигации.

### PR 3 — проверка плана (L4)

- Применить согласованную плотность и иерархию карточек.
- Переместить существующее «Изменить порядок» к метаданным; сохранить
  текущую рабочую перестановку и доступное управление.
- Меню `⋯` без отдельной круглой подложки, с прежней достаточной областью
  нажатия. Не добавлять круги вокруг номеров подходов.
- Сохранить «Править подходы», добавление, подготовку и «Далее»; подготовка
  остаётся выбором времени, не превращается в выбор режима тренировки.

Приёмка: 0/1/несколько упражнений, длинные названия, раскрытые подходы,
клавиатура, порядок/ошибка сохранения, круги/суперсеты, черновик/перезагрузка,
полная прокрутка до нижних действий. Live-числа и таймеры не затронуты.

### PR 4 — дата/время в сохранении и редакторе (L5, L6, L7)

- Применить строки параметров с оригинальными иконками и читаемыми значениями.
  Снять лишнюю вложенную плашку информационного текста сохранения.
- Расширить `FitLimeDatePicker` явным клиентским вариантом, используя header
  PR1 и геометрию дня PR2. Не дублировать вычисления календаря/local-date.
- Оставить только поля конкретного сценария: у сохранения — существующие
  дата/время; у редактора — дата/начало/необязательное окончание. Не добавлять
  окончание, повтор или выбор клиента туда, где их сейчас нет.
- Внутри окна менять черновик выбора, применять только существующим действием
  подтверждения; закрытие/отмена сохраняет прежние значения формы.
- Сохранить оба режима записи, optional time, «без времени», очистку окончания,
  заметку, подготовку, валидацию, права, конфликт/ошибку и повтор сохранения.
- Не привносить цвета отдыха/предупреждения в обычную дату автоматически.

Приёмка: оба режима записи, дата без времени / дата со временем,
начало/окончание/очистка окончания, отмена и подтверждение окна, переход месяцев,
год/часовой пояс, повторное открытие, draft/reload, offline/error/retry/conflict.
План тренера остаётся недоступным для редактирования клиенту по текущим правам.

## Проверка и выпуск каждого PR после команды на реализацию

1. Заново проверить main, текущую сборку и открытые/слитые PR. Если часть уже
   сделана параллельно, переиспользовать результат и отметить покрытие её ID.
2. Записать baseline/role/flags, точный scope, состояния и затронутых общих
   потребителей. Эскиз сам по себе не подтверждает работоспособность.
3. Реализовать только пункты PR и провести обязательные проверки проекта.
   Визуально: обе клиентские темы,390/430, WebKit/Chromium, полный scroll,
   клавиатура, доступность; регрессия тренера для общих компонентов.
4. Открыть PR, дождаться зелёных обязательных проверок. Соблюсти очередь более
   ранних активных PR; перед merge обновиться от main и повторить необходимые
   проверки. Следующий PR готовить без смешения scope; выпускать последовательно.
5. После разрешённого merge проверить опубликованную сборку и каждый ID из PR,
   обновить доказательства/статусы. Мобильные действия — по текущему workflow;
   физический iPhone не объявлять проверенным без реальной проверки.

Этот документ не является командой начать PR или rollout. Текущий запрос —
зафиксировать дизайн-код и план.

## Что сохраняем

YS Geo, действующие токены/темы и иконки; 5 клиентских вкладок; главную;
текущий компактный Live, перенос карточек, ввод чисел/клавиатуру, редактирование
подтверждённых подходов без сброса галочки, таймер отдыха; OFF полностью без
анимации/заглушки; исправления preview и pending-мультивыбора. Не меняются
данные, API/БД, права, расчёты, настройки LLM/SpeechKit и охват тренерского пилота.

Полный SVG-каталог содержит дополнительные тренерские паттерны для будущих
задач. Они задокументированы, но не включены в эти четыре клиентских PR.
