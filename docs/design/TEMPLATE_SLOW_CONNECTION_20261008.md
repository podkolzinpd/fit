# Сохранение шаблона при медленном соединении — 2026-10-08

Владелец подтвердил минимальный план и разрешил реализацию и штатный выпуск.

## Согласованный план

1. Убрать слишком короткое ограничение проверки соединения перед сохранением, сохранив ограниченное ожидание.
2. Сохранить защиту от дублей и сохранность черновика при ошибке или повторе.
3. Показывать имеющуюся техническую диагностику ошибки, без переделки редактора.
4. Проверить медленный ответ, повторное сохранение без дублей и сохранность черновика; выпустить через штатные проверки.

## Границы и проверенные причины

- Поток: product. База: main364d1020. API/БД/migrations/auth/rollout не меняются.
- Репозиторий шаблонов и Yandex POST/PUT, ownership/version/replay migration134 сохраняются; Supabase fallback не вводится.
- Локально воспроизведено: здоровый `/health` с задержкой1200ms отменяется секундным deadline; пять проверок не пропускают ни одного POST. Быстрый `/health` пропускает ровно один POST. Публичный read-only probe: HTTP200 за2.1916s. Причина конкретного пользовательского запроса по одному скриншоту не доказана.
- Первичная проверка mutation получает до5s; суммарный бюджет прогрева10s включает все паузы/попытки. GET recovery сохраняет прежний1s. Общая concurrent mutation-проверка и45s freshness сохраняются; POST/PUT автоматически не повторяются. Отмена/недоступность остаются ошибкой, не успешным сохранением.
- Диагностика отличает неуспешную предварительную проверку от потерянного ответа записи; экран переиспользует InlineRequestError. Primary — прежнее «Сохранить шаблон»; pending блокирует повторный submit. Палитра, шрифты, структура и поля не меняются.
- Состояния: пустой редактор/disabled, pending, медленное соединение/success, недоступность/error/retry, потерянный ответ/reload, сохранённый черновик, копирование/edit conflict.
- Приёмка: unit transport/repository/UI, WebKit/Chromium Mono+Lime390/430/1440 и существующие Live request cases; полныйcheck и зелёныйCI. Только после merge официальный frontend release/readback и свежий native bundle. Реальный аккаунт тренера и физический iPhone без доступа не выдаются за проверенные.
- Более ранние активные PR1499/1502/1503: вопрос владельцу о порядке задан; ответ — отдельный release gate.
- Тикет: [GitHub#1513](https://github.com/podkolzinpd/fit/issues/1513). Внешний YAFIT не используется без настроенного доступа.
