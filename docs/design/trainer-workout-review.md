# Дизайн: отзыв тренера к тренировке

Статус: **БЭКЛОГ — спецификация готова, в работу не взято.** Составлено по вводным пользователя.

## Что делаем
Общий **текстовый отзыв тренера к тренировке целиком** (не к упражнению) —
итог/резюме после проведённого занятия. Видят тренер и клиент.

### Вводные (согласовано)
- **Когда:** после тренировки, на экране завершённой (`status = 'done'`).
  Пишется/правится на экране итогов, не в форме планирования.
- **Видимость:** тренер и клиент (клиент видит в своём кабинете).
- **Формат:** просто текст (MVP), с голосовым вводом (переиспользуем
  `VoiceNoteField`, как в «Заметке»).

## Почему НЕ переиспользуем существующее
- `workouts.notes` — это «Заметка» на этапе **планирования** (заполняется в
  форме до тренировки). Смешивать план-заметку и пост-отзыв нельзя: разный смысл,
  разное время, разный экран. → нужно **отдельное поле**.
- `workout_exercises.trainer_comment` — комментарий к **упражнению**, не к
  тренировке. Тоже не то.

## Модель данных
Итоговая модель на `workouts` (nullable для обратной совместимости):

```
workouts.trainer_review text null   -- пост-отзыв тренера к тренировке
workouts.trainer_reaction text null -- thumbs_up / fire / strong
workouts.trainer_review_author_id uuid null
workouts.trainer_reviewed_at timestamptz null
```

Обоснование «поля, а не таблица»: один ответ на тренировку, реакция и короткий
текст редактируются целиком. Это не чат, история сообщений не требуется.

### Обновление типов
- `WorkoutRow` + `WorkoutListRow` в `database.types.ts` → добавить
  `trainer_review`.
- `Workout` domain-тип (`src/shared/domain.ts`) → `trainerReview?: string`.
- Пересчитать `schema-sha256`.

## RPC
Отдельная точечная RPC (как `set_exercise_comment`), а не расширение
`save_workout` — потому что отзыв правится **на завершённой** тренировке
(`done`), а `save_workout` работает только со `status='planned'`.

```
set_workout_review(p_workout_id uuid, p_reaction text, p_review text,
  p_expected_version bigint)
  → bigint (новая версия)
```

Логика:
- `security definer`, `search_path = ''`.
- Для назначения пишет trainer-author; для client-authored done workout —
  основной тренер карточки. Дополнительные тренеры не перезаписывают ответ.
- Статус только `done`; сохраняются автор и время ответа.
- `trainer_review = nullif(btrim(p_review), '')` (пустой → NULL).
- Оптимистичная блокировка по `version`, конфликт → **PT409** (не 40001!),
  см. миграцию `non_retryable_conflicts`. Коды ошибок сразу в таксономии
  (PT404/PT409), не P0001/P0002 — их переписывает `http_error_taxonomy`.
- Зарегистрировать в `database.types.ts` Functions.

### Клиентский доступ (чтение)
Клиент уже видит свои тренировки (`client_self_service_workouts`,
`author_scoped_client_data`, `list_workouts`). Нужно:
- добавить `trainer_review` в SELECT-список `list_workouts` (и в клиентские
  выборки, если они отдельные), чтобы поле доезжало до клиента;
- запись отзыва — **только тренер** (клиент не редактирует).
- Проверить RLS: клиент читает `trainer_review` своей тренировки, чужие — нет.

## UI
### Тренер — экран завершённой тренировки (`WorkoutDetailPage`, `done`)
- Под блоком `done-summary` (Время/Тоннаж/Группы мышц) — секция «Отзыв тренера»:
  - если отзыва нет: `textarea` (placeholder «Как прошла тренировка…») +
    `VoiceNoteField` для голосового ввода;
  - если есть: показываем текст + кнопка «Изменить» (тот же textarea).
- Сохранение по blur/кнопке через `set_workout_review` (мутация + `refetch`,
  как у комментария к упражнению; учесть паттерн key/version, чтобы значение не
  «возвращалось» после правки — та же ловушка, что чинили в ClampedNumberInput).

### Клиент — карточка/детали тренировки
- Показать отзыв тренера отдельным блоком «Отзыв тренера» (read-only), с
  иконкой (напр. 💬 или 📝). Пусто — блок не показываем.

## Тесты
- **pgTAP**: назначение, client-authored workout, root/member/outsider/client,
  reaction validation, author/time, idempotent retry и stale conflict.
- **e2e**: провести тренировку → на завершённой написать отзыв → виден в деталях;
  (если есть клиентский flow) клиент видит отзыв, но поля ввода нет.
- **unit**: маппинг `trainer_review` → `trainerReview` в repository.

## Объём / оценка
S–M. Одна миграция (поле + RPC + правка `list_workouts`), типы, две точки UI
(тренер-ввод, клиент-чтение), тесты. Риск низкий (nullable-поле, отдельная RPC,
не трогает live/планирование).
