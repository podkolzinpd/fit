# YAFIT-513 — исправления площадки поиска тренера

# Пользовательский результат

Тренер может опубликовать даже минимальную анкету, спортсмен без препятствий просматривает каталог и длинный публичный профиль, начинает чат, а статусы подключения одинаковы на всех экранах. Площадка остаётся удобной на iPhone, Android и планшете и не меняет ИИ-сценарии.

# Утверждённый план: пять последовательных PR

## PR 1. Публикация анкеты тренера

- Убираем требование минимум 40 символов в поле «О себе».
- Разрешаем оставлять «О себе» пустым.
- Разрешаем публиковать анкету без направлений.
- Разрешаем публиковать анкету без выбранного формата занятий.
- Остальные поля также остаются необязательными: фото, город, стаж, стоимость, образование, сертификаты.
- Обязательным остаётся только имя тренера, которое берётся из аккаунта.
- В пустой анкете показываем две кнопки: основная «Опубликовать» и дополнительная «Заполнить анкету».
- Убираем сообщения «Расскажите о себе чуть подробнее — от 40 символов», «Добавьте хотя бы одно направление», «Выберите формат занятий».
- Синхронно меняем проверки в приложении, основной базе, серверной части и обоих контурах хранения данных.
- Проверяем отображение минимальной анкеты в каталоге: имя, фото при наличии и статус приёма клиентов.
- Пустые разделы публичной анкеты не показываем и не оставляем после них пустые отступы.
- Первая публикация по-прежнему автоматически включает показ в каталоге.
- Ручное скрытие анкеты из каталога после публикации сохраняем.

Проверки: публикация только с именем; публикация с пустым «О себе»; обновление ранее опубликованной анкеты; одинаковое поведение во всех серверных контурах.

## PR 2. Публичная анкета и кнопка связи

- Помещаем публичную анкету в отдельную корректно прокручиваемую область.
- Проверяем прокрутку пальцем, колесом и свайпом.
- Убираем конфликт с фиксированной оболочкой экрана.
- Кнопку «Написать тренеру» размещаем сразу после основной информации.
- Добавляем закреплённую кнопку связи внизу экрана для длинных анкет.
- Учитываем нижнее меню и безопасную область iPhone, чтобы кнопка не перекрывалась.
- Если тренер не принимает клиентов, вместо исчезнувшей кнопки показываем понятный текст: «Тренер временно не принимает новых клиентов».
- Для авторизованного спортсмена сохраняем переход назад в каталог.
- При открытии прямой ссылки добавляем понятный возврат в Fit.
- После входа в аккаунт возвращаем пользователя в ту же анкету.
- Исправляем положение заголовка «Тренер Fit».

Проверки: короткая, длинная и почти пустая анкета; iPhone и Android; ширина 390, 430 и планшет; открытие из каталога и по прямой ссылке; возврат назад; переход в чат.

## PR 3. Единая логика подключения тренера

- Выбираем одну проверку действующего подключения для профиля и чата.
- Явный статус отключения имеет приоритет; старые membership-записи учитываем
  только если они не старше текущего подключения.
- Корневой trainer_id используем лишь как совместимость для карточки реального
  тренера без relationship-истории.
- В списке «Мои тренеры» показываем только действительно подключённых тренеров.
- После отключения тренер сразу исчезает из «Моих тренеров».
- Пустой диалог со старым тренером не создаётся и не остаётся только из-за старой записи.
- Если переписка со старым тренером уже существует, она остаётся в сообщениях.
- Такой диалог получает подпись «Не подключён».
- Статус в списке сообщений и внутри диалога становится одинаковым.
- Возможность продолжать существующую переписку после отключения сохраняем.
- Доступ отключённого тренера к тренировкам, замерам и прогрессу остаётся закрытым.
- Проверяем пользователей со старыми данными, несколькими прошлыми тренерами и новым активным тренером.

Проверки: отключение старого тренера; подключение нового; сохранение истории; отсутствие пустых фантомных диалогов; одинаковый статус на всех экранах; отсутствие доступа к данным после отключения.

## PR 4. Экран каталога

- Выравниваем заголовок «Тренеры» и кнопку назад.
- Растягиваем поле поиска на всю доступную ширину.
- Растягиваем блок кнопок «Найти» и «Фильтры».
- На планшете сохраняем компактную ширину приложения, но используем всю ширину карточки.
- Все нажимаемые элементы делаем не меньше 44×44 px.
- Добавляем крестик очистки имени тренера.
- Показываем количество активных фильтров.
- В пустой выдаче добавляем кнопку «Сбросить фильтры».
- После возврата из анкеты сохраняем поисковый запрос, фильтры и позицию списка.
- На телефоне открываем фильтры компактным нижним окном, чтобы они не отодвигали список на несколько экранов.
- Убираем лишние пустые пространства.
- Проверяем длинные имена, направления и описания.
- Для минимальной анкеты формируем аккуратную карточку без пустых секций.

## PR 5. Поведение каталога и финальная полировка

- Добавляем постраничную загрузку вместо ограничения первыми 100 анкетами.
- Сохраняем порядок: принимающие клиентов; недавно обновлённые; остальные по имени.
- Показываем реальное количество найденных анкет либо убираем число, если полный размер выдачи ещё неизвестен.
- Добавляем понятные состояния загрузки, ошибки и повторной попытки.
- «Напомнить позже» переименовываем в «Напомнить через месяц».
- После нажатия показываем короткое подтверждение.
- Перед постоянным «Неинтересно» показываем подтверждение «Больше не показывать эту карточку?».
- Карточка автоматически скрывается после подключения тренера.
- Постоянный вход через профиль остаётся доступен независимо от выбора на главной.
- В чате уменьшаем агрессивное сокращение имени тренера и спортсмена.
- Проверяем push-переход в созданный через каталог диалог.
- Подтверждаем, что сообщения не попадают в контекст ИИ.

# Финальная проверка

Тренер: открыть профиль; опубликовать полностью пустую анкету; заполнить часть полей и обновить публикацию; включить или выключить приём клиентов; получить новый диалог; предложить совместные тренировки; увидеть спортсмена после принятия приглашения.

Спортсмен: увидеть карточку на главной; открыть каталог; использовать поиск и фильтры; открыть длинную и минимальную анкеты; прокрутить их и начать диалог; принять приглашение; отключить старого тренера; убедиться, что старый тренер исчез из подключённых, а история сообщений сохранилась.

# Порядок выпуска

Каждый PR начинается от актуального main, ждёт более ранние активные PR, проходит полный CI и production-проверку. Следующий PR начинается только после успешного слияния и проверки предыдущего. ИИ prompt, matching, fallback, сохранение и SpeechKit не меняются.
