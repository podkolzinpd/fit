# План: убрать старые кадры при загрузке Vital Gym Pro

Статус: локальная реализация и проверки выполнены; rollout проходит через PR/CI.

Пользовательский результат: после тапа по упражнению с Vital Gym Pro карточка
сохраняет единый визуальный стиль. Старое фото с красным фоном и прежняя
двухкадровая анимация не появляются перед первым кадром видео.

## Acceptance-чеклист

1. Если у упражнения есть Vital Gym Pro видео, полностью запретить старое фото
   и двухкадровую анимацию в production-сценарии.
2. Пока подписывается ссылка и загружается первый кадр MP4, показывать
   нейтральную серую заглушку; если уже готов Vital-постер из того же ролика —
   показывать только его.
3. Показывать видео только после готовности воспроизведения, с существующим
   коротким плавным появлением, без нативных controls.
4. При ошибке приватного Vital-медиа показывать нейтральную иконку, а не старое
   красное фото. Для упражнений без Vital Gym Pro сохранить существующие
   локальные fallback-кадры.
5. Применить поведение к маленьким превью списка, активной карточке picker и
   крупному экрану техники; кэш подписанных URL сохранить.
6. Добавить регрессионную проверку с искусственно медленной загрузкой и
   подтвердить сценарий в Chromium/WebKit для Client и Trainer.
7. Пройти полный `npm run check`, обязательные CI checks, смержить при свободной
   очереди, дождаться production deployment и выполнить production smoke.

## Границы

- Не менять каталог, названия, aliases, exercise id, историю и БД.
- Не менять сами купленные ролики и их соответствие упражнениям.
- Не запускать видео без явного тапа в списке.
- Не добавлять нативные элементы управления видео.

## Матрица проверки

| Пункт | Видимый результат | Проверка | Статус |
| --- | --- | --- | --- |
| 1–2 | Между тапом и Vital-видео нет красного/двухкадрового legacy media | component test с задержанным signer | Выполнено |
| 3–4 | Видео появляется плавно; ошибка даёт нейтральный placeholder | component test | Выполнено |
| 5 | Одинаковое поведение в списке и крупной технике | component + E2E | Выполнено |
| 6 | Client/Trainer и iPhone/WebKit не регрессируют | Chromium/WebKit | Выполнено |
| 7 | Исправление доступно в production | CI, deployment, production smoke | Выполняется |
