# Срок оплаты в списке клиентов — 2026-10-08

## Неизменяемый принятый план

GitHub issue #1520. Пользователь подтвердил «делай, выкатывай» и отдельно разрешил выпустить
правку оплаты раньше более ранних PR, не меняя их.

1. Один неоплаченный абонемент: **«К оплате 2 500 ₽ · до 08.10»**.
2. Несколько с разными сроками: общая сумма и отдельно **«Ближайший срок — 08.10»**, чтобы не приписывать всей задолженности одну дату.
3. Если срок не указан или всё оплачено — дату не показывать.
4. На узком экране дата переносится на следующую строку, размер текста сохраняем.

## Контракт реализации и границы

Поток product; baseline main `4762fea4`. Маршруты `/clients` и существующий
`/finance` используют общий label, без новых запросов по каждой карточке.
Reference: текущие client-card/client-swipe-card и finance-overview-client,
Trainer Clients foundation. Переиспользуются Page/AsyncView, Link,
ChevronRightIcon, caption/secondary и существующие токены обеих тем.
Primary списка («Добавить») и переход в клиента не меняются.

В существующий actor-scoped SQL-агрегат добавляются ближайшая календарная дата
оплаты и количество неоплаченных незакрытых услуг. Только `due_cents > 0`
и `closed_at is null`; дата начала/конца и дата платежа не заменяют срок оплаты.
Несколько неоплаченных услуг всегда получают подпись «Ближайший срок», в том
числе при одинаковых датах или недатированной части долга. Приоритеты
«Не привязано», «Просрочено» сохраняются; срок может сопровождать этот статус,
но не скрывает его. Старый API без новых полей даёт прежнюю подпись без даты.
Суммы, платежи, списания, сортировка, фильтры, права, rollout и клиентский
финансовый кабинет не меняются. Нет новых таблиц, Supabase-migrations,
feature flags, coachmark, локальных шрифтов/цветов или дополнительных действий.
