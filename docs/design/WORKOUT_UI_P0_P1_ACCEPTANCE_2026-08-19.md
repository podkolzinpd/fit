# Финальная приёмка мобильного тренировочного UI P0/P1

> Задача: `YAFIT-316 / P1.9`. Проверенная основа: `main` после PR `#450`,
> commit `0287893`. Это закрывающая приёмка согласованной фазы, а не новый
> редизайн и не расширение функциональности.

## Итог

P0/P1 принят. Создание тренировки, review, plan, Live, завершение и история
используют один компонентный и визуальный язык. Основные действия доступны на
мобильном экране, сложные состояния не ломают компоновку, а вторичные экраны
используют согласованные состояния и семантику цветов.

Главные страницы клиента и тренера не менялись. Голосовой и текстовый старт
остались главным действием. Контракты LLM и SpeechKit не менялись.

## Матрица «требование → доказательство»

| Требование | Результат | Автоматическая защита |
| --- | --- | --- |
| Общие `WorkoutHeader / Exercise / SetRow / Status / CTA` | Общие компоненты используются в creation, review, plan, Live и history; бизнес-логика экранов остаётся специализированной | component-тесты `WorkoutExerciseHeader`, `WorkoutSetTable`, `WorkoutSurface`, поведенческие `trainer-flow` и WebKit |
| Фокус создания и сохранения | Один главный сценарий, пустая тренировка не сохраняется, primary/secondary/tertiary различимы | `создание тренировки сфокусировано…`, `пустую тренировку нельзя сохранить…` |
| Mobile ergonomics Live | Touch-targets не меньше 44 px, действия доступны одной рукой, меню и CTA не перекрываются нижней панелью и клавиатурой | `в live клиент видит те же действия…`, `создание тренировки сфокусировано…`, `live-меню остаётся непрозрачным…` |
| Устойчивый ввод факта | Введённое значение переживает сетевую ошибку и reload, экран не теряет текущий подход | `введённый live-факт переживает обрыв сети и reload…` |
| Сложные состояния | Проверены пустая и частичная тренировка, пропущенный подход, отменённый отдых, длинное название, 10 подходов, ошибка и повторное сохранение | WebKit-сценарии `mobile-shell.webkit.spec.ts` |
| Состояния компонентов | `loading / disabled / selected / completed / destructive` имеют единый язык и не допускают повторной отправки | unit/component-тесты общих UI-компонентов и WebKit-сценарий частичного завершения |
| Визуальная цельность | Client Progress/Workouts/Live защищены на 390/430 px; Trainer Clients/Schedule/Progress — контрольным снимком 1440 px | `ui-visual.spec.ts`, отдельные смысловые проверки до screenshot |
| Понятный результат | Личный рекорд назван прямо, показатели округлены, положительный результат выделен без перегруза | PR `#449`, `#450`, unit и e2e Progress/History |

## Проверенная граница

- полный локальный `check`: 496 тестов приложения, lint, typecheck, API,
  проверка схемы и production build;
- реальные профили Chromium и iPhone/WebKit;
- визуальные размеры клиента 390/430 px и контрольные маршруты тренера;
- CI PR `#450`: app, database, e2e и Vercel прошли; полный e2e — 11 минут
  11 секунд;
- production merge-коммит `0287893` успешно развёрнут.

## Что сознательно не входит

- desktop shell тренера отложен пользователем;
- P2: анимации, дополнительная персонализация, новые аналитические и
  декоративные блоки;
- изменения главных страниц, LLM, SpeechKit и тренировочной модели.

После этой приёмки новые задачи P2 автоматически не начинаются. Следующий
продуктовый блок требует отдельного решения пользователя.
