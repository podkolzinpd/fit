# Плотность временной сетки расписания

Статус: реализовано, локальная приёмка завершена.

Поток: product.

Пользовательский результат: тренер выбирает обычную или компактную часовую
сетку подробного дня, быстро меняет режим из расписания и получает тот же выбор
на другом устройстве.

Базовый main commit: `0445694c`.

Затрагиваемые таблицы/API и общие файлы: additive-колонка
`public.profiles.schedule_density`, `PUT /v1/profile`, профиль Yandex app-session,
actor preference, `/profile/settings`, подробный день `/schedule` и `/today`.

Общий repository-контракт: профиль принимает необязательное значение
`comfortable | compact`; отсутствие поля не меняет сохранённую настройку.

Yandex implementation: numbered PostgreSQL migration и существующий profile
command/session contract. Supabase migration, dual-write и fallback не добавляются.

Feature flag: не требуется; `comfortable` остаётся безопасным значением по
умолчанию для существующих профилей.

## Подтверждённый план

1. В настройках тренера добавить раздел «Расписание» → «Плотность сетки»:

   - «Обычная» — текущие 56 px/час.
   - «Компактная» — 44 px/час, на экране помещается примерно на 27% больше времени.

2. Продублировать быстрый выбор в меню расписания, чтобы тренеру не приходилось каждый раз идти в профиль. Обе точки управляют одной настройкой.

3. Применять плотность только к дневной временной сетке. Недельный режим и режим двух недель не менять.

4. В компактном режиме:

   - уменьшить высоту строк и внутренние отступы карточек;
   - сохранить нормальный размер шрифта;
   - в коротких тренировках показывать только имя клиента, остальные данные — после нажатия;
   - не менять текущее время прокрутки при переключении режима.

5. Сохранять выбор для аккаунта тренера, чтобы настройка работала после обновления и на другом устройстве.

6. Проверить тренировки на 30, 45, 60 и 90 минут, соседние и пересекающиеся записи, а также Safari и приложение с рабочего стола.
