# YAFIT-595 — третий тренер в Fit Lime

## Результат и границы

Включить существующие Fit Lime и Schedule V2 для одной дополнительно согласованной учётной записи тренера. Два прежних пилотных тренера сохраняют доступ; все остальные тренеры и клиенты остаются вне пилота. Экранов, цветов, маршрутов, бизнес-данных и клиентского интерфейса эта задача не меняет.

## Приёмка

1. Установить нативное значение поля `login`, которое Яндекс ID возвращает именно для согласованной учётки. Адрес для связи нельзя автоматически считать этим логином. SHA-256 нормализованного логина хранить только в закрытом параметре выкатки и приватной БД, не в публичном репозитории.
2. Добавить ровно один ключ в закрытые списки Fit Lime и Schedule V2. Привязка происходит только после проверки Яндекс ID, существующего профиля тренера и его карточки; чужой профиль не может занять запись.
3. Увеличить предел включённых тренеров до трёх в SQL и stage-инструментах. Выключение Fit Lime для одного тренера переживает повторный вход; четвёртый тренер и клиент не получают оба флага.
4. Проверить чистую цепочку Yandex PostgreSQL, actor/RLS, тесты флагов и регрессию двух существующих пилотов. Перед merge — полный `npm run check` и зелёный CI.
5. После merge проверить штатную выкладку API и frontend на `fit-training.ru`, затем выполнить закрытое подключение и повторное чтение ровно трёх записей. Если авторизованной сессии третьего тренера нет, честно отделить серверную проверку от проверки реального входа владельца.

## Техническая граница

- Поток: `identity-runtime`.
- База: `origin/main` на старте задачи — `e17ed22c`; перед реализацией обновлена до `ba911a31`, после параллельных выпусков — до `85584a47`. Клиентские исправления #1465 сохранены.
- Зависимые PR: нет на старте; очередь проверяется перед merge.
- Затрагиваемые таблицы: `app_private.trainer_schedule_v2_allowlist`, `app_private.fit_lime_pilot_allowlist`, `app_private.user_experiment_assignments`.
- Общий контракт: `profile.experiments.trainerScheduleV2` и `profile.experiments.fitLime` без изменения DTO.
- Yandex implementation: migration127 поднимает предел до трёх и создаёт owner-only операцию подключения; сама миграция не добавляет идентификатор пользователя. Номер126 уже занят выпущенной задачей flexible assistant scheduling. Ручной main-only workflow `enroll-fit-lime-trainer.yml` передаёт секрет `FIT_LIME_ADDITIONAL_TRAINER_LOGIN_SHA256` IAM-защищённому migration runner. Публичный API и роль `fit_api` не могут расширять список.
- Закрытая операция атомарно добавляет один ключ в оба списка, отклоняет четвёртый ключ и рассинхрон списков. Повторный вызов возвращает только число записей и `added=false`, не сбрасывая привязку и аварийное отключение.
- Legacy recovery/media: не меняются.
- Default-off: пользователь без точного разрешённого ключа, клиент и неверный профиль получают оба флага `false`.
- Запрещено: включать флаг по адресу почты или предполагаемому логину, менять production вручную через SQL, затрагивать других пользователей.
