## Утверждённый план (неизменяемый текст)

1. **Исправить существующий экран одинаково у клиента и тренера.**
   Показывать загрузку, ошибку и результат проверки. Не отображать зелёные переключатели по умолчанию до получения настроек. При сбое сохранять прежние значения.

2. **Оставить три категории.**
   Переименовать первую в «Напоминания о тренировках», добавив пояснение о тренировке на сегодня и незавершённой тренировке. Остальные — «Новые тренировки» и «Новые сообщения». Показывать только поддерживаемые для пользователя категории. Изменение структуры данных для этого не требуется.

3. **Показывать одно подходящее действие.**
   Если разрешения нет — «Включить». Если подписка потеряна — «Восстановить». Если проверка завершилась ошибкой — «Повторить». При исправном подключении — «Отправить тестовое уведомление». Дополнительный общий тумблер не добавляем.

4. **Сохранять пользовательский выбор при восстановлении.**
   В коде включение сейчас принудительно включает категории. Исправить это: повторное подключение устройства не должно включать ранее отключённые сообщения или напоминания.

5. **Подключить тестовую отправку к действующему серверу.**
   Использовать существующую отправку и очередь, добавить недостающий обработчик для текущего устройства. Показывать «Тестовое уведомление отправлено» либо понятную ошибку. Использовать имеющуюся диагностику, без новой системы мониторинга и обязательного опроса пользователя.

6. **Проверить реальную доставку.**
   Проверить тестовое уведомление, сообщение и новый план на iPhone, включая закрытое приложение. Если обнаружится сбой отправки, исправить конкретное место и повторить проверку.

Серверное напоминание о незавершённой тренировке я бы вынесла в отдельную задачу: ограничение таймера страницы действительно есть, но оно не объясняет автоматически исходную ошибку подключения. В этом исправлении его нужно явно учитывать, не обещая, что фоновое напоминание уже стало надёжным.

## Реализация и локальная приёмка

Уточнение по наблюдению: функции upsert_push_subscription и UI enable/onboarding принудительно включали reminder; UI также включал chat/scheduled. Исправлены все три уровня восстановления, без изменения существующих значений строк. Для теста добавлена migration148 с actor-scoped функцией и advisory-lock ограничением частоты; структура таблиц прежняя, отправитель/dispatcher неизменны.

Для честного результата очереди текст «Тестовое уведомление отправлено» уточнён продолжением «в очередь. Дождитесь уведомления на телефоне». Факт показа не утверждается. Существующий Supabase adapter остаётся legacy; preferences в его enable также не перезаписываются.

Новых длинных browser cases нет: исходные2 role-like cases теперь проверяют trainer/client и запрос теста, error/retry, прежнее false; третья проверка безопасной диагностики сохранена. Screenshot-only матрица добавлена внутри тех же cases: client390/430 light/dark и trainer390/1440 dark (Lime trainer не имеет светлой темы).
