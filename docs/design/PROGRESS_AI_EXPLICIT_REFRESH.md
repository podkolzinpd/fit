# Progress AI — явное обновление без фонового расхода

Статус: утверждено владельцем продукта 12.09.2026, реализовано и проверено локально.

Связанная задача: [#901](https://github.com/podkolzinpd/fit/issues/901).

## Пользовательский результат

Открытие Progress, повторный вход, новый календарный день и переключение
периода не запускают генерацию ИИ. Сохранённый анализ остаётся виден, а новый
платный вызов возможен только после явного действия пользователя. Тесты не
обращаются к live AI и не расходуют токены.

## Неизменяемый план

### 1. Убрать все фоновые вызовы генерации

- Клиент и тренер при открытии экрана только читают сохранённые анализы.
- Focus, reconnect, remount, полная перезагрузка, новый день и выбор
  `1/3/6 месяцев` не вызывают `generate`.
- Первый анализ также создаётся только явным действием, чтобы расход был
  полностью предсказуем.

Статус: выполнено.

### 2. Сделать один понятный ручной сценарий

- Если анализа нет, показать действие `Создать анализ`.
- Если есть новый завершённый workout или выбран другой период, показать
  понятную причину и действие `Обновить анализ`.
- В подробном анализе оставить ручное обновление на случай исправления старой
  тренировки, цели или замера, которые нельзя надёжно определить только по
  `completed_at`.
- Pending блокирует повторное нажатие, предыдущий анализ остаётся виден.

Статус: выполнено.

### 3. Оставить сервер источником истины по неизменности данных

- Ручное обновление всегда сначала строит серверный fingerprint.
- Совпавший fingerprint возвращает кеш и расходует `0` токенов независимо от
  устаревшего клиента и прежнего параметра `force`.
- Период, модель и версии правил остаются частью fingerprint, но сами по себе
  больше не запускают запрос: без клика пользователя сервер не вызывается.

Статус: выполнено.

### 4. Исправить совместный кеш клиента и тренера

- Один готовый результат модели должен обслуживать обе роли.
- Если тренер уже создал внутренний анализ, клиентская публикация готовой
  клиентской части не должна требовать второго обращения к модели.
- Непубликованный тренерский текст не раскрывается клиенту.

Статус: выполнено.

### 5. Сделать ошибки и лимиты честными

- Автоматических retry нет.
- Параллельный запрос не создаёт второй model call.
- Ошибка качества после платного ответа не запускает AI-repair.
- Пользовательский текст не обещает повтор через 30 минут, если суточный лимит
  периода всё равно запрещает новый платный вызов.
- Старый успешный анализ сохраняется при любой ошибке обновления.

Статус: выполнено.

### 6. Сохранить действующие ограничения расхода

- Не более одного model call на новое состояние данных.
- Не более одного платного вызова на период в UTC-сутки.
- Не более трёх платных вызовов клиента в UTC-сутки.
- Модельный JSON не больше 20 000 символов, ответ не больше 1 000 токенов.
- Аварийный выключатель генерации остаётся доступен.

Статус: выполнено.

### 7. Добавить наблюдаемую причину запроса

- Ручной запрос передаёт безопасную причину: `create`, `new_workout`,
  `period_change` или `manual_refresh`.
- В логи не попадают тексты анализа, персональные данные или содержимое
  тренировок.
- Счётчики кеша и токенов сохраняются.

Статус: выполнено.

### 8. Проверить без расхода токенов

- Component tests доказывают отсутствие `generate` при открытии, remount,
  смене периода и наличии сохранённого анализа.
- Repository/API tests используют mock provider.
- DB tests проверяют кеш, блокировку, cooldown и лимиты локально.
- Live AI smoke не запускается ни локально, ни в CI, ни при production smoke.
- Production проверяется по rollout/health и чтению существующего анализа.

Статус: выполнено.

## Acceptance matrix

| Сценарий | Ожидаемый результат |
| --- | --- |
| Открыть Progress с готовым анализом | Только чтение, `0` AI-вызовов |
| Перезагрузить приложение | Только чтение, `0` AI-вызовов |
| Наступил новый день | Старый анализ подписан своим периодом, генерации нет |
| Переключить 1/3/6 месяцев | Генерации нет; создать новый анализ можно вручную |
| Нет ни одного анализа | Видна кнопка `Создать анализ`, фонового вызова нет |
| Нажать обновление без изменений | Кеш, `0` токенов |
| Нажать обновление после изменения | Один model call |
| Два одновременных запроса | Один model call |
| Тренер уже создал анализ | Клиент получает клиентскую часть без второго model call |
| Ошибка обновления | Старый анализ виден, автоматического retry нет |

## Границы

- Качество и prompt анализа не меняются.
- Тренировки, цели, замеры и существующие анализы не переписываются.
- Отдельный polling/freshness endpoint не создаётся.
- Новый визуальный язык и соседние блоки Progress не создаются.

## Проверка без расхода токенов

- Компонентные и repository-тесты: 65 проверок, все сетевые вызовы замоканы.
- API-контракты: 155 проверок, live AI физически заблокирован в test-окружении.
- Локальная БД/RLS: 90 файлов, 1 236 проверок, включая общий кеш ролей.
- Lint, TypeScript, generated DB types и migration safety проходят.
- Платный AI smoke не запускался и не входит в production-проверку.
