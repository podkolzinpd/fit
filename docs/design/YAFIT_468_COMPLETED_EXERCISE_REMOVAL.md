# YAFIT-468 — удаление упражнения из завершённой тренировки

## Исходная формулировка

После завершения тренировки тренер и спортсмен должны иметь возможность удалить
упражнение, которое не выполняли. Нужно проверить удаление из завершённой
тренировки для обеих ролей, включая уже выполненное упражнение.

## План и acceptance-чеклист

1. [x] На экране завершённой тренировки у каждой доступной для редактирования строки есть понятное действие «Удалить упражнение».
2. [x] Удаление требует подтверждения, блокирует повторное нажатие и показывает понятную ошибку с возможностью повторить действие.
3. [x] Тренер может удалить упражнение из своей тренировки клиента; спортсмен — из доступной ему собственной или назначенной тренировки. Посторонний тренер не получает доступ.
4. [x] Удаляется только выбранное вхождение вместе с его подходами; каталог упражнений и другие тренировки не меняются.
5. [x] После удаления сводка, список, история и прогресс используют обновлённый результат без перезагрузки страницы.
6. [x] Отдельно проверены тренер и спортсмен, невыполненное и выполненное упражнение, конфликт версии и повтор после ошибки.
7. [x] Существующее удаление в Live и редактирование результата не получили регрессий.
8. [ ] Пройдены локальные тесты, SQL/RLS, WebKit 390/430 и trainer desktop, обязательный CI и production-проверка после merge.

## UI-контракт

- Референс: существующая строка упражнения на `/workouts/:id` и её `OverflowMenu` в Live.
- Переиспользуются `OverflowMenu`, `useConfirm`, текущие danger-токены и neutral surface строки результата.
- Основное действие страницы не меняется; удаление остаётся редким destructive-действием внутри меню.
- Pending блокирует повтор, error остаётся рядом со списком и даёт повторить запрос, success перечитывает все зависимые данные.
- Вне scope: права редактирования всей тренировки, каталог, структура плана и новая аналитика.
