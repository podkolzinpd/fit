# Восстановление ранее привязанных Yandex ID

Поток: `identity-runtime`.

Пользовательский результат: ранее привязанный и полностью перенесённый аккаунт
входит через Yandex ID без повторной привязки и без ручного обращения в
поддержку.

## Зафиксированный план

1. Проверить production-пакет всех привязанных domain-ready профилей и
   идемпотентно восстановить им `yandex/read_write` assignment.
2. При выдаче новой FIT-сессии автоматически восстанавливать только отсутствующий
   assignment ранее привязанного domain-ready профиля. Не менять явно
   отключённые, иначе настроенные, нативные или неполностью перенесённые аккаунты.
3. Сделать production workflow строгим: после `enable` число включённых
   профилей обязано совпадать с числом привязанных domain-ready профилей.
4. Проверить атомарность, повторный вход, явное отключение, неполный перенос,
   чистую цепочку миграций, полный backend-check и production после merge.

## Матрица приёмки

| Пункт | Видимый результат | Проверка | Статус |
| --- | --- | --- | --- |
| 1 | Привязанный перенесённый аккаунт снова может войти | Production workflow `35615214497` | выполнено |
| 2 | Отсутствующий legacy-assignment восстанавливается в транзакции выдачи сессии | 46 DB integration tests | выполнено |
| 3 | Неполный batch больше не может считаться успешным | unit + workflow policy | выполнено |
| 4 | Миграции и проверки зелёные, production smoke пройден | clean DB + `npm run check`; CI/deploy/smoke | локально выполнено, выпуск в работе |
