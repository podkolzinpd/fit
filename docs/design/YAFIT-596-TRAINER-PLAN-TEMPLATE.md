# YAFIT-596 — шаблон из формы плана тренера

Результат: тренер, составляя план для клиента, выбирает шаблон из своей личной
библиотеки прямо в блоке «Упражнения». Исходный экран — `WorkoutFormPage`;
источник шаблонов и правила доступа — уже существующий `workoutTemplates`.
Основное действие формы остаётся «Сохранить план», выбор шаблона вторичен.

1. В создании и редактировании плана тренера показать «Добавить шаблон» рядом
   с заголовком упражнений. В завершённой тренировке и у клиента действия нет.
2. Открыть список личных шаблонов в существующем типе нижнего листа. Покрыть
   загрузку, пустую библиотеку, ошибку с повтором, закрытие и длинные названия.
3. При выборе добавить независимую копию плановых упражнений в конец уже
   набранного плана: сохранить порядок, подходы, значения, отдых и комментарии;
   создать новые ID блоков. Не затирать клиента, дату, время, название и уже
   введённую заметку; заметку шаблона использовать только если поле пустое.
   Повторное использование не связывает будущую тренировку с шаблоном.
4. Проверить создание и редактирование плана, обе темы, компактный и desktop
   тренерский экран, сохранение через существующий API и отсутствие действия у
   клиента/в факте. Затем целевые тесты, WebKit и `npm run check`.

Переиспользуются `WorkoutHeader`, `WorkoutCta`, `AsyncView`, `EmptyState`,
`StatePanel`, `CopyIcon`, текущие `sheet-overlay`/`workout-decision-sheet`,
semantic surfaces и `--border`. Новых таблиц, API, цветов и маршрутов нет.
Клиентское «Избранное», библиотека шаблонов, голосовой разбор и главные экраны
не меняются.

| --- | --- | --- | --- |
| 1 | Действие только у тренера в плане | Chromium E2E: создание, редактирование, факт, клиент | Готово локально |
| 2 | Список/пусто/ошибка/повтор в листе | Chromium E2E и WebKit Fit Lime: длинное имя, выбор | Готово локально |

Полная команда `npm run check` в локальной среде один раз остановилась на
нерелевантном тесте `tenant-migration/bundle.test.ts`: с лимитом 5 секунд он
занял 8,5 секунды даже изолированно. Повторный запуск всех API-тестов с
лимитом 15 секунд прошёл. Исходный тест и его лимит в этой UI-задаче не меняем;
обязательный CI должен подтвердить результат перед передачей PR.
