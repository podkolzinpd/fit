# Серверная пагинация истории тренировок

Третий шаг аудита БД устраняет загрузку всей доступной истории перед выдачей
одной страницы. Экран, нейтральный контракт и сценарии пользователя сохраняются.
Работа ограничена Yandex API и transport/repository; Supabase не расширяется.

## Критерии приёмки

1. `workouts.listPage` получает одну ограниченную страницу с серверными
   фильтрами клиента и дат, точным количеством и следующим offset.
2. `workouts.get` открывает старую тренировку по ID независимо от первых страниц.
3. Каталог упражнений и очередь внимания не загружают историю тренировок.
4. `workouts.list` сохраняет полный результат для существующих расчётов,
   собирая только страницы запрошенного клиента/периода. Ошибка не маскируется
   пустым результатом; повторная попытка выполняет новый запрос.
5. Невалидные фильтры отклоняются; actor/RLS, авторство, мягкое удаление и
   согласованный snapshot сохраняются, включая прямой ID чужой тренировки.
6. Целевые unit/API и PostgreSQL actor/RLS тесты, WebKit и полный check
   выполняются до PR. Результаты фиксируются ниже без изменения критериев.

## Границы

Не меняются схема, grants, UI, статистические формулы, auth и Supabase baseline.
Полные исторические расчёты и trainer list пока остаются потребителями `list`;
их замена агрегатами или новым UI — отдельная задача, не скрытое усечение данных.
Пагинация сохраняет существующий offset-контракт. Между отдельными запросами
вставки/удаления могут сдвинуть offset; один ответ остаётся snapshot-consistent.

| --- | --- | --- |

| 2 | Выполнен локально | Старый ID вне первой сотни проверен в PostgreSQL; WebKit открывает последнюю карточку второй страницы для обеих ролей. |
| 3 | Выполнен локально | Catalog/attention/preferences разделяют один metadata-запрос; PostgreSQL wrapper подтверждает отсутствие SELECT корней и дочерних таблиц. |
| 4 | Выполнен локально | Полный list собирает две страницы; failure отклоняет Promise, retry запрашивает снова. Существующие summary/active workout контракты проходят. |
| 5 | Выполнен локально | API: UUID/date/range/scope/limit/offset validation; actor/RLS: чужой автор и outsider не видят ID, клиент видит свой доступный aggregate, soft-delete скрыт. Четыре snapshot race regression сохранены. |
| 6 | Локальные проверки выполнены | `npm run check` успешен; API unit 1084, PostgreSQL actor/RLS 83, WebKit 4. CI остаётся отдельным PR-гейтом. |

Полный check включает lint, typecheck, coverage, policy checks и сборки frontend/API.
Исходный check остановился на обязательном `totalCount`; после явного отклонения
несовместимого ответа повторный полный check прошёл. Никакие проверки не обходились.
WebKit проверяет первую/следующую страницы и старую карточку для Trainer и Client
на 390/430 px, а также существующие calendar/attention error и retry сценарии.

Схема и migrations не меняются. Независимые actor/RLS тесты выполнялись только
на локальной Podman PostgreSQL 17. `local:verify` в этой задаче не повторялся:
его ранее подтверждённый блокер — отсутствующая историческая Supabase migration
`20260919145000_source_cutover_migration_window.sql`; baseline не сбрасывался.
Локальные licensed Lime webfonts отсутствуют (0/2); скриншоты не подтверждают
production typography. Внешний YAFIT не настроен; чужие credentials не используются.

Удалённая PR Preview недоступна; production и мобильные сборки не проверены
до merge. В существующем frontend workflow уже есть гейт успешного matching
API rollout, поэтому сначала выпускается совместимый API. Предыдущий API rollout
#1449 успешен; frontend run37341195922 остановился с `fetch failed`, причина
не доказана. Это отдельный release-блокер, не основание обходить проверку.
