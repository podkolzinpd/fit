# YAFIT-479 — надёжное сохранение Live на телефоне

## Пользовательский результат

Клиент и тренер не теряют введённый результат при слабой сети, сворачивании или
перезапуске приложения. Live сам досылает локальный черновик, ограничивает
зависший запрос и оставляет понятное действие восстановления рядом с
закреплённой нижней панелью.

Маршрут: общий `/workouts/:id/live`. Визуальный референс — текущие
`client-live-visual-client-390.png` и `430.png`. Переиспользуются
`WorkoutSetRow`, `WorkoutCta`, `SaveStatus`, существующие semantic tokens,
48 px base controls и 18/14 px neutral surfaces. Primary-действием остаётся
подтверждение текущего подхода; завершение тренировки остаётся secondary.

## Утверждённый план

1. Сохранять ввод на устройстве при каждом изменении поля.
2. Добавить отложенный autosave и немедленную отправку при blur/подтверждении.
3. Автоматически повторять pending-черновики после online, pageshow и возврата приложения.
4. Ограничить ожидание live-запроса и не оставлять интерфейс бесконечно заблокированным.
5. Перед завершением принудительно сохранить открытую строку.
6. Сделать закреплённый статус синхронизации с кнопкой повтора.
7. Увеличить мобильную кнопку подтверждения.
8. Сократить лишние refetch и добавить диагностику сохранения без значений тренировки.

## Состояния и границы

- Локально сохранено: ввод уже защищён, серверная отправка ожидает debounce или
  восстановления сети.
- Сохраняется: виден `SaveStatus`, повторный запрос не создаётся.
- Сохранено: короткое подтверждение остаётся рядом с текущим подходом.
- Ошибка: закреплённая панель объясняет, что данные остались на устройстве, и
  даёт одно действие `Повторить`.
- Offline/возврат: pending-черновики отправляются последовательно; одинаковый
  payload дедуплицируется.
- Conflict/неоднозначный ответ: aggregate перечитывается; совпавший серверный
  факт считается успешным, отличающийся результат не перезаписывается вслепую.
- Loading/empty исходного workout не меняются.
- Поведение и проверка одинаковы для клиента и тренера; БД, права, план/факт,
  LLM, SpeechKit и соседние экраны не меняются.

## Приёмка

| Пункт | Видимый результат | Проверка | Статус |
| --- | --- | --- | --- |
| 1 | Последний ввод восстанавливается без предварительного blur | WebKit e2e: fill → reload без blur | Выполнено |
| 2 | После паузы значение отправляется; blur и ✓ отправляют сразу | unit autosave + Chromium/WebKit e2e | Выполнено |
| 3 | Возврат сети досылает черновик без reload | Chromium/WebKit e2e offline → online → reload | Выполнено |
| 4 | Зависший запрос завершается понятной ошибкой | unit для Supabase/Yandex write и recovery timeout | Выполнено |
| 5 | Завершение включает открытую изменённую строку | WebKit e2e с программным tap при сфокусированном input | Выполнено |
| 6 | Ошибка и `Повторить` видны у нижней панели | role smoke; visual 390/430 и dark | Выполнено |
| 7 | Подтверждение удобно на узком телефоне | WebKit bounding box и подпись на 360 px; visual 390/430 | Выполнено |
| 8 | Нет blind refetch/retry; фиксируются обезличенные события | unit/e2e + diff review | Выполнено |
