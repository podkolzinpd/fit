# Мои тренировки: одинаковый список и календарь для планов и истории

Дата: 2026-10-10. Экран: клиентские «Мои тренировки». Задача: [#1549](https://github.com/podkolzinpd/fit/issues/1549). Статус: локальная приёмка.

## Подтверждённый пользователем вариант

> Да, ты прав — я упустила календарь для актуальных тренировок. Переключатель должен быть одинаковым в обеих вкладках и стоять в одном месте, сразу под верхними вкладками.
>
> ```text
> Мои тренировки                         Добавить
>
> [ Актуальное ] [ История ] [ Готовые ]
> [       Список       |      Календарь       ]
>
> Содержимое выбранной вкладки
> ```
>
> В «Актуальном» список показывает предстоящие планы и отдельно планы, по которым нужно принять решение. Календарь показывает эти же тренировки по датам, включая будущие месяцы; нажатие на дату открывает её тренировки.
>
> В «Истории» список показывает завершённые тренировки, а календарь — те же результаты по датам. Переключение вида не смешивает планы с результатами. У каждой вкладки запоминается свой выбор: например, «Актуальное» можно оставить календарём, а «Историю» — списком.
>
> «Готовые» остаются отдельной вкладкой с шаблонами; календарь там не нужен. Это исправленный вариант дизайна — пока ничего не меняла.

После этого пользователь поручил: «фиксируй, делай, выкатывай».

## Acceptance и проверка

1. Верхний уровень: «Актуальное», «История», «Готовые». Сокращение последней подписи не удаляет готовые тренировки. По умолчанию открыто «Актуальное», старая ссылка на календарь истории продолжает работать.
2. В «Актуальном» и «Истории» одинаковый переключатель «Список / Календарь» непосредственно под вкладками. На мобильной ширине 390 и 430 px всё помещается без горизонтального скролла.
3. «Актуальное / Список» сохраняет все предстоящие и начатые тренировки, а прошлые планы, ожидающие решения, показывает отдельно. Ничего не скрывается из-за длины списка.
4. «Актуальное / Календарь» показывает те же статусы по датам, в том числе в будущих месяцах и прошлые планы без решения. День с тренировками открывает карточки; пустой месяц, загрузка и ошибка имеют явные состояния и повтор.
5. «История / Список» показывает завершённые и другие фактические записи согласно прежнему контракту с подгрузкой страниц. «История / Календарь» сохраняет прежний месячный запрос, выбор даты и возврат из карточки; будущие даты недоступны.
6. Вид и выбранный месяц/день каждого раздела сохраняются отдельно при переходе между вкладками и при возврате из карточки. Изменение фильтра не добавляет лишних шагов кнопке «Назад».
7. «Готовые» продолжают показывать шаблоны; кнопка «Добавить» продолжает открывать ручное создание тренировки. Тренерский экран и данные/API не меняются.
8. Проверить светлый Lime и монохромный клиентский экран: планы в большом количестве, список/календарь, пустые данные, loading/error/retry, выбранный день и возврат, 390/430 px WebKit. Затем полный `npm run check`, CI и production после разрешённого merge.

Повторно используем `Page`, `AsyncView`, `EmptyState`, карточки тренировок, `ClientWorkoutHistoryCalendar`, `ScheduleIcon`, существующие Fit-токены и месячную загрузку. Основное действие экрана — «Добавить»; переключатели являются навигацией, не CTA. Scope ограничен клиентскими «Моими тренировками» и общим календарным примитивом без изменения тренерского поведения.
