Для затронутого iOS-клиента после merge синхронизировать, собрать и проверить свежий bundle; веб-публикация не является доказательством обновления сборки на телефоне.

Не копить все восемь PR перед первой публикацией. Каждый PR является отдельным законченным выпуском. Пока идёт CI предыдущего, можно готовить следующую задачу в отдельной ветке без вмешательства в проверяемую ветку. После merge предыдущего обновить следующий PR от нового main и получить актуальный CI; merge и публикации последовательные, с учётом более ранних активных PR проекта. Не повторять дорогие проверки без изменения кода или нового сигнала; обязательные проверки не пропускать. Новые документы, фиксация результатов и скриншоты идут с соответствующей задачей, отдельный технический PR для них не планируется.

Границы: существующие токены/компоненты Lime, уже правильные шрифты и семантические цвета сохраняются. Поле подготовки — только оформление, переработка режимов выполнения остаётся вне этого плана. Общие функции требуют проверки тренерской части на регрессии. Явно заданный нулевой отдых сохраняется; массовое изменение ранее сохранённых планов не входит в PR1. Физический iPhone нужен для воспроизведения специфичного выхода полей даты/времени: fixture WebKit ранее его не воспроизвела, это ограничение нельзя объявлять закрытым только по CSS.
