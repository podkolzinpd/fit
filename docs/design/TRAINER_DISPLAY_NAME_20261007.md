# Имя тренера у клиента — утверждённый план

Пользователь подтвердил: «фиксируй, делай, выкатывай». Одна задача, одна ветка,
один PR; production-выпуск после зелёных проверок. Внешний YAFIT в этой среде
не настроен; план и приёмка сохраняются здесь и в продуктовом PR.

## Неизменяемый acceptance-чеклист

1. Зафиксировать правило отображения: **опубликованное имя из анкеты тренера → имя и фамилия аккаунта → «Тренер»**, только если имени нигде нет. Неопубликованный черновик клиенту не показываем.
2. Сервер должен возвращать готовое имя тренера по этому правилу. Одинаковое для карточки подключённого тренера и чата, без раздельных расчётов.
3. Клиент должен показывать полученное имя. Убрать бессрочное сохранение списка тренеров: при повторном открытии раздела данные обновляются.
4. Проверить сценарии:
   - В опубликованной анкете «Татьяна», имя аккаунта пустое — клиент видит «Татьяна».
   - Анкеты нет, имя аккаунта заполнено — показывается имя аккаунта.
   - Тренер публикует новое имя — клиент получает его без повторного входа.
   - Изменён только черновик — публичное имя не меняется.
   - Несколько тренеров — у каждого своё имя.
5. После проверок выпустить исправление и проверить карточку и чат в Lime и монохромной версии.

Перепривязывать клиентов, менять приглашения или переписывать имена в существующих аккаунтах не нужно.

## Реализация и границы

Основа — существующие ClientTrainerConnections и ChatPages/чатовые hooks;
Page, AsyncView, ChatStartButton, OverflowMenu и текущие semantic tokens/CSS
переиспользуются без новой геометрии, действий и палитры. Действие «Написать»
и текущая иерархия экранов сохраняются; новая primary CTA не создаётся.
Доступ, invitation, аккаунт и публикация не меняются. Сервер читает только
published_data->>'displayName', пакетно для уже авторизованных trainer IDs;
черновик не читается и не возвращается. Изменения схемы БД не нужны.
Legacy adapter остаётся неизменным; отсутствие нового поля поддерживается
для совместимости старого API во время последовательного rollout.

## Матрица приёмки

| Пункт | Проверка | Статус |
| --- | --- | --- |
| 1 | Published/draft/account/empty cases, без утечки черновика | Unit + PostgreSQL passed |
| 2 | Общий resolver, локальный PostgreSQL actor/RLS и серверные tests | Actor/RLS 127/127 passed |
| 3 | Repository refresh + client component/hook tests | Unit + WebKit passed |
| 4 | Несколько trainer IDs, rename, draft-only, retry/error | PostgreSQL + WebKit passed |
| 5 | WebKit 390/430 Lime/mono, CI, API/frontend readback, свежий iOS | WebKit 9/9 passed; CI/выпуск/iOS ожидаются |

Loading/empty/error/retry/pending сохраняются. Scope не включает соседний
редизайн, новое автосохранение профиля, push, finance или изменение авторства.
