# Реферальная ссылка сотрудницы

## Scope

Сделать одну ссылку для сотрудницы с независимым учётом переходов и новых
регистраций. Административную панель/отчёт не добавлять; следующий отложенный
пункт исходного обсуждения остаётся вне этой итерации.

Ссылка: `https://fit-training.ru/r/staff-001`.

## Контракт

- `/r/:code` сохраняет код источника в browser local storage и перенаправляет
  на `/auth`.
- Каждый переход отправляет отдельный публичный `POST /v1/referrals/:code/click`.
- Код передаётся только в двух сценариях создания нового аккаунта Yandex ID:
  прямая регистрация и handoff. Обычный вход код не передаёт.
- Запись регистрации выполняется в транзакции `register_yandex_account` и
  уникальна по `profile_id`; повторная регистрация существующей учётки не
  добавляет конверсию.
- Учёт хранится в закрытой схеме `app_private` Cloud.ru PostgreSQL; PII
  посетителя не собираются. Переходы — количество открытий ссылки, не
  уникальные посетители.
- `staff-001` имеет нейтральную подпись «Сотрудница», поскольку имя не было
  задано. Отчётный интерфейс остаётся отложенным.

## Реализация и решения

Добавлена миграция `000208_employee_referral_attribution.sql`, API click route,
маршрут redirect, хранение кода до завершения регистрации и передача кода в оба
Cloud.ru registration path. Источник и счётчики разнесены по таблицам.

Выбрана атрибуция последнего перехода по реферальной ссылке в текущем браузере;
это соответствует одной выделенной ссылке и позволяет осознанно заменить
источник повторным переходом. Отказ от IP/device идентификаторов оставляет
счётчик простым количеством переходов и не вводит дополнительное хранение
персональных данных.
