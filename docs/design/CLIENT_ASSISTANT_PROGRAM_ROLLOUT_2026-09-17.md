# Программы в клиентском ассистенте — утверждённый выпуск

Статус: утверждено владельцем продукта 2026-09-17. Реализация использует тот же
флаг, экран, оркестратор, генератор и формат программы, что и тренерский сценарий.

## Объём

1. Открыть действие «Составить программу» клиентскому аккаунту при общем
   `VITE_ASSISTANT_PROGRAM_ENABLED=true` / `ASSISTANT_PROGRAM_ENABLED=true`.
2. Автоматически использовать собственную активную карточку клиента. Не
   показывать выбор другого клиента и не разрешать чужой `clientId`.
3. Сохранить общий четырёхнедельный контракт: 1–3 занятия в неделю, 4/8/12
   назначений, подтверждение условий и просмотр до атомарного сохранения.
4. В пользовательских подписях программы убрать привязку к тренеру. Называть
   результат рекомендованным черновиком и явно сообщать, что это не медицинское
   назначение; нагрузку нужно сверять с самочувствием и техникой.
5. Ответы «всё равно», «не важно», «без разницы», «любые», «в любые дни» на
   вопрос о днях считать полноценным ответом. Для 1/2/3 занятий выбирать
   стабильное расписание пн / пн-чт / пн-ср-пт и продолжать квиз без повторного
   вопроса. В других вопросах эти слова не должны заполнять поле автоматически.
6. В Supabase и Yandex разрешить клиенту применить или отменить только свой
   валидированный `program-v1`. Старые/невалидированные и чужие программы
   остаются запрещены.
7. Будущие общие изменения генератора, валидатора и карточки должны одновременно
   применяться к клиентскому и тренерскому сценариям. Раздельными остаются только
   выбор профиля, ownership-проверки и при необходимости role-specific copy.

## Матрица приёмки

| Пункт | Видимый результат | Проверка | Статус |
| --- | --- | --- | --- |
| 1 | У клиента есть общий вход «Составить программу» | component + route | Проверено |
| 2 | Запрос сразу относится к собственной карточке | API unit | Проверено |
| 3 | Общая карточка показывает рекомендацию без слова «тренер» | component + WebKit 390/430 | Проверено |
| 4 | «Всё равно / не важно / в любые» не зацикливают вопрос о днях | parser unit + turn regression | Проверено |
| 5 | Клиент сохраняет 4/8/12 назначений только себе, retry без дублей | Supabase pgTAP + Yandex parity | Проверено |
| 6 | Чужой `clientId` и legacy-программа запрещены | Supabase pgTAP + DB contract | Проверено |
| 7 | Тренерский сценарий не изменил доступ и сохранение | unit + full check | Проверено |
| 8 | Зелёный PR объединён, production и mobile bundle проверены | CI + deployment smoke | В работе |
