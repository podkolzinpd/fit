# YAFIT-526 — Надёжная привязка по ссылке и QR в Yandex

## Цель

Привязка спортсмена и тренера по ссылке или QR должна полностью работать в production-контуре Yandex и не оставлять частично созданные данные.

## Изменения

1. Добавить отсутствующий Yandex-сценарий принятия приглашения спортсменом.
2. Создавать новую карточку спортсмена и защищённую ссылку одной транзакцией;
   повтор с тем же идентификатором операции возвращает тот же результат.
3. Принимать перенесённые ссылки с меткой `source=supabase` через Yandex API без записи в Supabase.
4. Возвращать понятные конфликты: сначала отключить действующего тренера либо обратиться в поддержку при неоднозначном объединении данных.
5. Проверить ссылку и QR как один и тот же защищённый маршрут.

## Критерии приёмки

- тренер создаёт карточку и получает ссылку/QR без появления карточки-сироты
  или дубля при ошибке и повторе;
- новый спортсмен принимает приглашение и получает доступ к назначенным тренировкам;
- существующая самостоятельная карточка спортсмена объединяется атомарно с карточкой тренера;
- повторное открытие уже принятой ссылки не создаёт дубль;
- спортсмен с активным тренером получает понятное требование сначала отключиться, данные не меняются;
- старые Yandex-мигрированные ссылки с `source=supabase` принимаются через Yandex;
- приглашение тренеру продолжает подключать его к существующей карточке;
- код приглашения остаётся совместимым на переходный период;
- все изменения и production-проверки выполняются только в Yandex-контуре.

## Проверки

- интеграционные тесты Yandex PostgreSQL для нового спортсмена, существующей карточки, повтора и конфликта тренера;
- API-тесты создания и принятия ссылки;
- компонентные тесты единого создания карточки со ссылкой и старой метки источника;
- проверка типов, линтер, unit/integration, production build;
- ручная проверка двух ролей на мобильной ширине после выкладки.
