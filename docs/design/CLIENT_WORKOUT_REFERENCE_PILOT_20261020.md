## Подтверждённый план (сохранять нумерацию)
Пилот — клиентская учётка budoha1@yandex.ru. Дополнение владельца: включить также все ранее утверждённые тестовые учётки из соседних задач после проверки действующих профилей. Два варианта — «Оригинальный» и «Компактный». Общий дизайн-код пока не меняем.
Тренерская зависимость плотности от выключенных по умолчанию анимаций клиенту не переносится:
- анимации по умолчанию включены в обоих вариантах;
- выключаются существующей настройкой;
- сохранённый выбор пользователя имеет приоритет;
- при выключении изображение и место под него полностью исчезают;
- переключение плотности не меняет настройку анимаций.
По умолчанию «Оригинальный». Выбор плотности сохраняется отдельно для клиентского режима.

## Обязательные механики (не менять смысл и нумерацию)
1. Быстрая замена числа. При первом нажатии на вес или повторы выделяется всё значение. Новое число заменяет старое без долгого выделения. Переход между полями сохраняется.
2. Спокойное открытие клавиатуры. Уже видимое поле не перемещается. Если строка перекрыта, прокручивается только необходимая часть содержимого, чтобы оставить её над клавиатурой. После закрытия экран сохраняет понятную позицию.
3. Повторение веса. Используем существующий перенос последнего подтверждённого веса в следующий нетронутый подход той же плановой группы. Другой запланированный вес, введённые вручную значения и подтверждённые результаты не перезаписываем.
4. Редактирование выполненного подхода. Поля доступны; изменение веса или повторов не снимает галочку и не запускает отдых заново.
5. Сохранение ввода. Обновление данных, переключение плотности и изменение размеров карточки не должны пересоздавать активное поле, закрывать клавиатуру или терять черновик.
6. Остальная механика Live. Сохраняем перенос всей карточки, заметки, меню, подтверждение подходов, отдых и завершение тренировки. Изменения режимов выполнения из #1741 учитываем отдельно от оформления.

LiveSetInput, live-input-visibility, live-set-cache, текущий coordinator и WorkoutGestures переиспользуем. Не создаём параллельные числовые поля, календарь, state machine или coordinator.

## Приёмка каждого PR
Перед каждым PR сверяем свежий код с соседними изменениями. Для Live: оба варианта плотности × анимации включены/выключены × обе темы, ширины390/430, WebKit/Chromium. Поведение настоящей клавиатуры iOS проверяется отдельно: уменьшение окна браузера не равно этой проверке. Доступность физического устройства и результат отмечаются явно; не выдавать симуляцию за физическую проверку.
Каждый PR публикуется только в тестовый пилот. Общая шрифтовая миграция, изменение дизайн-кода и включение для остальных пользователей в эту серию не входят.
