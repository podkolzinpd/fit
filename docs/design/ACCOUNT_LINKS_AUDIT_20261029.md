## Итерация 1 — 2026-10-29 — GPT / OpenAI

Задача: проверить все аккаунты и привязки переданного предполагаемого тренера.
Расхождения: существующий account_history рассчитан на четыре адреса другого
обращения; account-deletion использует цель параллельной задачи. Их секреты и
назначение не меняются. Прямых локальных credentials для рабочей БД нет.
Сделано: отдельный локальный проект диагностики и manual main-only workflow.
Решения: read-only транзакция; все retained bindings обнаруживаются по точным
колонкам login_sha256/profile_id в app_private; вывод только псевдонимы/состояния
и счётчики. Существование нескольких профилей не доказывает одного владельца.
Отвергнуто: подмена чужих целей, автоматическое объединение, поиск по именам,
публикация контактов, произвольный SQL через workflow inputs.
Проверка: результаты локальных тестов дополняются ниже. Production не запускался.
Открыто: публикация диагностического workflow требует отдельного разрешения
по AGENTS, пункт 5; приватный target ещё не сохранён. Нативный аккаунт без
retained login binding невозможно установить только по email/логину.
Дальше: разрешённая публикация/CI, временный private secret, один read-only
запуск и удаление только этого временного секрета после результата.

Уточнение владельца: добавлен адрес спортсменки; диагностика должна связать
её собственный профиль с карточками и найденными учётками тренера. Технический
формат допускает2–4приватных адреса, фактическая цель — только три переданных.
Локально:9/9unit/transport tests; PostgreSQL17 с полной текущей цепочкой
миграций — пустой результат, отдельные профили, native identity, связи, тренировки
и приглашения; отсутствие приватных значений в отчёте и неизменность fixture.
Это подготовка инструмента; реальные аккаунты ещё не проверены.

После добавления третьей цели:9/9целевых тестов и отдельный PostgreSQL17
probe прошли; собственная карточка спортсменки сопоставляется с псевдонимом
её профиля и историческим профилем тренера. Production/секреты не менялись.
