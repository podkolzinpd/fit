# Карта тела — калибровка и компактные карточки

Статус: реализация и локальная приёмка завершены; выпуск через обязательный CI.
Владелец продукта 26.09.2026 явно разрешил реализацию,
merge и полный production rollout без повторного согласования.

## Зафиксированный план

1. Сохранить исходные мужскую и женскую картинки, исправить контуры и области
   нажатия централизованно для всех экранов.
2. Схематическую фигуру временно скрыть. Она исправима, но требует отдельной
   подгонки практически всех зон.
3. Для пользователей без указанного пола и с сохранённым выбором «Схема»
   оставить список зон с показателями — данные не удалять, пол не подставлять.
4. Расчёты и ИИ-анализ не трогать.

В рамках пункта 1 применяется выбранный первый эскиз: в кабинете компактная
фигура слева, показатель справа, явная подпись «За последний месяц» с датами;
в прогрессе — исходная фигура целиком без высокой серой подложки и лишних рамок,
компактные переключатели, пояснение выбранной зоны ниже. Процент в кабинете
относится к фактическому rolling-month period, не к последней тренировке.
Значение процента поясняется отдельно, без «учтённых подходов» в основной строке.

Переиспользуются MapPanel, PeriodLoadMap, TrainingBodyProgressMap, Fit segmented
controls, кнопки и типографика Onest, существующие surface/border/success tokens.
Главным действием кабинета остаётся ввод тренировки; карта не добавляет primary
CTA. Настройки «Фигура / Список» сохраняют пользовательский выбор без угадывания
пола. Полноценные показатели и детализация доступны также в списке.

Тесты используют локальные данные и заглушки сетевых ответов. Расход токенов
продуктовой модели в тестах не допускается. Продуктовый ИИ-анализ не запускается.
Геометрия проверяется на исходных PNG и их alpha-маске, независимо для каждого
пола; общий SVG viewBox сохраняет единую систему координат картинки и контуров.

При проверке обнаружено и исправлено пересечение областей нажатия соседних зон
бедра: широкая hit-обводка перехватывала 12 из 512 контрольных нажатий. После
уменьшения обводки все 512 проходят. Для небольших зон сохранена равнозначная
альтернатива — кнопки списка, чтобы не увеличивать невидимые области до новых
перекрытий. Старый глобальный выбор пола тренером по-прежнему не переносится
на фигуру конкретного спортсмена; старый выбор схемы переносится в список.

Полная локальная проверка `npm run check` пройдена: lint, TypeScript,
2008 frontend-тестов, 927 API-тестов, контроль типов БД/инфраструктурных
контрактов и production-сборка. Обязательные UI-проверки дополнены 12 WebKit
сценариями на 320/375/390/430 px и 8 положительными/отрицательными проверками
доступного эквивалента маленьких SVG-зон: отсутствие, маленький размер,
отключённая кнопка, неверная подпись или другая карта не дают исключения.
17 обновлённых Linux PNG относятся только к картам и Home с картой; эталоны
профиля, Обзора, замеров и расписания не изменены. Повторный Linux-прогон без
обновления снимков завершился успешно. Диагностические harness и contact sheets
оставлены вне продуктовой ветки.

Первый CI дополнительно обнаружил пограничное отличие растеризации Linux
WebKit: правый контур внутреннего бедра мужской фигуры давал 98,9755% внутри
PNG вместо обязательных 99%. Уточнён сам край контура, порог не ослаблен:
повторное измерение Linux WebKit — 2453/2453 пикселей внутри (100%).
