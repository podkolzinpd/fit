# Просмотр техники из плана и live-тренировки

## Цель

Дать тренеру и спортсмену единый просмотр техники упражнения из двух рабочих сценариев:

- составление и редактирование плана;
- выполнение live-тренировки.

Просмотр не должен менять упражнение, подходы, введённые значения, положение экрана или состояние таймеров.

## UX

1. В редакторе плана техника открывается отдельной кнопкой в меню упражнения. Это не конфликтует с нажатием на основную часть карточки, которое уже раскрывает и сворачивает подходы.
2. В live-тренировке техника открывается нажатием на название упражнения. Поля подходов, подтверждение, перестановка и меню остаются независимыми зонами.
3. Используется один общий modal/sheet с анимацией, названием, оборудованием, целевой мышцей и инструкцией.
4. Для упражнения без медиа и инструкции вход в технику не показывается.

## Видео

- `autoplay`, `muted`, `loop`, `playsInline`;
- без нативного `controls`, fullscreen и Picture-in-Picture;
- статичный кадр остаётся виден, пока видео не начало воспроизводиться;
- после начала воспроизведения видео плавно появляется поверх кадра;
- при запрете autoplay появляется собственная кнопка запуска;
- при ошибке видео остаются изображение и возможность повторить загрузку.

Полный ролик запрашивается только после открытия техники. Каталог и карточки тренировки не должны заранее загружать все видео.

## Проверки

- общий просмотрщик корректно показывает метаданные и закрывается;
- video element не имеет нативных controls;
- открытие из плана сохраняет введённые значения и раскрытие карточки;
- открытие из live не останавливает таймер и не меняет подходы;
- WebKit/iPhone: ролик остаётся inline и не показывает системный fullscreen UI;
- упражнения без анимации корректно используют изображение/текстовый fallback.

## Выкладка

Изменение не требует миграции БД. Выкладка выполняется отдельным PR после обязательных CI-проверок с коротким smoke-тестом редактора плана и live-тренировки в production.
