# Закрытая аналитика Fit — 05.11.2026

## Область

Перенести основные метрики дашборда «Сводные метрики приложения» на отдельный адрес домена Fit без ссылки из приложения. Раздел использования и стоимости моделей отложен по решению владельца 05.11.2026.

Доступ — только двум согласованным владельцем Яндекс-аккаунтам. Отдельное право аналитики не наследует право корпоративного администратора. Идентификация через проверенный Yandex ID; проверка доступа и чтение данных выполняются на сервере. Контакты не публикуются в репозитории.

## Исходные факты и границы

- Дашборд содержит графики и таблицы тренеров, клиентов, тренировок и обратной связи, селектор самостоятельной регистрации и отметку обновления. Необходимо отдельно зафиксировать поля, формулы, фильтры, сортировки и полноту всех таблиц.
- В native PostgreSQL существуют `analytics.trainers_metrics`, `analytics.trainer_overview`, `analytics.client_overview`, `analytics.app_feedback`. Представления overview дополнены миграцией 000080 и исключениями тестовых календарных данных в 000119. Прямой доступ `fit_api` к данным закрыт; не расширять его общей выдачей прав.
- Корпоративный кабинет использует привязку проверенного provider login к первому subject. У аналитики должен быть собственный список и собственная проверка, включая отзыв доступа и защиту от повторного использования логина.
- Код Fit содержит оценку расходов моделей, а чарт DataLens использует биллинговый отчёт; эти данные не взаимозаменяемы. Раздел моделей в эту работу не входит.

## Приёмка

1. Полная инвентаризация чартов и селекторов основного раздела, их источников, формул и значений на контрольном срезе. Отдельно проверить связи селектора с каждым чартом.
2. Независимый серверный доступ по проверенному Yandex ID для двух аккаунтов: без сессии 401, другим аккаунтам 403, повторное использование логина не переносит право. Операторское включение, отзыв и прямой read-back без публикации контактов.
3. Данные через ограниченный серверный интерфейс с проверкой права при каждом запросе; кеширование чувствительных ответов отключено, прямые таблицы для `fit_api` закрыты. Таблицы, сообщения и идентификаторы не попадают в клиентскую аналитику и логи.
4. Страница доступна по прямому адресу, без нового пункта навигации приложения. Проверить вход, отказ, загрузку, ошибки и работу на узком и широком экранах.
5. Сверить каждый показатель и таблицу с DataLens на одинаковом срезе и времени, включая пустые значения, исключения, пагинацию и свежесть. Выполнить локальные и CI проверки, выпуск и production read-back двух разрешённых и постороннего аккаунтов.

### Проверенные проблемы

- `PrivateAnalyticsPage.tsx`: таблицы без сортировки, поиска и пагинации,
  технические имена полей; график показывает только крайние даты, значения
  доступны через SVG title, раскрытие дублирует все дни.
- `000080_analytics_overview_parity.sql`: `new` означает отсутствие последнего
  учитываемого действия, без ограничения возраста регистрации; `active` —
  последнее действие не старше 7 суток. Это операционное правило, не бенчмарк.
- В активность тренера входит `max(workouts.updated_at)` по принадлежности
  тренировки, без проверки автора изменения. Клиентское действие и изменение
  служебных полей могут выглядеть как действие тренера. `client_trainers.updated_at`
  тоже не доказывает изменение заметки. Недопустимо объявить это точным WAU.
- Входы сейчас приближены датами создания сессий; это не история посещений.
- Bundle000189 содержит только trainer/client overview и feedback, без питания,
  финансов, имён и событийного drill-down. Фильтрация накопленных сумм по дате
  регистрации не превратит их в активность за выбранный период.
- `nutrition_entries` позволяет считать владельцев, записи, дни дневника;
  `nutrition_consents` доказывает разрешение просмотра, но не сам просмотр.
  Просмотр тренером требует отдельного подтверждённого события. Историческое
  отсутствие таких событий отображается как «не измерялось», не нулём.
- `trainer_finance_payments/packages/sessions/events` существуют; поступления,
  цены пакетов, списания и долги нельзя складывать в один показатель выручки.
- Известные тестовые календарные данные исключены000119. `is_test_account=false`
  в исходных views не доказывает полноту исключения всех тестовых аккаунтов.
