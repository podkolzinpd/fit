# Один активный тренер — утверждённый план, 19.10.2026

Статус: реализация и локальная приёмка завершены, выпуск ожидает CI/очереди. Пользователь разрешил полный выпуск; строго один активный тренер у спортсмена, без потери данных и истории.

## Неизменяемый утверждённый план

### 1. Сначала проверить существующие данные
Подготовить проверку без изменений:
- активная связь и старые записи совпадают;
- есть только старое членство;
- есть активная связь без членства;
- обнаружены несколько потенциальных тренеров;
- карточка принадлежит старому техническому разделу тренера.

Для неоднозначных случаев — отдельный разбор. **Не выбирать автоматически «последнего тренера» и не удалять связи массово.**

### 2. Сделать один источник текущего доступа
Для привязанного спортсмена текущий тренер определяется единственной активной связью.

Все проверки должны одинаково различать:
- текущего тренера;
- бывшего тренера;
- постороннего;
- тренера, ведущего ещё не привязанную карточку.

Проверить применение правил к карточке, планированию, Live, прогрессу, целям, расписанию, уведомлениям, питанию и финансовым действиям. Авторство и финансовую историю не переписывать.

### 3. Согласовать все команды подключения
Ссылка, QR, ручной код, обратное приглашение тренеру и чат используют общие правила:
- проверка роли и владельца;
- блокировка карточки от параллельных подключений;
- запрет второго активного тренера;
- атомарность;
- безопасный повтор;
- отсутствие скрытой смены тренера.

Старые адреса API можно сохранить для совместимости, но не отдельные старые правила внутри них.

### 4. Исправить отключение и повторное подключение
Одна транзакция закрывает активную связь и текущий доступ.

После неё профиль, чат и список клиентов перечитывают одинаковое состояние. Новое приглашение через чат действительно создаёт новое предложение.

Бывшему тренеру не открываются новые данные спортсмена. Историческая видимость сохраняется только в предусмотренных границах.

### 5. Исправить вход и интерфейс
Сохраняются прежние необходимые доработки:
- приглашение открывается без сессии;
- роль регистрации соответствует приглашению;
- ссылки из нативного приложения ведут на публичный сайт;
- ошибки различают сеть, срок, отзыв и конфликт;
- состояние «уже принято» позволяет восстановить результат;
- профиль показывает «Мой тренер», без дополнительных тренеров.

Используем существующие компоненты Fit, без редизайна.

### 6. Удалить устаревшие исполняемые ветки
После перевода потребителей:
- удалить неиспользуемые методы и дубли;
- убрать обходы проверки активной связи;
- удалить многотренерские состояния и тесты, закрепляющие неправильное поведение;
- закрыть старые команды от вызова, если они больше не нужны.

Архив миграций, средства восстановления и ещё необходимые локальные зависимости не удалять под видом этой чистки.

### 7. Проверить весь жизненный цикл
Обязательный сквозной сценарий:

**Самостоятельные тренировки → подключение → план тренера → выполнение → отключение → самостоятельная работа → новый тренер.**

Отдельно проверить обе стороны приглашения, параллельные запросы, потерю ответа, повторный вход, старые ссылки и сохранность данных. Проверки прав — в настоящем PostgreSQL, интерфейса — в production-составе приложения.

### 8. Выпустить совместимо
Сначала серверные ограничения и безопасная работа с данными, затем интерфейс и удаление ненужных веток. Старая установленная версия приложения тоже не должна обходить запрет второго тренера.

После выпуска — проверка опубликованной версии и обновление документации по факту.

## Проверка существующего и границы

- База: main `327d9b8848989ac78ad0721690f6bc04f3e6eaa5`; открытых PR при старте нет. Поток identity-runtime.
- Уже работает: уникальный активный период (migration 19); атомарное объединение карточек и отказ при конфликте данных; выбранное отключение спортсменом (135); оригинальная история чата (145).

- Подтверждено на синтетическом PostgreSQL 17: обратное приглашение создаёт второе членство без второго активного периода; второе членство даёт доступ к прогрессу/Live. Выход тренера не закрывает период. Повтор приглашения чата после отключения не создаёт новое предложение.

- Не меняем техническое владение clients.trainer_id, авторство, финансовые записи, chat participants/messages/read cursors, миграционный архив, legacy recovery/media. Никакого второго тренера и никакой автоматической смены.
- Состояния UI: loading, без сессии, неверная роль, действующее приглашение, сетевой сбой/retry, истёкшее/отозванное/архивное, принято своим/чужим пользователем, уже отключённая связь; обе роли, 390/430/1440, WebKit и Chromium.
