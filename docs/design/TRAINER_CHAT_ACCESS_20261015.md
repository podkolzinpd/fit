# Тренерские чаты — утверждённый план, 15.10.2026

## Неизменяемый план пользователя

Предлагаю так: **тап по иконке — чат, движение влево — архивирование**. Отдельная ручка для свайпа не нужна: тянуть можно за всю карточку, включая кнопку чата.

### PR 1. Чат вместо трёх точек

- Убираем три точки. Справа оставляем одну кнопку чата с числом непрочитанных.
- Нажатие на имя открывает карточку клиента, на чат — существующую переписку.
- Короткий свайп влево открывает «В архив», полный свайп архивирует при отпускании — как сейчас.
- Если жест начался на кнопке чата, после свайпа переписка **не открывается**. Вертикальное движение только прокручивает список.
- Сохраняем «Вернуть» после архивирования, обработку ошибки и прежние ограничения прав.
- Архивирование кнопкой в карточке клиента остаётся — для работы без свайпов, в том числе с клавиатуры.

Переиспользуем существующие карточку со свайпом, кнопку чата и SVG-иконки. Размер кнопки — прежние 44×44, оформление — текущий Lime.

### PR 2. Убираем исчезающие входы в переписку

- В списке клиентов и внутри карточки используем одинаковое правило: **существующая история даёт вход в чат**, даже если клиент больше не подключён. Возможность отправлять сообщения определяет сервер.
- Для подключённого клиента без переписки кнопка начинает диалог.
- Для клиента без аккаунта и без истории не показываем неработающий чат; приглашение остаётся в его карточке.
- В недельном расписании добавляем компактный вход в «Сообщения». Дневную плитку сохраняем, нижнюю навигацию не перестраиваем.
- Ошибка загрузки переписок показывается как ошибка с повтором, а не как отсутствие диалогов.

### PR 3. Сохраняем доступ к старым чатам

- Исправляем выборку, из-за которой переписка может выпадать после объединения карточек или изменения привязки аккаунта.
- Сохраняем идентификаторы диалогов, сообщения, вложения и отметки прочтения.
- Не создаём переписки заново и не объединяем истории вслепую.
- Проверяем доступ обоих участников и запрет доступа постороннему пользователю.

В каждом PR — целевые проверки. Перед выпуском отдельно проверяем тап/свайп с самой иконки, отмену жеста, архив/возврат, непрочитанные и старую историю на мобильном WebKit/Chromium и компьютере.

**Итого: 3 PR. Пока только план — ничего не меняю и не выкатываю.**

Cloud.ru API/frontend выпуск, независимая проверка и свежая native-сборка.

тренерских чатов, не расширение Coach Live fixed2-пилота. Клиентский UI,

объединение карточки не передаёт чужую переписку новому владельцу.

## Preflight и приёмка

- Референс: текущие /clients, /clients/:id, /schedule и /chat.
- Компоненты: ClientSwipeCard, ChatStartButton, ChatHeaderAction, Page,
  AsyncView, Coachmark; существующие MessageIcon/ArchiveIcon/HistoryIcon.
- Primary списка — существующее добавление/приглашение; чат — компактное
  действие строки 44×44. Цвета/радиусы берутся из текущих токенов темы.
- Состояния: history/connected/no-account, active/archived/no-permission,
  loading/error/retry, pending/success/undo, unread0/99+, отменённый/короткий/
  полный/вертикальный жест. Desktop/keyboard остаются доступными.
- Нужные новые interaction cases расширяют существующие component/browser
  тесты; визуальная матрица отделена от длинного поведения. Chromium/WebKit
  проверяют разные engines, размеры — только реальную геометрию/жесты.
- PR3: clean PostgreSQL17 migrations, actor/RLS/grants, оба участника,
  посторонний, архив/перепривязка/объединение, прежний ID/сообщения/вложения/
  read-cursor. Никакого SQL вручную в production.
- Каждый PR: check, зелёный CI, очередь createdAt, обновление от свежего main.
- Финал: официальный Cloud.ru release, exact public readback, controlled
  browser acceptance без реальных сообщений; native sync/build/install/launch.
  Физический iPhone/реальный OAuth не подменяются fixtures.
