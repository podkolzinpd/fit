Уточнение пользователя: сворачивание выполненных и ещё не начатых упражнений сохраняется. Пункт 2 первоначального предложения отменён; стабилизируем переход между свёрнутыми и активной карточками.

## Утверждённый план

1. Сделать таблицу подходов стабильной.
   В активном упражнении все строки сохраняют одинаковые колонки и примерно одинаковую высоту: номер, кг, повторы, галочка. Тап по значению сразу открывает ввод — дополнительное «Заполнить» больше не требуется. После галочки меняются состояние строки и отметка выполнения, но строка остаётся на месте. План и фактический результат продолжают храниться отдельно.
2. Сохранить сворачивание выполненных и ещё не начатых упражнений согласно уточнению пользователя. Смена активной карточки не должна вызывать несколько последовательных скачков.
3. Добавить отдельную кнопку «Таймер».
   В компактной закреплённой шапке: общее время тренировки и кнопка «Таймер». При запущенном отдыхе кнопка показывает остаток времени. Тап открывает нижнюю панель с длительностью, запуском, −15 с, +15 с и остановкой. У упражнения — небольшая настройка «Отдых 1:30» или «Отдых выкл.». Появление отсчёта не меняет высоту страницы; общий таймер тренировки продолжает идти.
4. Добавить «Заметка» к упражнению у клиента.
   Под названием — компактная строка «Заметка», по нажатию открывается ввод. Существующий текст виден в карточке. Заметку клиента сохраняем для этого упражнения в данной тренировке, отдельно от указаний тренера, чтобы один текст не перезаписывал другой.
5. Согласовать подтверждение, сохранение и переключение.
   Одно нажатие должно давать один последовательный переход. Введённые значения сохраняются локально; ответ сервера и realtime не должны возвращать старые числа, заново раскрывать строки или перемещать фокус. Секундный отсчёт обновляет только таймер. Ошибка сохранения показывается компактно, не перестраивая карточку.
6. Проверить движение экрана на телефоне.
   Отдельно пройти: ввод с открытой клавиатурой, галочку, последний подход, переход к другому упражнению, окончание отдыха, открытие техники и заметки, возврат после блокировки, медленную сеть и суперсеты. Записать положение активной строки и потерю фокуса — обычного теста «кнопка сработала» недостаточно.

## Порядок

Сначала стабильность строк и переходов, затем таймер и заметка, после — финальная мобильная проверка. Приёмка: значения не исчезают, клавиатура самопроизвольно не закрывается, таймер не толкает содержимое, завершение подхода не вызывает несколько последовательных скачков.

## Проверки и ограничения

- `npm run check`: 1310 frontend, 364 API и 112 infrastructure tests; build/lint/types/coverage зелёные.
- `npm run db:test`: 998 assertions, 80 файлов, включая раздельное хранение заметок и права.
- Yandex PostgreSQL integration: 30/30.
- Общая регрессия auth/trainer: 25 исходных сценариев + 2 исправленных повторно зелёные.
- Полный локальный `db:reset` не выполнен: auto-review запретил разрушительный сброс общей локальной БД. Миграции применены штатно без сброса; свежую БД дополнительно проверяет обязательный CI.
- Нет проверки на физическом iPhone с реальной системной клавиатурой; WebKit проверяет геометрию, фокус и возврат из фона.
- Настройка отдыха сохраняется только для текущей сессии/вкладки; исходный план не переписывается.
- До фронтенда необходимо выкатить additive Supabase migration; Yandex deployment применяет свою миграцию перед публикацией API. Никакие старые факты или заметки не мигрируются и не удаляются.

Существующие Fit-компоненты и graphite-токены сохраняются. Основное действие — подтвердить подход. Выпуск: полный check, обязательный CI, merge, production deployment и smoke.
