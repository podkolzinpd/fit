# ФИТ19 — единое завершение тренерского Live

Владелец01.11.2026 утвердил один PR, самостоятельную реализацию и полный
выпуск в новой айдентике Fit/Lime. База:f0dfdbe5. Это развитие существующего
YAFIT-698, без новых статусов, команд API, миграций и финансового механизма.
Канонический план и журнал этой задачи — этот документ; отдельного DEVLOG нет.

## Согласованный объём одного PR

| ID | Результат | Проверка |

| L107 | Штатный выпуск по очереди и независимая проверка опубликованного runtime | exact-head CI, current-main CI, API/web/OTA, файлы/health и публичный UI |

«Завершить» и «Отметить проведённой» — одна операция. Отдельный пункт
«Просто сохранить» не добавляется: выход без завершения остаётся назад.
Не состоялась сохраняет запись/план/результаты без расхода; удаление пустой
записи не подменяет отмену. Отправленные факты не переписываются планом.
Нижняя панель удаляется как набор дублирующих действий, сообщения о
синхронизации и восстановление отправки остаются доступными.

## Границы

Только тренерский Live и явный вариант существующего окна. Detail/quick
attendance и клиентская механика сохраняются. Исходные full-макеты,
коммерческий шрифтовой пакет, PII и секреты не публикуются.
Соседние PR1920/1921/1922 и их актуальные изменения сохраняются; публикации
идут по действующей очереди, не параллельно. Отдельного PR ради приёмки нет.

## Журнал

### Итерация1 — 01.11.2026 — GPT / OpenAI

Задача: зафиксировать утверждённый план, реализовать и полностью выпустить
одним PR в новой айдентике; три названия без поясняющих подписей.
Расхождения: существующее окно поддерживает проведение/отмену, а удаление
живёт отдельной кнопкой; нижняя панель также содержит sync/retry. Решение —
расширить явный Live-вариант окна, переиспользовать команды и сохранить
ошибки/восстановление отдельно от удаляемых действий.
Сделано: чистая своя ветка от свежего main, прочитаны контракты и проверки.
Решения: L101–L107 выше; клиентский/detail-вариант не получает новый chooser.
Отвергнуто: второй backend-процесс, новый финансовый учёт, инструкции под
пунктами, произвольное удаление непустых записей.
Проверка: Git/instructions/main/фактические handlers и существующие E2E.
Открыто: реализация, проверки, очередь и выпуск. Автопроверка запретила
новое сообщение координатору; обхода нет, очередь читается через PR.
Дальше: существующее окно и Live-входы, затем применимые проверки/CI.
