# YAFIT-568 — сократить экран завершения тренировки

Пункт 1 плана [YAFIT-567](https://st.yandex-team.ru/YAFIT-567). Реализация и выпуск разрешены владельцем продукта. Остальные пункты общего UX-плана остаются в бэклоге.

## 1. Сократить экран завершения

Цель: сразу понятно, что сохранено и выполнено, следующий шаг — feedback.

- Оставить статус завершения, дату и краткую строку полезных итогов.
- Убрать дубли процента выполнения: вместо трёх представлений оставить один блок «Выполнено X из Y подходов», с процентом максимум один раз, если он нужен в этом же блоке.
- При частичном завершении оставить краткую информацию о незавершённых подходах. Не делать из процента отдельный «Главный результат».
- Поднять существующую форму обратной связи сразу после краткого итога. «Поделиться» перенести ниже feedback и сделать вторичным.
- Сохранить действительное достижение/рекорд, если его определяет существующая логика; не заменять повтор выполнения новым мотивационным блоком.
- Не менять подтверждение частичного завершения, запись факта, расчёты, вопросы RPE/самочувствия/боли и повторное открытие результата.

Приёмка: полное/частичное завершение, отсутствие подтверждённых подходов согласно текущим правилам, feedback до/после сохранения, loading/error. Нет ложного «сохранено» при ошибке. Нет повторов процента. Feedback достигается без прокрутки через несколько одинаковых итогов. Клиент и доступный тренеру экран завершения проверяются отдельно; клиентские вопросы не добавляются тренеру.

## Матрица проверки

| Пункт | Видимый результат | Проверка | Статус |
| --- | --- | --- | --- |
| Статус, дата, краткие факты | Один верхний блок с фактическими итогами | Компонент; WebKit 390 px, Chromium 430 px; светлая/тёмная темы | Проверено |
| Одно выполнение плана | Одна строка «Выполнено X из Y» и один процент | Unit: полное/частичное/0 подходов; мобильный e2e | Проверено |
| Незавершённые подходы | Конкретные упражнения и количество остаются видимыми | Unit: частичный результат; правило подтверждения не менялось | Проверено |
| Feedback перед шеринговым действием | Форма выше «Поделиться»; после сохранения — краткие итоги | DOM-порядок, мобильный e2e; существующий feedback-контракт не менялся | Проверено |
| Достижение | Реальный рекорд/рост остаётся отдельным фактом | Unit: рекорд, отсутствие результата, загрузка/ошибка; мобильный e2e | Проверено |
| Роли | Клиентский и тренерский результат сохраняют свои действия | Клиент 390/430 px, тренер 1440 px; Lime использует тот же клиентский компонент | Проверено |

Референс: текущий клиентский экран результата и существующая форма `WorkoutClientFeedback`. Переиспользуются `WorkoutCompletionReport`, `WorkoutClientFeedback`, Fit action variants и семантические токены `--surface-*`, `--fg`, `--secondary-label-fg`, `--success-*`, `--warning-*`. Primary-действие до отправки обратной связи — «Сохранить итоги»; после — «Готово». Новые метрики, правила сохранения и палитра не вводятся.
