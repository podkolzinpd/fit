# Progress AI — повтор после неудачной генерации

Статус: реализовано и проверено локально 15.09.2026.

## Пользовательский результат

Неудачный ответ модели больше не блокирует обновление выбранного периода до
следующих UTC-суток. После защитной паузы пользователь может повторить запрос,
при этом общий дневной лимит продолжает учитывать каждый фактический вызов
модели. Интерфейс показывает точную причину отказа вместо общей ошибки.

## Неизменяемый план

### 1. Освободить период после неудачного вызова

- Неудачная генерация сохраняет 30-минутную паузу для всего периода, в том
  числе при изменившемся fingerprint.
- После паузы `failed`-попытка не занимает периодный слот.
- `succeeded` и действующий `pending` по-прежнему блокируют второй платный
  вызов за период в те же UTC-сутки.
- Просроченный `pending` не блокирует период навсегда.

Статус: выполнено.

### 2. Сохранить контроль расхода

- Каждый реально начатый model call, успешный или неуспешный, остаётся в общем
  лимите: не более трёх вызовов на клиента за UTC-сутки.
- Кеш, параллельная блокировка, отсутствие фоновых вызовов и аварийный
  выключатель не меняются.
- Автоматический повтор модели не добавляется.

Статус: выполнено.

### 3. Не терять код backend-ошибки

- Yandex repository сохраняет предметный код ошибки endpoint генерации.
- Для cooldown, period/daily limit и quality failure интерфейс показывает
  точный текст и не предлагает немедленный повтор.
- Ошибки авторизации и доступа сохраняют общий repository-контракт.

Статус: выполнено.

### 4. Проверить без расхода токенов

- SQL-тест проверяет cooldown, повтор после него, успешную блокировку,
  просроченный lease и общий дневной лимит.
- Repository-тест использует только mock HTTP-ответы.
- Локальные, CI и production smoke не обращаются к модели.
- После deployment выполняется только проверка доставки; один реальный запуск
  оставляется пользователю.

Статус: выполнено.

## Acceptance matrix

| Сценарий | Ожидаемый результат |
| --- | --- |
| Ошибка модели, прошло меньше 30 минут | `cooldown`, model call не выполняется |
| Изменился fingerprint во время cooldown | `cooldown`, обхода паузы нет |
| Ошибка модели, прошло больше 30 минут | новый вызов разрешён, если дневной лимит не исчерпан |
| Успешный вызов уже был сегодня | повтор периода блокируется или отдаёт точный кеш |
| Pending lease истёк | новая попытка не блокируется старым lease |
| За день начаты три вызова | четвёртый блокируется независимо от результата первых трёх |
| Backend вернул предметный 409/422/429/5xx | UI получает точный код и правильный retry-контракт |

## Границы

- Prompt, агрегатор, модель, лимиты входа/выхода и quality gate не меняются.
- Production-данные вручную не редактируются и счётчики не обнуляются.
- Автоматические и тестовые live AI-вызовы не добавляются.
