## Полный реестр подтверждённых исправлений

### R07 · P1 · Потеря нажатия / закрытие окна / скачок после ввода

**Наблюдение:** переход из input к кнопке снимает keyboard-open и перестраивает
экран между pointerdown и click. Create при пустом поиске закрывает каталог;
при результатах Create/Add теряют первый тап; заметка и некоторые действия Live
не получают click. Применение изменённой даты способно стать закрытием без
применения. Есть случаи, когда действие срабатывает, но экран всё равно прыгает.

**Источник:** src/app/app-viewport.tsx:60,86,97,107, ExercisePicker.tsx:530,
FitLimeDatePicker.tsx:54, workout-live-reference.css:207.
activeInput=false преждевременно возвращает stableHeight, хотя visualViewport
ещё мал. Прокрутка к явно выбранному следующему упражнению — ожидаемое действие,
его сюда не относим. Точный commit появления общего дефекта не установлен.

**Менять:** согласовать существующие viewport recovery, blur-save и жест;
закрывать backdrop только по намеренному нажатию на фон. Не заменять
контролы/хранение или глобально удалять восстановление WebKit.
**Где ещё:** общий AppViewportProvider; каталог из всех трёх клиентских входов,
Live обеих плотностей и клиентская дата; регрессия остальных ролей.
**Приёмка:** первое нажатие исполняется один раз; нет случайного закрытия,
потери черновика/даты и сдвига цели до окончания жеста. Проверить физический
iPhone отдельно. Подробная матрица/события/снимки — BUTTONS_AUDIT.md.

### R08 · P1 · Завершённое упражнение остаётся раскрытым из-за отдыха

выполненное упражнение должно сворачиваться по согласованному сценарию,

**Приёмка:** последний подход/ручной минус/остановка/следующее упражнение/
