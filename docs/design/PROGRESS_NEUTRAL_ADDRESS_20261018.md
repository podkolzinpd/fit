## Подтверждённый план — дословно

Исправлять нужно контроль ответа, а не просто усиливать промпт:

- Сохранить нейтральный стиль и добавить понятные примеры допустимых обращений.
- Проверять родовые формы, относящиеся именно к пользователю, включая слова между «ты» и глаголом. Не запрещать «вес вырос» и «тренировка выполнена».
- Найденное нарушение сделать обязательным к исправлению через существующий ограниченный механизм коррекции.
- После коррекции повторно проверять обращение и факты. Если нарушение осталось — не сохранять неправильный новый ответ и не затирать предыдущий анализ.
- Закрепить тестами точную фразу со скриншота и похожие конструкции. Старые сохранённые анализы обновлять отдельно.

Важно: одна расширенная регулярка не гарантирует проверку всего русского языка.
Поэтому нужны и проверка, и ограниченное исправление, и запрет принимать обнаруженную ошибку.
Передавать пол для этого не требуется.

## Исполнение без расширения scope

Уже работает: нейтральный prompt, quality assessment/repair/recheck, cache fingerprint,
один платный model request, явное обновление и сохранение старого результата при ошибке.
Переиспользуем: summary-quality, requestStructuredYandex, ClientTrainingSummaryCard,
progress-analysis-preview, SummarySheet и существующий link «Обновить анализ».
Primary/геометрия/токены прежние; нового Coachmark нет — это исправление текста.
Действительно меняем: обязательная проверка адресованных человеку форм, ограниченные
нейтральные переформулировки без правки фактов, примеры prompt/version.
Сверка UI подтвердила: явное обновление уже есть внутри полного анализа,
включая период без новых тренировок. Новую кнопку в превью не добавляем.

Runtime сейчас maxAttempts=1: не добавляем платные коррекционные вызовы. Безопасные
поддержанные конструкции исправляются детерминированно; неподдержанное обнаруженное
нарушение возвращает existing quality error. Не применяем глобальную замену окончаний.
Старые тексты не переписываем в БД и не запускаем массовую генерацию: новое правило
входит в fingerprint через prompt version, пользователь явно обновляет анализ.
Существующий runtime-parity contract требует идентичности prompt/quality в
services/api и сохранённых Supabase function sources. Две существующие копии
синхронизированы; это совместимость, не новый adapter/fallback/deployment Supabase.

Не проверено: профиль/исходный model response конкретной девушки и live генерация
с её персональными данными. Проверяем synthetic cases на том же серверном пути и
реальном маршруте /me/progress; реальный OAuth/физический iPhone не выдаём за тест.
KB search недоступен (scope mismatch/unsafe ignore); контекст проверен по origin/main.
Отдельный внешний Tracker не используется без настроенного доступа.
