# YAFIT-533 — загрузка фото анкеты тренера на iPhone

## Проблема

На iPhone кнопка «Добавить фото» могла не открыть системный выбор файла либо
завершить обработку без видимой ошибки. Причины накладывались: файловый input
был отделён от области нажатия, фото без MIME type отклонялось, а ошибка
показывалась только внизу длинной формы. При переносе старого одиночного фото
запрос также повторно отправлял legacy data URL и приближался к лимиту API.

## Исправление

1. Нативный файловый input покрывает всю кнопку и получает прямое нажатие.
2. Поддерживаются JPEG, PNG, WebP, HEIC и HEIF, включая iOS-файлы без MIME type;
   исходный файл может занимать до 20 МБ и перед отправкой преобразуется в JPEG.
3. В блоке фотографий сразу видны состояния подготовки и загрузки, а также
   понятная ошибка с возможностью повторить действие.
4. При первом добавлении к старой анкете legacy-фото не дублируется в теле
   запроса; лимит gallery endpoint покрывает допустимый подготовленный payload.
5. WebKit проверяет открытие системного выбора файла. Компонентные и API-тесты
   покрывают iPhone-файл без MIME, inline-ошибку, legacy-перенос и лимит тела.
6. Выкатка не проходит без настоящей загрузки, подписанного чтения и удаления
   тестового JPEG через Yandex API, PostgreSQL и приватный Object Storage.
7. В политике внешнего Yandex-бакета разрешён отдельный закрытый префикс
   `trainer-profile-media/*`. Удаление объекта ограничено пятью секундами:
   задержка Object Storage больше не удерживает ответ профиля до 504, а ошибки
   очистки остаются best effort после удаления ссылки на фото из анкеты.

## Границы

- Лимит галереи остаётся равен трём фотографиям.
- Существующие анкеты, опубликованные фото, каталог, чат и ИИ не меняются.
- Фото по-прежнему хранятся только в Yandex Object Storage, метаданные — в
  Yandex PostgreSQL; fallback в старое хранилище не добавляется.
