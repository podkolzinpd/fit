# Бэклог: фидбэк тренера-нутрициолога (демо, выходные)

Статус: **бэклог, приоритизировано, в работу не взято.** Источник — отзыв
тренера после теста демо. Ниже — что берём, с привязкой к тому, что уже есть в
коде, и оценкой. Приоритет: **P1** (близко, ценно) / **P2** (важно, крупнее) /
**P3** (позже/обсудить).

---

## 1. Замеры: выпадающий список типовых параметров — **P1, S**
Сейчас: фикс. поля (грудь/талия/бёдра `chest_cm/waist_cm/hip_cm`) + кастомные
метрики (`client_custom_metrics`, клиент/тренер добавляет свои). Работает.

Доработка: **пресеты замеров из списка** вместо только ручного создания. Тренер
выбирает из готовых, не придумывая название:
- живот (на уровне пупка) — важен при снижении жира;
- **парные** (нужны левое+правое): бедро, плечо, предплечье, икра.

Тех.решение: справочник пресетов метрик + флаг «парная» (создаёт две метрики
Л/П). Ложится на существующие custom_metrics — не ломает модель.
→ маленькая, ценная, берём в первую очередь.

## 2. Биоимпеданс + состав тела — **P2, M**
Сейчас: Storage/вложений нет; состав тела не считается.

Что просят:
- Поля состава тела: **жир (кг + %), мышцы, вода** (вода особенно для женщин).
  `%` жира считать из кг жира и веса.
- Наглядный **тренд-график** прирост/снижение (референс — InBody; скрин по
  запросу).
- **Только ручной ввод**, без синхронизаций (инструментов много: InBody, весы).
- **Вложение файлов**: скрины из приложения весов/InBody → нужен Supabase
  Storage + привязка к записи замера.
- **Напоминания о взвешивании**, периодичность настраиваемая.

Тех.решение: расширить `client_progress`/метрики полями состава тела; подключить
Storage для вложений (RLS по владельцу); механизм напоминаний (позже). Разбить
на под-задачи: (а) поля состава+%+график, (б) вложения, (в) напоминания.

## 3. База упражнений и мышечные группы

### СТАТУС КАТАЛОГА (обновлено)
**Сейчас: 216 упражнений** (49 базовых + 167 импортированных из Free Exercise DB,
public domain). Группы: `legs`(44) `arms`(37) `back`(31) `shoulders`(30)
`chest`(28) `core`(26) **`glutes`(13, новая)** `cardio`(7). Каждое «как в
приложении»: картинка + рус.название + оборудование + мышца + рус.инструкции.

**Решение по объёму:** на 216 останавливаемся (все группы покрыты, не раздуваем).
В запасе ещё **~334 чистых силовых** в источнике (873 всего → 796 годных → 485
чистых силовых без растяжек/SMR/плиометрики → 334 ещё не у нас). Технический
потолок ~550. Догонять по числу ради числа не нужно (мелкие вариации типа «жим
под углом 15/30/45°» тренеру не полезны) — при желании доберём порциями.

**Сравнение с Hevy (референс):** у Hevy ~400-500 встроенных упражнений + видео
вместо статичных фото + безлимитные пользовательские. У нас 216 + свои
упражнения (безлимитно) + фото/инструкции. По качеству карточки сопоставимо,
по числу ~в 2 раза меньше, из отличий у них — видео (наш источник даёт только
фото). ⚠️ Точная цифра Hevy — их внутренние данные, порядок ~400+, не гарантия.

### 3a. Чистка ошибок каталога — ✅ СДЕЛАНО (PR #102, YAFIT-56)
Сверено по спортивной анатомии (прайм-мувер): Гиперэкстензия→спина, Ножницы→кор,
пауэрлифт-жим→грудь, становые деталь→бицепс бедра. + фикс подкатегорий
(PR #109/YAFIT-61): «Бицепс бедра» больше не всплывает в «Спине»; добавлен
регресс-тест «деталь строго в своей группе».

### Ягодицы + расширение — ✅ СДЕЛАНО (PR #107 YAFIT-59, #108 YAFIT-60)
Новая группа «Ягодицы» (13 упр.) + добор дефицитных (икры/бицепс/предплечья/
бицепс бедра/трапеции): каталог 162→216.

### 3b. Пересмотр детализации мышц — **P2, M** (вернуться и свериться)
Переименовать/переразбить на анатомически корректные:
- квадрицепс → **передняя поверхность бедра**;
- бицепс бедра → **задняя поверхность бедра**;
- плечи → **пучки дельтовидных** (передний/средний/задний).
Фиксируем как «вернуться и согласовать формулировки с тренером» — это меняет
справочник `primaryMuscleDetail`, затрагивает иерархию пикера.

### 3c. Новые виды тренировок — **P2–P3, L** (обсудить)
- Кардио: добавить **степпер**.
- **Функциональный** вид тренировок + база под него; сюда же протоколы
  **AMRAP / EMOM** (совпадает с уже отложенным «Этап B: форматы на время»).
- **Игровые виды** (волейбол, падел, футбол…) — ручной ввод, чтобы была общая
  картина по клиенту.
- **Пилатес, йога** — сюда же.
Ручной ввод достаточно; ценность — единая картина по клиенту в одном приложении.

## 4. Карта задействованных мышц — **P3, M** (вкусное, не срочно)
При формировании силовой по мышечным группам — визуальная **карта мышц** (как в
Garmin): подсветка задействованных. Зависит от п.3b (корректная детализация).

## 5. Женский цикл — **P2, M** (важно, ручной ввод)
Ввод фаз цикла для женщин — для дозирования нагрузки. **Синхронизация не нужна**
(дневников цикла много и все разные) — достаточно ручного ввода. Совпадает с
уже намеченной «Периодизацией» (женский цикл был её частью).

## 6. Питание / нутрициология — **P3, L** (обсудить, зона роста)
Тренер ведёт клиентов в комплексе тренировки+питание.
- Вкладка **общих рекомендаций КБЖУ + клетчатка**.
- Для желающих клиентов — синхронизация с **FatSecret**.
- ⚠️ Предупреждение от тренера: в FatSecret проблема с **клетчаткой** (данные
  неполные) — заложить это в оценку интеграции.

## 7. Синхронизация с часами (сон и пр.) — **P3, L** (зафиксировать, вернуться)
Гаджеты разные: Garmin, Apple, Whoop. Не первостепенно; фиксируем, чтобы
вернуться при реализации wearables-интеграций.
