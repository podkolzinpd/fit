# Каталог упражнений — применение согласованного списка

Источник: `FIT_final_core_uncommon_rare_remove.xlsx`, 03.09.2026, четыре листа:
Core / нечастые / редкие / убрать. Решения по каждому ref сохранены в
`src/shared/exercise-catalog-decisions.ts`.

## Применённые правила

- Из согласованных 662 записей остаются 573 самостоятельных движения:
  80 основных, 278 дополнительных, 215 редких. Добавленный позднее
  `smith-single-leg-romanian-deadlift` сохранён в дополнительных. Текущий итог:
  **574 движения: 80 / 279 / 215**.
- 89 записей больше не являются отдельными карточками обычного каталога:
  18 дублей, 64 варианта, 7 форматов тренировки.
- Из 18 дублей 16 имеют одинаковый тип записи и заменяются при новом выборе.
  У `fedb-parallel-bar-dip` и `fedb-external-rotation-with-band` тип записи
  отличается от основной карточки. Поэтому они доступны как явные варианты,
  а не автоматически конвертируются с потерей веса / повторов / времени.
- 64 варианта + эти две записи выбираются внутри панели техники одной основной
  карточки. Выбор сохраняет исходный ref и его поля. Поиск может сразу показать
  конкретный вариант; несколько результатов одной семьи объединяются.
- 7 форматов доступны в отдельном разделе «Форматы тренировки», с прежними
  полями. Новую логику таймера AMRAP/EMOM этот PR не добавляет.
- Названия взяты из согласованного списка; повторяющиеся подписи снаряда в
  скобках убраны из заголовков. Оборудование остаётся отдельным атрибутом.
  Смысловые уточнения (например, пауэрлифтинг) не удаляются из названия.
- По умолчанию открываются основные; поиск работает по всем разделам, с
  сохранением фильтров направления, мышцы, оборудования и пользовательских
  упражнений. Последние упражнения не размножают одну семью карточек.

## Сохранность данных и поиска

Физического удаления строк БД, тренировок, критериев целей, custom exercises
или медиа нет. Полный каталог из 663 идентификаторов остаётся доступен для
чтения истории. Снимки названий в старых тренировках не переписываются;
прежние цели не меняют упражнение или единицу измерения автоматически.

Все прежние названия, ручные синонимы и сленг сохраняются в поисковом индексе.
Для точного дубля словарь переносится на основную карточку. Для отличающегося
варианта — остаётся на его ref. Английские имена и автоматически полученные
формы остаются поисковыми подсказками, не повышаются до точного совпадения.
LLM-разбор нового ввода получает каталог без 16 заменённых точных дублей.
Пользовательские упражнения не сливаются с системными даже при совпадении ref.

## UI и приёмка

Переиспользованы `Field`, `Coachmark`, существующие карточки каталога и панель
техники. Primary-действие в панели — добавление выбранного варианта. Новых
цветов, геометрии, CSS-тем и библиотек компонентов нет. Подсказка внутри sheet
порталится в свой dialog, чтобы не оказаться под ним.

Проверяются: core / дополнительные / редкие / форматы, поиск старого названия,
сленг, custom, пустая выдача, выбор варианта, возврат в список, ввод подходов;
Client и Trainer, light/dark, 390 / 430 / 1440 px, Chromium / WebKit.
Общие loading/error/retry ветки существующего каталога сохранены.

Автоматические контракты сверяют все 662 решения, все 663 исторических ref,
все прежние названия и ручные aliases, поля и медиа, цели объединений и
доступность каждого несводимого варианта. Финальные результаты проверок и
deployment фиксируются в PR; документ не означает, что изменение уже выкачено.

Откат — revert PR. Миграций БД и новых feature flags нет.
