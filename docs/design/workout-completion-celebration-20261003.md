# Поздравление после тренировки — утверждённый план

Утверждено 3 октября 2026. Пользователь разрешил реализацию и полный выпуск.
Любая завершённая тренировка получает полноценное поздравление — одинаковые фразы и иконки для 10 из 12, 11 из 12 и 12 из 12 подходов. Фактический результат показываем отдельно.

1. **Поздравление вверху экрана.**  
   По центру — случайная объёмная иконка: звезда, кулачок или медаль, размером примерно 80–96 px. Под ней крупная мотивационная фраза, короткая подпись и дата. Например:

   > **[Объёмный кулачок]**  
   > **Вот это мощь!**  
   > Ещё одна тренировка в твою пользу  
   > *Тренировка завершена · 3 октября*

2. **Общий набор фраз для всех завершённых тренировок.**  
   Все согласованные варианты участвуют в ротации независимо от количества выполненных подходов. Никакого отдельного «утешительного» набора. Женские и мужские окончания учитывают данные профиля; если пол не указан — используются нейтральные формулировки.

3. **Случайный выбор без постоянных повторов.**  
   Фразы и иконки перемешиваются независимо. Иконка не повторяется две тренировки подряд, фразы чередуются. Выбранное сочетание закрепляется за тренировкой и не меняется при обновлении экрана или заполнении самочувствия.

4. **Результаты — сразу под поздравлением.**  
   Показываем фактические подходы, время, тоннаж и другие доступные показатели. Например, «Выполнено 10 из 12 подходов» — обычная строка результата. Крупный заголовок «Тренировка сохранена частично» убираем. Ниже располагаем личный рекорд или рост результата, затем новые ачивки с собственными рисунками.

5. **Самочувствие и подробности — следующим блоком.**  
   После результатов и наград остаётся форма «Как прошла тренировка?». Кнопку «Сохранить итоги» переименуем в **«Сохранить самочувствие»**, чтобы было понятно, что сама тренировка уже сохранена. Под формой — свёрнутый блок «Что записано» с упражнениями и возможностью исправить результат.

6. **Действия — вместе внизу.**  
   Главная кнопка — **«Готово»**. Рядом по смыслу, но с меньшим визуальным акцентом — «Посмотреть прогресс» и «Поделиться». В карточку для публикации добавим ту же фразу и иконку, которые человек увидел на экране.

7. **Проверка оформления.**  
   Выровняем три иконки по визуальному размеру, проверим светлую и тёмную темы, небольшие экраны и длинные фразы. Верх останется компактным, чтобы поздравление не отодвигало результаты далеко вниз.

## Дополнение пользователя
«Обязательно добавь иконки, но чтобы они быстро загружались».

## Preflight и границы
Референс — действующий WorkoutCompletionReport на /workouts/:id после завершения, соседний экран истории. Переиспользуем Page, WorkoutCta, WorkoutChoice, существующие report/facts/highlight, NewlyEarnedAchievements, feedback, share canvas и семантические токены UI Identity. Primary — «Готово», сохранение самочувствия — secondary в этом состоянии. Только клиентский экран завершения и его публикация; тренерская оперативная карточка, Home, backend и расчёты не меняются. Для пола — существующая карточка клиента, нейтральный fallback при отсутствии/загрузке/ошибке. Рекорды: данные/нет/loading/error+retry; ачивки: одна/несколько/нет. Дополнительно storage unavailable, offline image fallback, длинный текст, 320/390/430, обе темы, повторный вход/обновление и публикация без личных заметок.

Локальная полная проверка: `npm run check` прошла (2294 frontend tests; 1043 API tests, 66 existing skipped). После финальной правки доступного имени региона — 65 целевых тестов, включая Yandex repository contract. Backend/API/schema не менялись. WebKit/390 и Chromium/430 полные и частичные тренировки прошли; client-realtime 2/2. Отдельный старый feedback-coach-state smoke в локальном WebKit останавливается ещё на регистрации нового аккаунта (до completion); этот внешний для экрана сценарий дополнительно проверяется CI. В Linux VM подтверждён OOM-kill WPEWebProcess при экспорте: доступно 4 ГБ на все локальные контейнеры. Тест сравнивает непосредственно созданный PNG как image snapshot, без лишнего повторного рендера во второй странице; продуктовый сценарий не изменялся.

Ограничение хранения: сочетание сохраняется на текущем устройстве в пространстве пользователя; при закрытом/переполненном storage — детерминированный fallback. Через сервер декоративная ротация не синхронизируется. Отсутствие/ошибка профиля не блокирует результат и даёт нейтральную грамматику. Изменение доступного пола меняет только окончание той же фразы.
