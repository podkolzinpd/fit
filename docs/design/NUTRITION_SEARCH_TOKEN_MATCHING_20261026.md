# YAFIT-659 — общее правило коротких слов

Дополнение после PR1824, база main3702c1be. На присланном клиентском Lime-скрине
поиск «сыр» показывает «Брокколи, сырая»; «сыр пар» показывает пармезан.
Версия установленной сборки неизвестна. На текущем main ошибка фильтра
подтверждена: BasicNutritionCatalog.search('сыр',1) возвращает брокколи.

| Уже работает | Переиспользуем | Меняем | Не проверено |
| --- | --- | --- | --- |
| Поиск по нескольким словам и рецептуры1824 | Общий isRelevantCatalogSearch для Basic/Perek/Vkusvill | Границы коротких токенов, без исключений по названиям еды | Установленная сборка пользователя |
| Карточки поиска, выбор порции | NutritionPage и исходный WebKit-сценарий | Только серверное сопоставление + read-only probe | Авторизованный production-дневник |

## Приёмка

1. Короткое самостоятельное слово (2–3 символа) совпадает с целым токеном;
   «сыр» не возвращает «сырую» брокколи. Правило одинаково для «рис», «мак»,
   «лук», «чай», «сок»: словаря продуктов и отдельных веток для них нет.
2. Последний токен многословного запроса может быть незавершённым:
   «сыр пар», «рис бас», «чай зел» сохраняют поиск по началу слова.
   Для токенов от4символов остаётся существующее сопоставление по первым5
   буквам; числа сравниваются целиком. Короткий самостоятельный префикс
   «йо» больше не выдаётся за полное название; «йогу» находит йогурт.
3. Общая runtime-композиция показывает сыр по «сыр» и пармезан по «сыр пар»,
   не возвращает брокколи. Йогурт/оливье/рецептуры/продолжение сохраняются.
4. WebKit проверяет оба запроса на существующем маршруте; полный check,
   exact-head CI, очередь более ранних PR, штатный merge и production readback.

Локальное воспроизведение до правки:6 новых упавших assertions, в том числе
реальная базовая запись брокколи. После общего правила:60API проверок passed.
WebKit10/10 повторно прошёл после замены частного правила общим.
Живой собранный runtime с общим правилом: ready=true, все6 запросов found;
по «сыр»15 сырных записей, по «сыр пар»11 вариантов пармезана
(число/состав меняются на стороне источника). CI/production ещё
гейты, эти результаты не объявляются выпуском. Первый check прошёл2855frontend
и остановился на sandbox EPERM listen127.0.0.1 в relay-тестах. Финальный полный
check с разрешением localhost завершён exit0: frontend2855/API1516+196 штатных
conditionalDBskip, lint/typecheck/policy/hosting/build/startup прошли;
тесты и таймауты ради повторного прогона не менялись.

Диагностический снимок: [поиск пармезана](nutrition-search-20261026/nutrition-search-cheese.png).

Ручная диагностика nutrition_search расширена до6 фиксированных публичных
запросов; ограничение65s покрывает последовательные bounded-запросы к двум
источникам. Дневники, БД, сессии и секретные значения по-прежнему не читаются.

UI-компоненты, CSS, флаги, авторизация и сохранение питания не меняются.
Единственное primary-действие остаётся выбором продукта в существующей выдаче.
