## Вердикт

Главная проблема — разные входы меняют смысл одного действия. Интерфейсу нужна единая последовательность «запланировать / начать сейчас / записать результат / отметить занятие», с сохранением важных возможностей. Полная переделка приложения не требуется. Найдены 12 пунктов; первые четыре важнее косметики. Реальных пользователей, тренировок и финансов аудит не изменял.

## Правило сценариев

- **Запланировать**: Клиент → дата/необязательное время → формат → необязательное наполнение → «Запланировать» → карточка «План». Не выдавать это за проведение.
- **Начать сейчас**: Явные клиент и формат → существующая или новая Live → упражнения и подходы → завершение → результат. План на другую дату: заранее объяснить фактический день.
- **Записать прошедшую**: Дата факта → упражнения и фактические значения → «Записать тренировку» → результат. Не требовать запускать Live задним числом.
- **Отметить занятие проведённым**: Сохранённая запись → подтверждение клиента/даты/формата/учёта → «Подтвердить проведение» → «Проведена». Упражнения можно дописать позже; отмена окна ничего не проводит.
- **Не состоялась**: Сохранённый план/Live → осознанное подтверждение → «Не состоялась», с сохранением плана. Возможность вернуть в план. Не заменять это удалением.
- **Удалить ошибочный пустой старт**: Только подходящая пустая запись → отдельное явно разрушительное действие. Не удалять заполненное занятие под видом выхода.
- **С тренером / самостоятельно**: Это формат присутствия и учёта, а не способ ввода. Голос, текст, каталог, шаблон и копия должны сохранять один выбранный формат.
- **Спортсмен и назначенный план**: Сохранять права на авторский план тренера и собственную копию спортсмена; не открывать редактирование чужого плана ради единообразия.

### WUX-01 · P1 · Нельзя добавить нового клиента в коротком сценарии

**Основание:** Воспроизведено.

**Правка:** Под поиском — существующая кнопка «+ Клиент». После создания автоматически выбрать клиента и вернуть в исходный сценарий с сохранёнными датой, временем и черновиком. Не запускать тренировку до успешного создания.

**Приёмка / решение:** Добавление уже согласовано. Проверить отсутствие клиента по поиску, полностью пустой список, ошибку создания, отмену и успешное создание без дубля.

### WUX-04 · P1 · Будущая дата: старт и проведение объясняются по-разному

**Основание:** Воспроизведено + проверено по коду.

Будущий план можно запустить сейчас у обеих ролей. Тренеру показано пояснение о сегодняшнем старте, спортсмену — нет. Серверный trigger 000133 правильно переносит Live на фактический день и сохраняет исходный план; упрощённый браузерный mock этого не моделирует. **Приёмка / решение:** F04 проверяет переход интерфейса, не DB trigger. Финальная политика будущего проведения требует выбора. Проверить today/past/future, часовой пояс и исходную дату, без запрета штатного раннего старта.

### WUX-09 · P2 · Ввод текста уводит из формы; возврат ведёт в календарь

**Основание:** Воспроизведено.

Из быстрого плана текст открывается на отдельном экране. У него возврат в календарь, а не в исходную форму. Внутри проверки и сохранения есть корректные шаги назад. Данные не объявляются потерянными: перенос параметров в полный редактор и текстовая проверка работают.
