# Фотография во время запуска Fit

Задача: YAFIT-592. Ветка: codex/startup-photo-splash-20261003.

## Запрос владельца

«Так, смотри, у нас в самом начале идёт достаточно долгая загрузка. Сможешь ли
ты вместо загрузки вот этого чёрного экрана поставить вот эту вот фотографию?
В общем, чтобы она была на главной. Ну, короче, до того момента, пока не
загрузится приложение. То есть, пока загружается, эта фотография и вместо там
восстанавливаем сессию вот этого всего.»

Два приложенных SVG идентичны и содержат один PNG 940×1673. Используется
неизменённый снимок, перекодированный в JPEG quality 82, 144072 байта.
SHA-256: 983c93dc4df8183ceb215442feb1b20394aee7f9a871cd2c8a1c693b4c4b89f0.

## Минимальный план и границы

1. Одна фотография в HTML до запуска React и в loading-ветках Protected,
   AuthPage, YandexAppSessionPage и первичной проверке LegalAcceptanceGate.
   Один cacheable URL, preload, без анимации,
   таймера показа и новых запросов к аккаунту.
2. Критические стили фотографии встроены в HTML и сохраняются после его
   стартовой оболочки. Общая таблица стилей загружается неблокирующе с preload
   для сохранения приоритета; прежний
   контроллер не снимает оболочку, пока CSS не применён и root не виден.
3. При сетевой ошибке не маскировать проблему фотографией: сохранить 12-секундный
   watchdog, аварийную оболочку и штатные StatePanel/повтор восстановления входа.
   Если не загрузилось только фото, показать короткий loading fallback.
4. Проверить холодный/тёплый запуск, медленные JS/CSS/session, ошибки и готовый
   интерфейс на 390/430/1440 px; затем штатные проверки и выпуск по очереди.

Переиспользуются startup controller, asset recovery, auth providers и StatePanel.
Новые цвета интерфейса не вводятся: fallback использует тёмные Foundation-цвета
#111214/#F1EDE6; лаймовый цвет принадлежит исходной фотографии. Primary нет
при нормальной загрузке; при ошибке остаётся одно штатное действие повтора.
Главные страницы после загрузки, иконки, авторизация, API, БД, Lime allowlist,
OAuth callback/setup формы и внутренние skeleton/data-loading не меняются.

## Приёмка

| Пункт | Видимый результат | Проверка |
| --- | --- | --- |
| До React | Фото без технических надписей | startup-shell WebKit, 390/430/1440 |
| Восстановление входа | То же фото на /, /auth, /auth/yandex/session, включая первичную проверку документов | yandex-only-auth WebKit; AuthPages/LegalPages component tests |
| Готовность | Нет искусственной задержки, заставка удалена | успешный вход / legal gate; normal bootstrap |
| Медленный CSS | Фото рисуется, не виден нестилизованный root | delayed stylesheet WebKit + проверка настоящей production-сборки |
| Ошибка JS/CSS | Фото сменяется recovery с повтором | startup-shell WebKit |
| Ошибка сессии | Штатный retry, не бесконечное фото | yandex-only-auth WebKit |
| Ошибка фото | Читаемый loading; запуск не зависит от изображения | HTML WebKit + React component error |
| Вес/совпадение | До 160 KB, один URL и hash для HTML/React | postbuild verify-startup-build |

Ограничения: до получения HTML браузер не может отрисовать заставку; она не
ускоряет сеть или API и не заменяет native launch screen. Фото декоративное,
loading доступен скринридеру, движения нет. На мобильном используется cover
с центральным кадрированием, в горизонтальной ориентации — contain.

Локальная приёмка: полный npm run check прошёл с VITEST_MAX_WORKERS=2
(2320 frontend, 1048 API; DB integration suite штатно skipped без БД).
После добавления final legal-loading ветки отдельно прошли 31 auth/legal tests
и 6 Yandex WebKit scenarios; startup WebKit — 11/11. Изменённые legal/e2e
файлы дополнительно прошли eslint, итоговая сборка/typecheck зелёные.
Реальная сборка в WebKit/Chromium даёт first-contentful-paint с pending CSS,
затем штатный styled login. Холодный и повторный запуск с кешем проверены.
Исходный светлый экран с надписью и итоговые снимки 390/430/1440 просмотрены.
Первый full check был запущен с ошибочно глобальными Yandex-only flags
(18 legacy failures); следующий при конкурирующей нагрузке дал два прежних
ExercisePicker timeout. Ограниченный по workers полный прогон зелёный;
таймауты/проверки продукта не ослаблялись.
