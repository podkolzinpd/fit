# PR3 — клиентские свайпы удаления, 21.10.2026

## Проверка существующего

База72d3ea09 после PR2; родительский PR1 b0ebd845. До реализации локально
открыт Live обеих ролей в WebKit/Chromium: клиентский reference-gate сработал,

## Переиспользовано

WorkoutGestureList/WorkoutSwipe, deleteLiveExercise/requestRemoveLiveSet,
removeExercise/removeSet и серверные команды с version/ownership; существующие
подтверждения и coachLiveSetRemovalError. Нового способа удаления в API нет.
Свайп раскрывает семантическое destructive-действие; запись только после
нажатия «Удалить» и предупреждения. Упражнение удаляется вместе со своими
данными по прежнему явному предупреждению. Замена остаётся в меню.

Scope — существующий client-workout-reference пилот, без расширения allowlist.
Базовая геометрия свайпа переиспользует действующие тренерские CSS-правила
через явный общий селектор coach/client reference. Цвет ошибки/удаления
семантический, не лаймовый. Общая защита удержания номера подхода затрагивает
оба reference-потребителя; тренерский сценарий проверяется отдельно.

## Что изменено

- Подключены exercise/set swipe и nativeSwipe у клиентского reference.
- Подтверждённый и последний подход защищены, в том числе при конфликте
  подтверждения с другого устройства; ошибка допускает безопасный retry.
- Суперсет использует существующее атомарное удаление только последнего
  добавленного неподтверждённого круга, ограничения не ослаблены.
- Номер подхода остаётся зоной свайпа строки и не начинает перенос упражнения.
  Заголовок/свободное место карточки сохраняют удержание для переноса.
- Кнопка завершённой карточки/техники допускает горизонтальный свайп, короткий
  тап выполняется через существующий trusted pointer-up путь. Это необходимо
  для WebKit: preventDefault жеста иначе подавлял совместимый click.
- Нативное раскрытие summary заметки исключено из перехвата свайпа;
  первое нажатие при клавиатуре сохраняет стандартное действие details.
- Неизменённые placeholder-значения не превращаются в сохранённый факт после
  открытия/отмены удаления. Активный input жест не перехватывает.
- Удаление постороннего упражнения сохраняет отдых текущего, как у тренера;
  удаление владельца отдыха проходит прежний stopRest.
